# 사건 묶음으로 비교하는 V4 Go 학습 실행기

개발 진행·완료 보고·질문 힌트를 위한 유지보수용 실행기입니다. 기존 Go 분류기의
교차 엔트로피와 AdamW를 사용하며, Python이나 별도 GPU 런타임이 필요하지 않습니다.
Laya 신경망·LoRA·3진 가중치 학습과는 별도 실험입니다. 기존 모델과 V3 실행기를
바꾸지 않습니다. 이 문서는 구현된 실행 절차를 설명하며 **새 실제 학습 결과가 아닙니다**.
전체 원본 자료와 검토·해시 잠금이 준비되기 전에는 실행 가능한 계획을 만들지 않습니다.

사람이나 에이전트가 같은 방식으로 호출합니다. 먼저 검증된 소스 commit의 깨끗한
작업 트리에서 Go1.27.1로 독립 실행 파일을 빌드합니다. 빌드 파일 자체의 SHA-256,
Go가 기록한 Git revision과 clean stamp, 현재 필수 Go 소스의 해시를 계획과 비교합니다.
숨겨진 전역 설정이나 자동 모델 다운로드를 사용하지 않습니다.

```sh
go build -trimpath -o .cache/statehint/v4-fit ./cmd/riido-statehint-tune-v4
.cache/statehint/v4-fit --plan .cache/statehint/v4/PLAN.ready.json --check
.cache/statehint/v4-fit --plan .cache/statehint/v4/PLAN.ready.json --fit --out .cache/statehint/v4/run01
```

`--check`와 `--fit` 중 정확히 하나를 명시해야 합니다. `--check`는 부모 모델의
파일·형식을 읽어 확인하고, 학습·선택·보정 자료 세 파일을 검사합니다. 모델 추론이나
학습은 하지 않고 최종 평가 본문도 열지 않습니다. 실제 학습은 `--fit`으로만 시작합니다.
현재 2,400행이 준비된 실행 계획은 아직 없으며, 작은 임시 자료로 이 요건을 우회하지 않습니다.

계획의 정확한 필드는 `Plan`의 JSON 태그로 정의합니다. 중첩 객체까지 누락·추가·
중복·대소문자 별칭·null·잘못된 자료형을 거부합니다. 고정된 의미 기준의 기록과
한·영 정의, 원본 작성 검토 기록, 부모 모델, 필수 소스, 실행 파일과 네 자료 분할의
구체적 해시가 필요합니다. 알려진 부모 v0.2는 32,960바이트/1,920학습 단계입니다.
원본·권리·의미·번역·계보·중복 검토 기록은 정확한 사건 목록의 해시에 연결합니다.
기록의 bool은 검토자의 선언이며, 소프트웨어가 저작권이나 인간 정답을 증명하지 않습니다.
빌드 메타데이터와 체크섬도 신뢰한 로컬 빌드를 확인하는 수단이지 외부 서명 인증이 아닙니다.

사건 목록은 본문 없이 전체 1,200가족/2,400행의 ID·언어 쌍·의도·계보·문장 해시를
검사합니다. 분할별 가족 수는 840/120/120/120, 의도별 수는 105/15/15/15입니다.
전역 ID와 같은 문장의 SHA-256 중복을 거부하고, 같은 계보가 분할을 넘지 않게 합니다.
ID가 다르다고 의미적으로 독립적인 것은 아닙니다. 실제 문장은 목록과 다시 대조하며
**Text와 expected_intent만** 학습에 넘깁니다. 단위 설명이나 계보를 몰래 입력에 붙이지 않습니다.

학습 후보는 고정된 순서의 네 개입니다. 부모에서 .005/.01/.02로 이어 학습하거나,
새 가중치에서 .02로 시작합니다. 매번 새 optimizer, 40epochs·batch32·decay.001·seed1729를
사용하며 후보마다 2,120번 갱신합니다. 학습은 직렬이고 명령의 Go 실행 스레드는 두 개로
제한합니다. 이는 동시에 실행하는 Go 코드의 CPU 처리기 수이며 전체 OS 스레드 수가 아닙니다.
엄격한 실행 시간 취소는 별도 프로세스 감독이 필요하며 여기서 보장하지 않습니다.

선택은 [사건별 평가](../statehintfamily/README.ko.md)의 자격을 통과한 후보만 대상으로
잘못된 제안 비용 → 8의도 NLL → 사전에 정한 후보 순서로 합니다. 자격이 없으면
결과를 보존하고 끝내며 최종 평가를 읽지 않습니다. 후보 하나만 온도 .5부터5.0까지
.1 간격으로 보정합니다. 같은 자격 안에서 8의도 NLL을 최소화하고 동점이면 먼저 나온
온도를 고릅니다. 표시 기준 .9/.05는 바꾸지 않습니다.

선택한 파일을 저장한 뒤 다시 읽어 실제 모델로 재로딩합니다. 선택·보정 자료의 모든
8개 확률과 의도·출처·학습 단계·guard가 일치하는지 확인합니다. 그 후 선택 모델과
코드·자료·검토 기록·부모·온도·선택 결과의 `LOCK.before-test.json`을 파일과 폴더에
동기화하고 같은 바이트를 재확인합니다. 입력 계획과 세 분할의 해시도 다시 검사합니다.
입력 파일의 symlink와 서로 같은 inode 별칭은 본문 읽기 전 메타데이터 단계에서 거부합니다.
이는 호출자가 지정한 계획 파일을 읽은 후의 검사입니다. 그 다음에만 최종 평가를
한 번 열어 자식·고정 부모·기존 규칙을 비교합니다. 평가 후
후보·온도·정답을 다시 고르거나 고치지 않습니다. 규칙의 one-hot 점수는 확률 보정 결과가
아니며 학습 모델의 표시 자격을 받지 않습니다.

출력은 새 `.cache/statehint/v4/단일실행이름`으로 제한합니다. 경로의 symlink를 거부하고
열린 폴더가 관측한 폴더와 같은지 확인합니다. v4와 실행 폴더는0700, 파일은0600이며,
기존 실행 파일을 덮어쓰지 않습니다. 실패한 부분 파일도 포함해 출력 한도를8MiB로
예약합니다. 매 후보·온도 결과와 실패 기록을 남기며 새 실행으로 실패를 감추지 않습니다.
이 보호는 신뢰한 로컬 소유자 안의 사고 방지이며 악의적인 동일 계정이나 변조된 컴파일러를
방어하는 인증 체계가 아닙니다. 원본 입력과 소스는 작업 공간 안의 제한된 일반 파일로 읽고,
최종 평가 파일의 해시 계산도 lock 이후까지 미룹니다.

정상 결과도 연구용입니다. 공개 합성 자료의 의도 정답은 실제 업무 성공, 권한,
라벨·이모지 생성이나 업무 상태 변경을 증명하지 않습니다. 네트워크·게시·앱 연동·상태
변경 경로는 이 명령에 없습니다. 모델 본체와 원본 결과는 Git에 넣지 말고, 검증한 공개
자료만 별도 Hugging Face 게시 절차를 거칩니다. `RESULTS.first.json`은 원문 없이
숫자를 기록하고, 후보별 파일은 원본 순서의 전체 8개 점수를 보존합니다.

현재 테스트는 원본 계산·메타데이터·가짜 단계 콜백으로 구두 계약, 누출 경계, 비용과
봉인 순서를 확인합니다. 실제 Model.Fit/Predict를 실행한 학습 성능 검사가 아닙니다.
