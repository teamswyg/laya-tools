# 한·영 학습 자료의 구조 점검

`riidolaya corpus-check`는 한 사건의 한국어·영어 문장을 묶는 준비 도구입니다.
모델을 불러오거나 학습하지 않습니다. 결과는 개수와 구조 통과 여부만 표시합니다.
문장, 작업 ID, 파일 경로, 문장 해시는 출력하지 않습니다.

```sh
riidolaya corpus-check --partition train --rubric-sha256 "$RUBRIC_RECEIPT_SHA256" < train.jsonl
```

`partition`은 `train`, `validation`, `calibration`, `test` 중 하나이며,
해시는 먼저 동결한 의미 기준의 기록을 가리킵니다. 이 명령은 기록 파일 자체의
해시를 재계산하지 않습니다. 값을 제대로 연결하는 일은 이후 학습 실행기의 책임입니다.
현재는 한 파일만 읽습니다. 다른 분할을 자동으로 열지 않으며, 사용자가 `test`
파일을 직접 넣으면 그 파일은 읽게 됩니다. 최종 평가를 봉인하는 학습 실행기는 아직 별도 작업입니다.

한 사건에는 `ko` 한 문장과 `en` 한 문장이 필요합니다. 두 문장은 같은 사건 ID,
계보 ID, 분할, 의도, 단위 설명과 모호성 표시를 공유해야 합니다. 원본 순서는
유지하며, 같은 ID나 같은 문장의 SHA-256이 중복되면 거부합니다. 문장은 4,096바이트,
파일은 16MiB, 행은 2,400개까지 허용합니다. 빈 행, 추가·누락·중복 JSON 키,
대소문자를 바꾼 키, null, 잘못된 자료형, NUL과 잘못된 원본 UTF-8도 거부합니다.
실패하면 부분 자료나 원문을 내보내지 않습니다. Go JSON의 해석된 문자열을 사용하므로
이스케이프 표기의 원본 바이트 보존이나 짝이 없는 surrogate의 엄격한 거부를 주장하지 않습니다.

입력은 초기 V4 작성 형식 `statehint-v4-original-train-seed-row-v1`의 정확한
20개 필드입니다. 형식 이름의 `train`과 별개로 명시한 분할을 검증하며, 스키마를
암묵적으로 확장하지 않습니다. `Row` 구조체의 JSON 태그가 전체 필드 계약입니다.
불명확한 문장에 한해서 선언 형태 목록을 빈 배열로 둘 수 있습니다.
2400행에 들어갈 의미 문장에는 `role=prose`, `semantic_applicable=true`,
`task_level_completion=false`, `wording_index=1`, `license=Apache-2.0`,
고정된 ontology 버전과 동결 기록 해시가 필요합니다. 라이선스 문자열은 작성자의
선언이지 권리 검증 결과가 아닙니다. 표 머리글·코드 등 제외 자료는 따로 관리합니다.

내부 `ValidateMetadata`는 본문이 없는 사건 목록으로도 계보가 분할을 넘는지
검사합니다. `MatchMetadata`는 읽은 분할과 그 목록의 사건·의도·계보를 대조합니다.
다른 분할의 본문을 열 필요가 없습니다. 같은 계보 안에서 여러 의도나 사건을
가질 수 있지만, 모든 사건은 하나의 분할에 있어야 합니다. 숫자 배열과 정렬된
슬라이스를 사용하며, 이 패키지에는 map, 사용자 잠금, 전역 캐시가 없습니다.
이 설계가 더 빠르다는 성능 비교는 아직 하지 않았습니다.

**구조 통과는 정답 검증이 아닙니다.** 번역의 의미가 같은지, 완료 보고가 현재
범위를 닫는지, 질문이 주행위인지, 실제로 다른 사건인지, 비공개 자료인지,
작성자가 공개·학습 권리를 갖는지는 별도로 검토해야 합니다. 바꾼 이름이나
다른 ID만으로 독립 사례가 늘지 않습니다. 계보 선언이 누락되면 이 도구만으로
근접 중복이나 실제 의미 누출을 발견할 수 없습니다.

출력의 `semantic_verified`, `training_allowed`, `model_used`,
`mutation_executed`는 항상 `false`입니다. 미검토 사례를 학습에 넣거나 이
점검 결과로 업무 상태를 바꾸지 마세요. 이후 학습 실행기는 전체 원본과 코드의
해시, 권리·의미 검토, 분할별 정확한 수, 선택·보정 규칙을 먼저 고정해야 합니다.
