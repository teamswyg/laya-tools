# 영수증을 남기며 크기가 제한된 공개 검토 파일 읽기

[English](review-packet.en.md)

`riido-reviewpacket`은 바이트 한도 안에서 일반 파일 하나를 읽고, 독립적으로
미리 고정한 SHA-256과 일치하는지 확인한 뒤 검증한 바이트를 stdout으로
내보냅니다. 입력 내용을 열기 전에 내구성 있게 시작 영수증을 저장하고,
어떤 내용도 내보내기 전에 별도의 최종 결과 영수증을 저장합니다.

이 명령은 준비 도구입니다. 실패한 파일럿이나 감사를 복구하지 않으며, S2
권한을 부여하거나 cohort 또는 Fit을 허가하지 않습니다. 의미적 검토나 코드
정확성을 입증하지도 않습니다. 모든 예제와 테스트는 영구적으로 공개 fixture이며,
정식 데이터가 아닙니다. 이 도구를 통과해도 정식 데이터로 바뀌지 않습니다.

## 명령

```sh
go run ./cmd/riido-reviewpacket \
  --input ./public-fixture.go \
  --sha256 <independently-pinned-64-hex-digest> \
  --receipt ./receipts/read.json \
  --max-bytes 1048576 \
  --actor public-fixture-check
```

해시 자리에는 이번 실행 전에 독립적으로 확정한 값을 넣습니다. 현재 입력의
해시를 계산해 곧바로 이 명령에 다시 넘기는 방식은 독립적인 고정값을 제공하지
않습니다.

| 옵션 | 계약 |
| --- | --- |
| `--input` | 필수. 일반 파일 하나의 경로입니다. 경로의 마지막 구성요소는 심볼릭 링크일 수 없습니다. |
| `--sha256` | 필수. 독립적으로 고정한 예상 해시이며, 정확히 64개의 16진수 문자여야 합니다. |
| `--receipt` | 필수. 새 시작 영수증의 경로입니다. 상위 디렉터리는 호출자가 먼저 만들고, 지정한 경로로 산출물을 찾을 수 있도록 실행 중 경로를 유지합니다. |
| `--max-bytes` | 입력 바이트 한도입니다. `1`부터 `8388608`(8 MiB)까지 허용하며, 기본값은 `1048576`(1 MiB)입니다. |
| `--actor` | 선택적 공개 라벨입니다. 지정했다면 최대 256바이트이며, 빈 값이나 공백만 있는 값은 거절합니다. 호출자의 진술이며, 검증된 신원이 아닙니다. |

입력·영수증 경로에는 상위로 이동하는 `..` 구성요소를 넣을 수 없습니다.
입력 열기를 지원하는 플랫폼은 macOS(`darwin`), `linux`, `freebsd`, `openbsd`,
`netbsd`, `dragonfly`입니다. 다른 플랫폼에서는 내용 열기를 거절합니다.

JSON 출력 플래그는 없습니다. 영수증 파일은 기계가 읽을 수 있는 JSON이며,
성공 후 stdout에는 검증한 원본 입력 바이트만 나옵니다. 상태와 호출자가
지정한 영수증 경로는 stderr로 나옵니다. 오류는 안전한 사유를 사용하며 원본
입력 텍스트를 포함하지 않습니다.

## 공개 fixture 예제

아래 직접 작성한 fixture는 `package fixture` 뒤에 줄바꿈 하나를 붙인 정확한
바이트입니다. 이번 읽기 실행과 독립적으로 이 문서에 고정한 해시는
`c9f09e0a76fbbf83847013f7d79aa09c1566778489cc499e76e3e5d72b1c8db6`입니다.

```sh
printf 'package fixture\n' > ./public-fixture.go
mkdir -p ./receipts
go run ./cmd/riido-reviewpacket \
  --input ./public-fixture.go \
  --sha256 c9f09e0a76fbbf83847013f7d79aa09c1566778489cc499e76e3e5d72b1c8db6 \
  --receipt ./receipts/read.json \
  --actor public-fixture-check
```

성공하면 stdout은 fixture의 바이트와 정확히 같습니다.
`./receipts/read.json`과 `./receipts/read.json.result`를 함께 보존합니다.
다음 실행에는 새 영수증 이름을 사용해야 합니다. 기존 산출물을 덮어쓰거나
복구하지 않습니다.

## 읽기와 영수증 저장 순서

1. 옵션과 경로 관계를 검사합니다. 잘못된 옵션, 상위로 이동하는 `..` 구성요소,
   같은 대상을 가리키는 경로, 기존 영수증 산출물은 시작 영수증이 생기기 전에
   거절될 수 있습니다.
2. 시작 영수증을 `0600` 모드로 배타적으로 새로 만들고, 기록한 뒤 동기화하고,
   상위 디렉터리도 동기화합니다. 이 단계가 모두 성공한 뒤에만 이 도구가
   입력 내용을 열 수 있습니다. 시작 영수증은 이후 수정하지 않습니다.
   두 영수증 저장과 디렉터리 동기화는 같은 상위 디렉터리 핸들을 유지하여
   경로가 이동하거나 다른 대상을 가리켜도 원래 디렉터리에서 수행합니다.
   기존 상위 디렉터리의 권한은 변경하지 않습니다.
3. 일반 파일만 엽니다. 지원하는 플랫폼에서는 내용을 열 때 nonblocking과 no-follow
   보호를 사용하고, 마지막 구성요소가 심볼릭 링크이면 거절하며, 열린 파일의
   동일성을 `lstat` 및 `stat` 메타데이터와 대조합니다. 읽기 버퍼는
   `max-bytes + 1`로 제한하므로 무제한으로 읽지 않고 한도 초과를 거절할 수
   있습니다.
4. 제한된 읽기를 완료한 뒤에 실제 SHA-256을 계산합니다. 입력 부재, 읽기
   실패, 크기 초과, 해시 불일치를 거절합니다. 끝까지 읽지 못했거나 크기를
   초과한 입력은 완전히 읽은 입력의 해시로 보고하지 않습니다.
5. 시작 영수증 경로에 `.result`를 붙인 같은 디렉터리의 최종 영수증을 `0600`
   모드로 배타적으로 새로 만들고 동기화합니다. 성공 결과는 시작 영수증의
   정확한 바이트에 대한 SHA-256과 검증 결과를 연결합니다. 그 뒤에만 stdout으로
   검증한 내용을 내보낼 수 있습니다.

시작·결과 영수증에는 입력/파일 경로를 넣지 않습니다. 선택적 공개 actor
라벨은 영수증에 포함될 수 있습니다. 결과는 JSON을 다시 직렬화하거나
정규화한 표현이 아니라 실제 저장된 시작 영수증의 정확한 바이트와 연결됩니다.
이번 실행의 근거를 확인할 때 두 파일을 함께 유지합니다.

도구는 숨은 재시도를 하지 않습니다. 내구성 있게 시작 영수증을 저장한 뒤,
최종 결과를 저장하기 전에 입력 확보나 검증이 실패하면 저장소가 허용하는 한
실패 결과를 남깁니다. 영수증 기록이나 동기화가 실패하면 기존 산출물을 보존하고
입력 내용을 내보내지 않습니다. 저장소가
고장 난 경우 내구성 있는 실패 기록까지 보장할 수는 없습니다. 완료된 결과가
없는 시작 영수증은 불완전한 근거입니다. 성공 결과는 출력 전 검증을 기록한
것이며, 이후 수신자가 stdout의 모든 바이트를 받았다는 증거는 아닙니다.

## 이 근거가 입증하는 범위

영수증이 입증하는 범위는 **이 도구가 중재한 이번 입력 내용 읽기 전에 의도를
기록했고, 내용을 내보내기 전에 바이트를 검증했다는 것**뿐입니다. 에이전트의
최초 읽기, 다른 도구·프로세스 전체의 전역 시작, 검토 품질, 정확성, 공급자/모델
신원 또는 S2 권한을 입증하지 않습니다. actor 라벨도 이 범위를 넓히지 않습니다.

이 명령과 fixture는 제한된 영수증 절차를 준비하고 검사하는 데 사용합니다.
성공하더라도 보존된 파일럿·감사 결과를 바꾸거나 cohort/Fit 적격성을 부여하거나
정식 데이터 읽기를 허가하지 않습니다.
