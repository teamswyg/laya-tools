# 관측한 두 요청을 학습 자료로 만들기

비슷한 함수가 실제로 어떻게 다른지 확인한 뒤, 기존 초안의 요청 2개를 개발용 학습 자료로 확정했습니다. 후보 5개의 유한 정답은 긍정 2개·부정 3개입니다. 반복 입력이 많다고 한 요청의 학습 가중치를 늘리지 않으며, 후보마다 가중치 1을 부여했습니다.

설명에 있던 미실행 동작은 빼고, nil 출력의 성공·빈 hook의 오류·실패 메시지 뒤의 줄바꿈을 명시했습니다. 새 설명은 Go에서 기존 512바이트·32단어 제한을 모두 통과했고 잘라내지 않았습니다. 함수 이름은 식별자로만 보존하며 모델이 읽는 설명에는 넣지 않았습니다.

두 요청은 개발용으로만 사용합니다. 기존 79개 자료와 평가·보정 자료는 그대로이고, 새로운 모델 학습이나 성능 평가는 아직 하지 않았습니다. 이번 라운드의 적격 자료를 30개·60개로 늘린 뒤 고정된 조건으로 비교합니다. 도메인별 보호 평가 2,400개 목표와 기존 효용 기준은 유지합니다.

다음 과제는 반올림입니다. 입력 6개와 후보 3개로 18개 관측을 준비했고, 계산 원리와 기대값은 별도 검토했습니다. 실제 실행은 아직 0회이며 원본 한 파일 경계·호환 제어기·컴파일 원천·자원 검사를 마친 뒤 실행합니다.
