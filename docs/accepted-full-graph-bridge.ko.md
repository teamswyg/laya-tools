# 전체 인벤토리의 검토 결과와 그래프 연결하기

`internal/acceptedfullbridge.Join`은 서로 다른 두 자료를 연결합니다. 독립
검토자는 **원본의 전체 인벤토리(FULL)**를 검토하고, 문장 작성 계획은 여기서
뽑은 **그래프**의 항목을 참조합니다. 검토의 기준은 끝까지 FULL입니다.
그래프의 해시를 FULL의 해시 대신 넣을 수 없습니다. 이 Go 인터페이스는
호출자가 제공한 고정된 바이트만 사용하며 파일·네트워크에 접근하거나 작성자,
검토자, 승인 기록을 새로 만들지 않습니다.

먼저 `inventoryprojection.Project`로 FULL·설정·원본 형식 계약·매핑 계약·
어댑터·Source 바이트를 확인하고 그래프를 실제로 추출합니다. 제공된 그래프는
추출 결과와 바이트까지 같아야 합니다. 그래프 추출 연결 기록은 일곱 필드
전체가 실행 결과와 같아야 합니다. 여기서는 실제 UTF-8 글자 경계를 검사하기
위해 Source 바이트도 필요합니다. 모든 입력은 별도로 기대한 상대 경로,
SHA-256, 정확한 바이트 수를 갖습니다.

새로 정의한 형식은 명확한 **일반 선언 형식**입니다.

| 형식 | 연결하고 검사하는 내용 |
| --- | --- |
| `Version` | 원본·수정본 인벤토리 선택과 별도 최초·재검토 관계, Source ID, Source·관찰·FULL·그래프·추출 연결 기록·작성자·현재 표준 Review·독립 FULL 검토·이전 기록의 고정 참조. |
| `Producer` | 같은 인벤토리 선택·Source·관찰·FULL, 이전 인벤토리 기록만. 작성자 ID와 행위자 값은 FULL의 작성자 선언과 일치해야 합니다. 작성자가 스스로 승인하는 필드는 없습니다. |
| `Acceptance` | 정확히 선택된 FULL·관찰·작성자·현재 Review, 현재 Review의 검토자 ID, `declared_pass`, `complete_full_inventory_official_and_support` 범위, 전체 공식 필드 목록, 이전 기록. 검토 시각은 현재 Review보다 이를 수 없습니다. |
| `History` | 같은 Source와 별도 이전 FULL·관찰·작성자·Review·버전 참조, `held` 또는 `superseded` 상태와 `inventory_predecessor` 또는 `review_predecessor` 관계. 참조하는 이전 기록 본문은 열지 않으며 검증 완료로 취급하지 않습니다. |
| `Frame` | 승인 대상 FULL과 추출 연결 기록의 별도 참조, `riido-projected-family-plan-v1` 형식의 `semanticframe.Frame` 작성 계획. 계획의 인벤토리 참조는 그래프이며 원본 형식 계약과 선택 버전 연결이 일치해야 합니다. |

현재 `sourcecohort.Review`는 보류 없이 전체 구조 검토 통과를 선언하고,
Source·관찰·의존 관계가 정확히 일치해야 합니다. 제공된 공개 reviewpacket
읽기 시작·결과 기록은 그 Review의 검토자 행위자, Source 해시·크기, 기록된
한 번의 읽기 시도, 시각 순서를 연결합니다. 별도 검사 연결 기록·결과도 정확한
관찰·Source 스키마에 연결하고 실행 시각은 읽기 종료와 Review 사이여야 합니다.
이는 **기록의 연결 확인**입니다. 행위자의 신원을 인증하거나 에이전트의 생애
최초 읽기를 증명하거나 과거 검사기를 다시 실행하지 않습니다.

역할 ID가 달라도 작성자와 검토자·읽기 행위자가 같은 선언이면 거부합니다.
이 일반 계약에서는 ASCII `label`과 `/root/label`을 대소문자를 구별하는 같은
행위자 이름으로 취급합니다. 다른 네임스페이스나 중첩 경로는 추측하지 않고
거부하며 별도 명시적인 계약이 필요합니다. 이름이 다르다고 실제 사람·에이전트·
제공자의 독립성을 인증하는 것은 아닙니다. 알려진 자기 검토 선언을 거부하는
검사입니다.

원본 인벤토리 선택에는 이전 인벤토리가 없어야 하고 수정본 선택에는 있어야
합니다. 별도로 `first_review`에는 이전 검토가 없어야 하고 `fresh_review`에는
있어야 합니다. 이전 검토 관계는 FULL·관찰·작성자가 같고 Review·버전 참조가
달라야 합니다. 따라서 원본 인벤토리를 수정하지 않고도 이전 절차 보류를 남긴
채 새로운 독립 검토 결과를 사용할 수 있습니다. 이전 기록을 재귀적으로
승인하거나 보류를 통과로 바꾸지 않습니다. 현재 보류
Review는 현재 승인으로 쓸 수 없습니다. 입력·FULL의 출처 참조·이전 참조·
검토 방법과 읽기 기록·작성 계획의 방법 참조까지 모두 함께 확인합니다. 같은
고정 참조의 반복은 허용하지만 같은 경로가 다른 내용을 가리키면 거부합니다.

지원 근거만 수정하면 그래프 바이트는 같아도 FULL 바이트가 달라질 수 있습니다.
이때 FULL·설정·추출 연결·선택 버전·작성자·독립 검토·작성 계획의 참조를
명시적으로 갱신해야 합니다. 그래프가 같더라도 이전 FULL의 승인을 재사용하면
거부합니다. 따라서 V3의 `semanticframe.NormalizeAccepted`로 그래프 승인을
만들지 않습니다. `semanticframe.JoinGraphPlan`은 그래프와 계획의 구조 검사만
공유하며, 단독 호출로 FULL 승인까지 확인하지 않습니다.

```go
result, err := acceptedfullbridge.Join(inputs)
// 고정된 바이트를 제공합니다. 함수는 파일을 열거나 쓰지 않습니다.
// result.Projection에 정확한 FULL 원본과 별도 해시의 그래프가 보존됩니다.
```

입력 하나가 128 KiB, Source가 16 KiB, 읽기 기록이 8 KiB, 합계가 8 MiB를
넘으면 입력 전체를 거부합니다. 독립 검토·이전 기록 목록은 각각 256개,
등록 Source ID는 400개까지입니다. JSON 토큰 사전 검사로 목록·객체 256개,
중첩 32단계 제한을 적용한 다음 자료를 할당합니다. 키·ID·문자열도 제한하고,
작성 계획은 JSON 이스케이프 확장 크기를 검사한 뒤 정렬·포인터 분리를 합니다.
오류는 고정 코드로 반환하며 입력 문장·ID·경로를 포함하지 않습니다. 실행
코드는 크기가 제한된 배열·정렬 슬라이스를 사용하며 전역 잠금·Python·모델
의존성을 추가하지 않습니다.

**실제 과거 기록과의 연동은 아직 미완료입니다.** 일반 선언 형식을 보고 기존
기록의 스키마를 추측하면 안 됩니다. 선택 버전·작성자·독립 FULL 검토·이전 및
현재 상태 기록의 정확한 형식을 원문 없는 자료로 내보내야 합니다. 스키마 이름,
필드 이름·자료형·null 허용 여부, FULL·관찰·검토자 연결, 원본·수정본 관계,
원본 스키마와 공식 필드 목록이 필요합니다. 검토한 어댑터가 기존 기록을 그대로
보존·고정 참조하고, 공식 판단과 지원 근거 전체의 독립 검토를 작성자 플래그나
구조 검사 결과와 구별해야 합니다. 이 함수는 해당 내보내기나 변환, 실제 자료
투입, 작성 계획 생성, 정답 라벨 생성, 모델 학습을 하지 않습니다. 실제 추출·
작성 전에 전체 Source QA가 여전히 필요합니다.

성공 상태는 `FULL_ACCEPTANCE_AND_GRAPH_PLAN_DECLARATIONS_JOINED_QA_PENDING`입니다.
`MeaningProven`과 `TrainingEligible`은 계속 false입니다. 의미·충실도·전체
자료 QA·이용 권리·검토자 및 제공자 독립성·실제 유용성은 증명하지 않습니다.
시험은 공개 소프트웨어용으로 새로 만든 자료만 사용하며, 그래프가 같은 지원
근거 수정, 이전 보류, FULL·그래프 바꿔치기, 행위자 불일치, 부분 검토 범위,
참조 충돌과 자원 제한을 포함합니다.
