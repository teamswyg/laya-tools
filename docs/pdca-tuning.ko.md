# 난이도 모델 PDCA와 다음 튜닝 준비

[English](pdca-tuning.en.md) · [실행 체크리스트](https://github.com/teamswyg/laya-tools/issues/11)

## 이번에 판단하는 것

사용자가 준 작업 설명을 fast / standard / strong 중 어디에 가까운지 평가하는
**결정 모델**을 학습합니다. 코드나 작업 계획을 생성하는 모델이 아닙니다.
난이도 모델을 먼저 개선하며 분할 모델은 별도 과제입니다.

“정답”은 현재 자체 작성한 난이도 기준입니다. 실제로 어떤 Codex 모델이 작업을
성공시키는지, 요금제 사용량이 얼마나 줄어드는지는 아직 측정하지 않았습니다.
수용 신뢰도 0.9를 통과해도 자동 실행 권한을 주지는 않습니다.

## 작은 실험을 반복하는 방법

1. Plan: 가족별 train/validation/calibration/test를 고정하고 계획·데이터 해시를 이슈에 먼저 기록합니다.
2. Do: 동일 원본에서 두 seed를 각각 학습합니다. validation 손실로만 체크포인트를 선택합니다.
3. Check: 두 후보를 고정한 뒤 새 final, 기존 영문 사례, 선택지 순서 변경을 검사합니다.
4. Act: 실패는 보존합니다. 이미 본 final은 개발용으로 이동하며 새 사이클은 새 final을 씁니다.

두 seed는 같은 데이터의 반복 실행입니다. 독립 데이터셋 두 개가 아닙니다.
가족을 분리해도 작성자·문체·문제 패턴은 공유되므로 독립 저장소 일반화를
입증하지 않습니다. 여러 사이클의 새로운 소규모 시험을 통과할 때까지 반복하는
것도 선택 편향을 만들 수 있으므로 모든 실패와 시도 수를 공개합니다.

## 바꾸지 않는 1차 개선 기준

- final 정확도 80% 이상, 원본보다 낮지 않음.
- strong 재현율 87.5% 이상, strong→fast 오류 0건.
- 기존 신뢰도 0.9에서 수용률 25% 이상, 수용 정답률 90% 이상.
- 정확도 10%p 상승 또는 Brier 오차 10% 이상 감소.
- 선택지 순서 변경 시 결과 뒤집힘 10% 이하.
- 기존 영문 사례 정확도 하락 5%p 이하.
- 두 seed 모두 위 조건 통과.

원본과 학습 모델 모두 동일 calibration 데이터와 temperature 탐색 범위를
사용합니다. 작은 12건 calibration의 한계는 남습니다. 선택지 순서를 여섯 번
평가한 수는 독립 사례 수로 세지 않습니다.

## 재현과 자원

[PDCA-01](../benchmarks/training/pdca-01), [PDCA-02](../benchmarks/training/pdca-02),
[PDCA-03](../benchmarks/training/pdca-03)에 고정 계획과 데이터가 있습니다.
유지보수자만 Python 학습 환경을 사용하고 사용자 런타임은 Go를 유지합니다.

MPS에서 encoder/action head를 동결하고 head/type_emb/scorer를 학습합니다.
CPU fallback은 끕니다. 동결 가중치 해시, 유한한 gradient/loss, 저장 후 재로딩,
출력 파일 해시를 검사합니다. 모델을 한 번에 하나씩 실행하며 RSS 5GiB,
시스템 메모리 여유 20%, 디스크 여유 30GiB, seed당 20분 한도를 검사합니다.
프로세스 RSS와 MPS driver 값은 통합 메모리에서 겹치므로 합산하지 않습니다.

CI에는 torch나 모델 다운로드 없이 실행되는 고정 계획/가족 분리 검사를
추가했습니다. 로컬 MPS 실측과 CI의 무거운 학습 재실행은 서로 다른 검증입니다.
학습된 가중치는 원본과 결합하는 약 100MiB head이며 현재 Go ONNX 모델의
대체 파일이 아닙니다. 새 배포는 버전을 올리고 정확한 소스 commit의 CI 성공을
요구합니다.

## 다음 튜닝의 준비물

[공개 작업 후보 6건](../benchmarks/training/public-task-candidates.json)은
이 저장소의 고정된 공개 commit에 연결됩니다. 주석 변경, 조건 추가,
동시성/권한 처리까지 포함합니다. 두 코드 가족을 공유하므로 여섯 독립 가족이
아닙니다. 각 후보에 예상 난이도, 이유, 완료 조건을 적었지만 실제 모델별
실행 결과는 비어 있습니다. 이번 학습에는 넣지 않습니다.

다음 단계는 다음 순서로 수행합니다.

1. 공개 실제 작업의 새 가족과 한국어 사례를 수집하고, 난이도 이유·모호함을 검토합니다.
2. 동일한 작업/제한/검증 아래 모델별 성공, 재시도, 지연, 실제 사용량을 기록합니다.
3. 성공한 최소 비용 프로파일을 목표로 삼되, 성공 결과가 없는 작업은 미확정으로 둡니다.
4. 분할은 부모 작업과 자식 작업의 의존성·통합 실패·전체 비용으로 별도 평가합니다.
5. Go ONNX 변환 뒤 CPU/MPS/ONNX 선택·확률 차이, p50/p95, RSS, native 메모리를 측정합니다.
6. 이전 버전과 새 버전을 병행 비교한 후에만 기본 모델 변경을 검토합니다.

새 데이터의 출처·라이선스를 기록하며 비공개 코드, 고객 요청 원문, 토큰은
수집/게시하지 않습니다. 새 유료 모델 실행이나 자동 반복 일정은 시작하지 않았습니다.
