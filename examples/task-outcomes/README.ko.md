# 직접 작성한 이벤트 예제

[English](README.md)

두 JSONL 파일은 파서 검증을 위해 직접 작성했습니다. 실제 모델 응답·작업 완료
기록·모델 평가·비용 절감의 증거가 아닙니다. 실제 요청이나 자격증명은 포함하지
않으며, 이 원본 예제에는 저장소의 Apache-2.0 라이선스를 적용합니다.

```sh
go run ./cmd/riido-taskoutcome --input examples/task-outcomes/complete-authored.jsonl
go run ./cmd/riido-taskoutcome --input examples/task-outcomes/partial-authored.jsonl
```

첫 예제의 관측 합계는 입력 250, 캐시 입력 110, 출력 50입니다. 캐시 입력은
이미 입력에, reasoning 출력은 이미 출력에 포함됩니다. 이를 다시 더하거나
청구 토큰·구독 사용량·요금으로 환산하지 않습니다. reasoning은 한 turn에서만
관측되므로 관측 합계 5와 별도로 전체 합계는 미확정입니다. 두 번째 예제는
입력 100·출력 20의 관측값을 보존하되 실패한 두 번째 turn 때문에 전체 사용량을
확정하지 않습니다.

`requested-model`, `requested-reasoning`, `task-label`은 호출자가 제공한 짧은
식별자입니다. 실제 사용된 모델의 증거가 아닙니다. 실제 모델·프로세스 종료
코드·실행 시간·작성 출처·요구사항 충족 여부는 `unknown`으로 남습니다. Codex를 실행하거나 임의의
승인 옵션을 받지 않습니다. 작업 완료는 나중에 독립 검증기가 작업 명세·고정
base·결과 파일을 연결해 확인해야 합니다.

메시지·명령·경로·thread/item 식별자는 집계에 보관하지 않습니다. SHA-256은
공백과 개행을 포함한 입력 bytes를 연결할 뿐 작성자나 실제 실행을 증명하지
않습니다. 누락된 사용량은 0으로 채우지 않습니다. 필드별 관측 합계·관측 turn
수·완료된 turn 중 누락 수·전체 합계를 구분합니다. 캐시 값만 없으면 알려진
입력과 출력은 보존됩니다. 실패·미종료·알 수 없는 control 이벤트가 있으면
전체 사용량은 미확정입니다. 선택 필드인 reasoning의 완전성은 별도로 표시합니다.

한도는 전체 64MiB, 한 줄 1MiB, 이벤트 100,000개, turn 4,096개입니다. 원문
item도 줄 한도 안에서 읽고 버립니다. 잘못된 입력은 원문 없는 고정 오류 코드로
반환하며, 성공한 JSON 기록을 출력하지 않습니다.
