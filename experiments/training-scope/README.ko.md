# 후속 숫자 모델의 학습 범위와 입력 계약 — 실험 41

**실제 파일 검색용 숫자 모델의 입력 16개를 고정하고, 긴 질문·큰 후보 목록을 처리하는 별도 Go 경로를 추가했다.** 기존 기본 API 한도는 유지한다. 이번 단계는 입력 계약과 이용 범위 정리이며 실제 새 모델 학습이나 법적 일괄 승인, HF 배포가 아니다.

[범위 계획](plan-41.json)과 [특징 계획](path-features-41.json)은 구현 전에 커밋했다. 후속 학습은 추론 시 계산 가능한 숫자를 사용해 보조 검색이 도움이 될 가능성을 제안하는 목적이다. 결정을 강제하거나 후보를 삭제하는 모델이 아니다.

현행 [GitHub 약관 D.6](https://docs.github.com/en/site-policy/github-terms/github-terms-of-service#6-contributions-under-repository-license)은 저장소 라이선스 아래 기여와 별도 계약의 우선 적용을 설명한다. GitHub 자신에게 주어진 AI 학습 권리를 우리 권리로 가져오지 않으며, 현행 조항을 과거 이슈 전부의 권리 증명으로 소급하지 않는다.

이는 카드의 빈 라이선스 필드만으로 학습 금지를 단정할 근거가 없다는 판단을 뒷받침한다. 다만 각 원 저장소/작성자의 조건을 일괄 대신하지 않는다. Prefect의 문제된 과거 시점은 [README](https://raw.githubusercontent.com/PrefectHQ/prefect/c36f1a2bc58e1e3b18e2a63f8a6ac1d92e045f10/README.md)까지 확인했으나 허가 문구를 찾지 못했다. 현재 Apache 분류로 이 공백을 메우지 않는다. 원 README를 복사·게시하지 않고 참조와 식별자만 남긴다.

### 진행 범위

[기계 판독 정책](policy-41.json)은 기술적 진행 판단과 권리 확인을 분리한다.

| 대상 | 이번 판단 |
|---|---|
| 고정 개발 자료의 검사·숫자 입력 구현 | 진행 |
| 자체 숫자 헤드의 로컬 학습 | 출처 적격성과 사전 실험 규칙을 확인한 자료에 한해 진행 가능한 범위로 정의; 아직 새 학습 실행 전 |
| 권리가 미확인/충돌하는 시점 | 미확인 상태 유지, 학습 가능으로 조용히 바꾸지 않음 |
| 이슈·코드·패치 원문 재배포 | 승인하지 않음 |
| 원문 생성 모델/원 인코더 파인튜닝 | 이 좁은 검토의 범위 밖 |
| 새 모델의 HF 공개·기본 활성화 | 별도 출처/산출물/품질 검증 전 승인하지 않음 |

역할 소속은 학습 7,335개·검증 5,686개·최종 2,402개 그대로다. 권리·목록·정답 미확보를 이유로 행을 분모에서 지우거나 다른 역할로 옮기지 않는다. 학습에서 제외되는 경우에는 모델 결과를 보기 전에 이유를 기록한다. CI는 기술 검증 관문이며 모든 권리에 대한 법적 보증이 아니다.

### Go 입력 계약

새 `searchclaim.PathFeatures`는 `riido-path-claim-v1` 전용 API다. 128KiB까지의 유효한 UTF-8 질문과 최대 100,000개 경로 후보의 기본 검색 점수를 받는다. 기존 `Features`의 8KiB/4,096개 한도와 `ScoreSpread`의 4,096개 한도는 유지한다.

16개는 기존 12개 숫자와 상위 20개 점수 분포 4개다: 상수, 단어/바이트 수, 대문자·숫자·밑줄 비율, 단어당 camel 경계, 고유 단어 비율, 상위 점수·점수 차이, 상위 10개/전체 양수 점수 비율, 상위 20개 상대 평균·표준편차·첫 점수 점유율·마지막/첫 점수 비다. 모든 값은 유한한 [0,1]이다. 긴 질문의 바이트 특징은 기존 8KiB 스케일에서 1로 포화하며 원 질문을 잘라내지 않는다.

정답 경로·정답 순위·보조 검색 결과·저장소 ID는 함수 입력에 없다. 단어/경로의 식별자를 모델 특징으로 넘기지 않는다. 기본 검색 인덱스가 생성한 순위를 전제로 하며, 이 함수가 임의 외부 순열 전체를 인증하는 것은 아니다. 새 경로를 만들었다고 이전 도메인의 가중치를 자동 적용하지 않는다.

합성 검사에서 짧은 입력의 16개 값이 기존 두 함수 조합과 정확히 일치했고, 긴 한글 질문/10,000개 점수, 128KiB/100,000개 경계, 잘못된 UTF-8·점수·범위, 호출자 배열 보존을 확인했다. 전체 race/vet/형식/redacted scan을 통과한 뒤 공개한다. 수집과 동시 진행했으므로 시간·메모리 개선이나 SIMD 효과를 주장하지 않는다.

다음 학습 전에는 출처 적격성 표, 비용 목표, 기준선, 초기값, 자원 예산 및 검증 선택 규칙을 고정한다. FP32에서 유용한 신호를 먼저 확인하고 3진 변형은 독립 측정한다. 최종 평가를 반복해서 보며 튜닝하지 않는다. 현재 실제 비용 절감과 모델 유용성은 여전히 미입증이다.
