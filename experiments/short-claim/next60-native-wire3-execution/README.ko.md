# 실제 함수 관측과 고정 기대값 비교

작은 `riidolaya` 주장·힌트 모델이 후보를 확인할 순서를 제안하려면, 먼저 설명이 실제 동작과 맞는지 검증해야 합니다. 이 묶음은 Union 디렉터리 읽기와 JSON 중복 키 처리라는 **두 개발 요청**을 원본 Go 라이브러리로 관측한 기록입니다. 모델이 내린 결정이나 새 학습 결과가 아닙니다.

## 이번에 확인한 것

| 항목 | 실제 값 |
| --- | ---: |
| 요청 / 고정 입력 / 후보 설명 | 2 / 13 / 6 |
| 저장·검증을 마친 후보별 입력 행 | 39 |
| 고정 Wanted 비교 | 통과24 / 불일치12 / 관측 불가3 |
| 직접 계측한 원본 메서드 / 자체 콜백 | 96 / 89 |
| 저장 응답을 확인한 프레임 | 528 |
| 자식 전체 실행 시간 | 2.748737667초 |
| 자식 최대 RSS, macOS에서 Wait 후 측정 | 12,189,696B ≈ 11.63MiB |
| 보관 실행 파일 | 4,575,474B ≈ 4.36MiB |
| 실제 결과 파일 / 저널 | 14,303B / 404,858B |
| 새 Laya 추론 / Fit / 보호 평가 행 | 0 / 0 / 0 |

한 번의 유한 관측입니다. Sync와 프로세스 준비를 포함한 시간이며, 반복 벤치마크나 Laya 모델의 지연·메모리 측정이 아닙니다. GPU를 사용했다는 증거는 없습니다. `GOMEMLIMIT=64MiB`는 Go 힙의 안내 값이고 하드 RSS 제한이 아닙니다. 시작·중첩 원본 호출 수는 미확인으로 유지합니다.

39행은 `6×3 + 7×3` 조합입니다. 입력이나 후보·번역을 늘려도 독립 요청 수가 늘지 않습니다. 기존 연결 그룹79·83의 `development_train` 역할을 그대로 이어받으며, 새 독립 원천·20→60 독립 코호트·보호2400 평가 추가는0입니다. 전체 작업의5% 이상 개선이나 비용 절감도 입증하지 않았습니다.

## 두 요청을 쉽게 보면

첫 요청은 겹치는 두 목록을 합친 뒤 여러 번 나눠 읽는 작업입니다. 모든 항목을 한 번 캐시하고 커서를 옮기는 설명은 고정6입력을 통과했습니다. 매번 원본에서 양수 개수를 읽거나 처음부터 전체를 다시 읽는 설명에는 항목 누락·반복 또는 반환 계약 차이가 있었습니다.

두 번째 요청은 JSON 객체 내부의 중복 키를, 값이 하나로 합쳐지기 전에 잡는 작업입니다. `a`와 `\u0061`은 같은 해독된 키입니다. 해독된 키를 객체마다 별도로 확인하고 첫 중복에서 멈추는 설명은7입력을 통과했습니다. 문자 표기만 비교하면 escape 별칭을 놓칩니다. 이미 Map으로 바꾸면 중복 정보가 사라지고 오류·위치·중단 채널도 없습니다. 이는 요청 계약과의 차이이며 원본 라이브러리 버그라는 주장이 아닙니다.

| 요청 | 후보0 | 후보1 | 후보2 |
| --- | --- | --- | --- |
| Union | 6T → T | 2T·4F → F | 3T·3F → F |
| JSON | 4F·3U → F | 6T·1F → F | 7T → T |

T는 모든 고정 조건이 확인됐다는 뜻입니다. F는 적어도 하나의 알려진 반례가 있다는 뜻이고, 함께 남은 U를 지우지 않습니다. U만 있는 후보를 음성 라벨로 바꾸지 않습니다. 각 조건은 [저장 비교](NATIVE-CACHE-RESET-WANTED-COMPARISON.actual.public.v1.json)에 남습니다. 라벨의 채택·자료 생성은 별도 단계입니다.

## 발견한 오류와 수정

첫 실제 실행은 첫 행을 저장하기 전에 실패했습니다. 우리 관찰 코드가 전체 캐시 결과 버퍼를 첫 부분 결과로 재사용해 사용하지 않는 항목이 남았습니다. `InfoReturn{}`으로 결과 목적지를 새로 시작하도록 수정하고, 비어 있지 않은 목록의6개 회귀 대조 사례를 추가했습니다. 실패 실행 파일과 부분 저널은 그대로 보존했습니다. 수정 실행은 새 파일·새 기록으로 한 번 실행했고, 고정 Wanted나 원본 소스를 수정하지 않았습니다.

비교기에서도 알려진 null과 미확인 값을 구분하고, 내부 복구된 원본 패닉을 별도로 반례에 남기며, 모든 행을 상태 전진 전에 검증합니다. 테스트용 가짜 API와 실제 원본 실행을 구분합니다.

## 사용 관점

Go1.27.1 환경에서 다음 명령으로 공개 자체 대조 사례를 재현할 수 있습니다.

```sh
bash scripts/verify-next60-native-wire3.sh
```

기존 공개 wire3·core·파일·저널 모듈을 임시 폴더에 복원하고 수정 부분을 덮어쓴 뒤 race 검사, `panicnil=1` 검사, 정적 검사와 포맷 검사를 합니다. 기본 CI는 가짜 API와 임시 파일을 사용합니다. 원본이나 모델을 다운로드·실행하거나 학습하지 않습니다. 새 CI 통과 여부는 PR에서 별도로 확인하세요.

`source/controller`는 원본 자식을 한 번 시작·회수하고 파일·저널·ACK·정상 EOF를 대조합니다. `source/comparer`는 저장 자료만 비교합니다. `source/core-overlay`는 캐시 결과 수정과 회귀 사례입니다. `source/archive`는 과거 실행 파일을 보관하는 유지보수 도구입니다. `source/compiler`와 `source/native-worker`는 선택형 macOS 원본 관측용 소스이며 기본 검사에서 원본 실행은 하지 않습니다. 이 연구 묶음은 기본 `riidolaya` 실행 명령에 자동 등록되지 않습니다.

원본 재현은 별도 공간 예산, 고정 revision·라이선스·파일 SHA, fresh 출력 경로를 먼저 확인해야 합니다. 템플릿의 `originals`는 실제 고정 원본 디렉터리를 뜻합니다. 실행 파일·원본 본문·원시 저널·개인 경로는 GitHub에 올리지 않습니다. 공개 소스는 자체 관찰·비교·보관 코드이며 원본 라이선스를 대체하지 않습니다.

## 저장 공간을 확보한 방법

첫 실패 실행 파일을 남기고 새 실행 파일을 만들기 위해, 완료된 과거 GJSON 실행 파일2개를 압축 보관했습니다. 원본6,339,316B를 gzip2,753,963B로 바꾸어 제어 기록을 제외하고3,585,353B를 확보했습니다. 원본과32KiB씩 직접 비교하고 크기·SHA·CRC·ISIZE·단일 멤버·EOF를 확인한 뒤 COMMIT을 저장하고 원본을 한 번 삭제했습니다.

이번 방식은 **스트림 비교**이며 실제 디스크 복원을 했다는 뜻은 아닙니다. 기존44개 실제 복원 검증 보관 절차와 구분합니다. 실패 부분 파일도 보존하고 자동 재시도하지 않습니다. 유지 연구 자료512MiB 제한은 실제 누적 파일 기준으로 계속 적용하며 Mac 전체 RAM·디스크 용량과 구분합니다.
