# Source80 observer preparation handoff

Preparation is complete. The native observer, upstream package initializers, original APIs and original tests have not been executed. Adapter work, original package imports and binary builds began only after a separate author had derived and sealed the Want document from source. This handoff does not establish observed results or training eligibility.

The scope is three behavior goals from two public source families: 8 UUID Parse fixtures, 8 UUID Scan fixtures and 8 original humanize Ordinal fixtures, totaling 24 finite fixtures. These are not 24 independent parents or 24 new labels. UUID preserves all 15 retained non-JS runtime Go files, its original go.mod and complete BSD-3-Clause LICENSE. Ordinal is an explicitly declared source slice preserving one original ordinals.go, its original go.mod and complete MIT LICENSE. The 20 original source/module/license files and Want remain byte-exact. Ordinal64 and the full humanize package are not included.

The plan records **29 expected calls**: 24 direct entrypoints plus 5 explicit Error method calls. Each fixture can dispatch Error at most once. To retain unexpected errors, the plan separately fixes a conservative maximum of 24 Error calls and 48 tracked dispatches. Only the 16 Parse/Scan entrypoints have error-return channels; 48 is a loose cost bound, not an observed or achieved count. The expected 5 Error calls comprise one UUID URNPrefixError and four standard errorString calls. An unexpected dynamic error type retains its actual type and an unclassified counter.

The four namespace MustParse→Parse initializer locations are static source sites. Actual initializer callback/return counts remain null. Internal Scan recursion, Parse and fmt formatting calls are not dynamically instrumented. This is a Go native CPU observer, not a Laya or GPU execution experiment.

Before callbacks, the worker exclusively reserves a fresh directory and results.json, then fsyncs them. Every dispatch intent and callback return/panic has a synchronous partial checkpoint. Undispatched Got/Matches remain null. Returned observations preserve the UUID array hex, Scan receiver before/after, nil interface versus typed nil bytes versus nonnil empty bytes, input dynamic type, exact output string and nullable error channels. Error type `%T` does not invoke the Error method; the explicit message-producing Error call has separate budget and counters.

Panic payloads are never converted through arbitrary Error/String methods. Only their type and primitive string text are retained; other panic text stays null with an unobserved flag. Panics and Want differences retain the original record without Want rewriting or retries. Completed ordinary differences exit 0; observed panics, storage errors and incomplete runs exit nonzero. Final, partial and stdout use the same canonical JSON bytes. After an external interruption, only the last successful sync snapshot is evidence. In-flight returns and complete retention following a storage failure are not guaranteed.

The plan remains Frozen=false. Root will verify pins and reserve an outside attempt before changing only the false token to true and executing once with a 60-second outside limit, CPU 1, a 256 MiB Go soft heap setting and no automatic retry. The soft heap setting is neither a total RSS hard cap nor a measurement. Output stays below 1 MiB. Upstream initializers run before main, so the outside controller's start/timeout scope must remain separate from worker direct-call reservations.

Two compile-only builds used Go 1.27.1, darwin/arm64, CGO=0, trimpath and buildvcs=false. Original module bytes retain UUID's absent Go directive and humanize's Go 1.21 directive. Compiler package-selection metadata confirms the 15 UUID files and the one-file Ordinal slice; this is not execution. Three pure-package race invocations and three vet invocations passed. The final invocation passed 7 top-level tests and 13 subtests. The earlier 6-test invocation and intermediate boundary checks remain recorded. One failed patch context changed no source and is preserved in the ledger.

Neither the whole module nor native main was go-tested, because such tests can execute upstream initializers. These are author-run synthetic controls, without a human-blind or independent-source correctness claim. Separate Want authorship and source-only peer review are bound by their own reference pins. New labels, roles, weights, models, Features, Fit, protected-final reads, shared code changes and external publication remain 0. training_ready, production_ready and qualification remain false.
