# 작은 관측 결과를 정확하게 기록하기

[![CI](https://github.com/teamswyg/laya-tools/actions/workflows/ci.yml/badge.svg)](https://github.com/teamswyg/laya-tools/actions/workflows/ci.yml) · [English](README.en.md) · [진행 이슈](https://github.com/teamswyg/laya-tools/issues/19)

riidolaya의 저사양 실험 준비 코드입니다. 작은 모델을 자주 호출하는 시스템에서는 모델 밖의 복사·직렬화 비용도 줄여야 합니다. 잘못 기록한 결과로 학습하지 않도록 원본 함수의 반환/실패, 복사 실패, 관측 함수의 결과, 확인 응답을 구분합니다.

Go 1.27.1에서 저장소 루트의 `bash scripts/verify-next60-compact-evidence.sh`를 실행하면 checksum 확인 후 자체 합성 검사 34개와 하위 사례 5개를 실행합니다. 사람과 에이전트 모두 같은 경로를 사용할 수 있습니다. 원본 패키지·Laya·GPU·모델 다운로드·학습은 필요하지 않습니다. 이 파일들은 준비용 텍스트이며 일반 riidolaya 명령어에는 아직 연결하지 않았습니다.

| 자체 측정 | 기존 표현 | 압축 시제품 |
|---|---:|---:|
| 같은 합성 1행 복사·직렬화 시간, 3회 중앙값 | 12.958µs | 1.133µs |
| 호출당 할당 바이트 | 5,888 | 586 |
| 호출당 할당 횟수 | 3 | 7 |

압축 열에는 snapshot 생성 비용이 포함됩니다. 할당 횟수는 늘었지만 할당 바이트와 시간이 줄었습니다. 이 수치는 파일 동기화·해시·모델 추론·전체 작업 비용·RSS·GPU 메모리 측정이 아닙니다. pprof 원본은 로컬에만 보관하며, 누적 할당량을 프로세스의 최대 메모리로 해석하지 않습니다.

전체 고정 배열을 그대로 출력한 자체 결과는 179,946바이트였습니다. 새 형식은 활성 읽기/방문/값 목록만 저장하고, 미확인·참·거짓·null을 상태 비트로 그대로 보존합니다. 예를 들어 available-unknown은1, known-false는3으로 다릅니다. 오류 상태의 비트 의미도 별도로 유지합니다. 이는 관측 상태 표현의 압축이며 모델 가중치의 1.58-bit 양자화나 새 학습이 아닙니다.

행당 상한은 LF 포함 1,536바이트입니다. 고정 숫자 범위와 배열 길이를 모두 최대로 둔 보수적 자체 검사에서는 Union 행882 / JSON 행889바이트, 39행과 header/footer 예약4096바이트의 합38,631바이트였습니다. 더 보수적으로 최대 행 크기만 곱해도38,641바이트로 결과 파일 예약65,536바이트 안입니다. 실제 파일 구현이 이 예약을 지켜야 하며, 데이터 손실로 크기를 맞추지 않습니다.

다음 연결은 후보 완료 기록 이전에 snapshot을 복사·동결하고 결과 파일에 기록한 뒤, 그 행의 offset/길이/SHA를 검증 기록에 결속하는 방식입니다. 전체 파일을 동기화한 뒤 FINAL에 파일 SHA를 연결합니다. SHA는 바이트 대응을 확인하며 원본 호출이나 의미의 정답을 증명하지 않습니다. 엄격한 외부 reader, 상태 비트 의미 검증, wire3, 실제 파일/프로세스 수명주기와 원본 실행은 준비 중입니다.

초기 실패와 수정 전 소스는 history에 남깁니다. 원본 함수 연결용 source/worker는 자체 함수만 import하며 source/frame의 wire2를 사용합니다. source/compact의 ExecutionGate는 계속 ErrPending입니다. 모델·원본 소스 본체·바이너리·프로파일 본체·개인 입력은 포함하지 않습니다.

이번 단계의 새 원본 실행·모델 추론·학습·Golden 행은0입니다. 기존35개 개발 사례, 제안한20→60 cohort, 보호된 도메인별2400개 평가는 서로 다릅니다. 전체 검증 작업량5% 개선도 아직 확인하지 못했습니다.
