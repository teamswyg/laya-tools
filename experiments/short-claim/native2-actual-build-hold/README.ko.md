# 실제 빌드에서 발견한 실행 전 문제

PR107은 필수 CI 네 개가 첫 시도에 통과해 자동 병합됐습니다. Root는 실제 Go1.27.1/Apple Silicon/CGO0 관측기와 실행 제어기를 각각 한 번 빌드했습니다. 크기는 4,537,554B와 5,118,610B입니다. 모델 크기나 추론 RAM이 아닌 실행 도구의 디스크 크기입니다.

원본을 시작하기 전, 실제 빌드 정보에 `-ldflags`가 없는 것을 확인했습니다. Go는 로컬 경로 노출을 피하기 위해 `-trimpath`일 때 이 항목을 생략합니다. v4 제어기가 이 두 조건을 동시에 요구하던 검사는 실제 바이너리를 수용할 수 없습니다. 더미 테스트15개는 프로세스·파일 제어를 검사했지만 이 실제 빌드 호환성을 검증하지 않았습니다.

기존 계획, readiness, 실행 파일과 v4 공개 봉인은 그대로 보존합니다. 실제 controller/원본 Start·원본 관측·once marker는 모두0입니다. 이를 실행된 관측의 실패·재시도로 세지 않습니다. 원본의 초기화를 포함할 수 있는 `--help` 실행도 하지 않았습니다.

수정본 v5는 실행 파일을 실행하지 않고 Mach-O의 실제 Go 문자열 header와 연결된64바이트를 읽어 source/vector/readiness SHA를 비교합니다. 파일·주소·심볼·문자열의 범위를 제한하며 세 선언값을 바이트로 확인합니다. 이 검사는 compiler-independent 또는 커널 실행 시점의 공격 방지 증명이 아닙니다. 정확한 소스와 빌드의 소유권은 Root가 유지합니다.

수정한 소스의 독립 검토와 새 CI 뒤에 새로운 권리·소스·자원 계획을 고정합니다. 이전 계획의 핀을 고치거나 실패 모델을 활성화하지 않습니다. 현재 실제 corpus Fit3/8회·논리 모델3/16개이며 추가 학습은0입니다.
