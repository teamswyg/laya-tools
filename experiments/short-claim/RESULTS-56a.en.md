## Implementation

`riido-shortclaim` suggests an independent verification order for bounded requests and candidate descriptions. It validates lengths, Unicode, duplicate JSON keys and counts while retaining every candidate. It provides a resident JSONL `--stream`, `pkg/shortclaim`, and four nonlearned controls. Python, model downloads and external API keys are unnecessary. Existing Laya difficulty routing and Codex defaults remain unchanged.

The controls are fixed order, BM25, word/ordered-bigram matching and an explicit `behavior-v1:` grammar. Rules are not guessed from prose. All48 natural-language development requests are out of grammar scope, producing **48/48 BM25 fallbacks** for narrow rules. Fast finite-grammar matching does not establish general language understanding.

## Data and truth

The authored dataset contains **48 parents,144 candidate descriptions,12 prototypes and11 connected groups**, all English from one author. It covers conditional retention, authorization negation, inclusive boundaries, summed quotas, stable filtering, first removal, adjacent compaction, rotation, nondecreasing order, clamp, prefix balance and arithmetic order. Variable/constant changes, translations and model settings are not independent requests.

Twelve correct and24 wrong Go functions are checked against68 literal vectors not generated by candidates. Applying each prototype's vectors to three functions yields204 base control checks; candidate-set checks are recorded separately. Source and normalized-code hashes, core templates, shared requests and negative candidates join transitively. Closed-window and clamp-window share a closed-boundary core, merging12 prototypes into11 groups.

Natural-language fidelity was independently read apart from Go tests. Under-specified acceptance and adjacent-compaction phrases were strengthened before scoring. Finite vectors and one independent reading do not certify general semantic truth. Source, labels, evaluator modes, roles and IDs are excluded from scorer features; only request/candidate descriptions enter scoring.

There are24 answerable requests,12 verified no-answer sets and12 unknown ambiguous policies. Unknowns remain in the original48 denominator but are excluded from utility and Top1/3. No-answer sets exhaust all candidates for both baselines and oracle. Acceptable sets may contain multiple candidates.

## Profile and optimization judgment

The frozen plan permits one separate narrow-rule profile with10,000 repetitions per stage; it is excluded from headline latency/RSS. Across1.34 profile seconds and1.06 sampled seconds, runtime.kevent accounts for0.88 flat seconds(83.02%), runtime.madvise0.07, BM250.02 and lexical tokens0.05 cumulative. **Do not call kevent an application CPU bottleneck or shared-lock contention.** [Go issue80921](https://github.com/golang/go/issues/80921) describes a separate go1.28-devel Darwin syscall stack-attribution report; it was reviewed as context, neither reproduced nor established as the cause of this go1.27.1 observation.

Candidate arrays bound8 slots, word arrays32, and frequencies use small contiguous arrays. There are no runtime maps, shared mutable state or shared locks. Selected `Rank` computes only its requested control. Normalization, validation and JSON still allocate, so this is not a zero-allocation tool. SIMD/SoA gains and an application hotspot are unproven; first validate profile attribution and stage resource costs.
