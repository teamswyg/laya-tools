# Source80: 동작 근거를 학습 후보로 연결하기

원 함수의 [24개 동작 확인](../native-observation-80/ACTUAL-RESULTS.ko.md)을 **사용자형 요청 초안 3개·비교 후보 9개**로 연결하는 작은 pilot입니다. fixture 수를 사용자 요청 수로 바꾸어 세지 않습니다. 아직 실제 후보 실행이나 학습 정답 승격이 완료된 자료는 아닙니다.

| 요청 | 비교할 세 후보 |
|---|---|
| UUID 오류와 부분 반환 바이트를 보존 | 오류 때 값 지우기 / 그대로 반환 / 오류를 panic으로 바꾸기 |
| DB 입력의 UUID 상태와 오류를 보존 | 그대로 Scan / 먼저 상태 지우기 / 오류 버리기 |
| 숫자의 서수 예외를 지켜 문자열 만들기 | 마지막 숫자만 확인 / 항상 th / 11·12·13 예외도 확인 |

각 후보는 [구체적인 Go 함수](preparation/candidates.go.txt)에 연결되어 있습니다. 잘못된 후보도 실제 코드의 동작을 충실히 설명하는 caption을 갖습니다. 코드가 요청을 만족하는지, 설명이 코드에 충실한지, 학습에 적격한지, 필요한 값·상태·오류 채널을 관찰했는지는 [별도 네 항목](preparation/CONVERSION-PROPOSAL.v1.json)으로 기록합니다. 현재 actual truth·role·mask·weight·Got·acceptable은 null입니다.

## 다음 검증의 범위

[과거 preplan](preparation/CANDIDATE-VERIFICATION-PREPLAN.v1.json)은 미봉인·미실행 상태로 보존합니다. 새 관찰에는 모든 후보와 같은 기존 입력을 사용해 **후보 호출 72회**를 계획합니다. 반환 오류의 Error 관찰은 예상 10회, 보수적 최대 48회입니다. 명시적으로 추적할 후보 호출과 Error의 합계는 예상 82회, 최대 120회입니다.

후보 코드 안에서 원 API를 한 번 사용하는 경로는 소스상 56회, 자체 Ordinal 코드 경로는 16회입니다. 이 내부 경로를 계측하지 않는다면 실제 원 API 계수는 null로 남깁니다. 72개 후보 dispatch를 72개 원 API 실행이라고 부르지 않습니다. 오류값으로 panic한 경우에는 type/present만 읽고, 오류 문자열을 추가 호출하지 않습니다. 실제 실행 전에 새 기대값·코드·계획을 봉인하고, 한 번의 자식 프로세스에서 전체 실패와 차이를 보존할 예정입니다.

## 데이터와 역할

[원천·역할 검토](family-review/REVIEW.v1.ko.md)는 기존 76요청·19그룹의 실제 역할을 보존했습니다. UUID Parse·Scan과 모든 파생 후보는 같은 원천 그룹이어야 하고, Ordinal 파생 후보도 함께 묶어야 합니다. 기존 자료의 명시적 원천 연결이 없으므로 현재 새 역할은 null입니다. 이전 조사·코딩 작업에 노출된 원천이며 새 독립 held-out 자료로 부르지 않습니다.

후보 코드 실행과 설명의 감독 적격성까지 확인한 뒤 고정 네 기준선과 oracle을 같은 전체 후보에서 비교합니다. 기존 그룹·역할·truth·mask·가중치·임계값을 바꾸지 않습니다. 세 요청만의 효용이나 최종 최소 2,400개 요청 달성을 주장하지 않고, 다음 한 번의 FP32 개발 학습은 전체 범위의 개선 여지와 적격 자료 확인 후 별도로 계획합니다.
