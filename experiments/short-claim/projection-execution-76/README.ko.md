# 전체 76개 요청의 첫 배열 준비

76개 개발 요청을 Go 학습기가 읽을 수 있는 배열로 만드는 첫 실행이 성공했습니다. 학습·추론 성능은 이후의 별도 기록으로 평가합니다. 이 준비 과정은 Laya 인코더나 GPU를 실행하지 않습니다.

| 용도 | 요청 | 후보 | 학습용 행 | 가중치 0 행 | 미확정 후보 |
|---|---:|---:|---:|---:|---:|
| train | 44 | 130 | 91 | 18 | 39 |
| validation | 20 | 60 | 45 | 1 | 15 |
| calibration | 12 | 36 | 0 | 0 | 9 |

기존 72개 요청의 문장·정답·후보 순서·마스크는 유지했습니다. 새 4개 요청은 공개 upstream의 유한한 관측에서 제안한 정답이며 원래 자료와 구분했습니다. 두 새 원천 그룹은 모두 train에 들어갔으므로 새 원천으로의 일반화 검증이라고 부르지 않습니다. 21개 미확정 요청의 후보 63개는 null 정답을 유지하고 학습 손실에서 제외합니다. 알려진 후보 중 가중치 0인 19개도 배열에서 삭제하지 않았습니다.

실제 Validate 76회와 Project 1회가 반환됐고 feature scan은 272회였습니다. 반환 배열의 소유 payload는 1,928,154 B(약 1.84 MiB), 전체 자식 프로세스의 최대 RSS는 50,036,736 B(약 47.72 MiB), 바깥 실행 시간은 0.475047292초였습니다. CPU 1개·Go heap soft limit 256 MiB·바깥 시간 제한 300초를 설정했습니다. 단일 준비 관측이며 Go heap/GPU 메모리·상시 추론 지연·LLM 비용 절감 수치가 아닙니다.

원본 결과는 8,390,462 B, SHA256 `f68bff5f48747a66f038c17262568c1bd91251a8c81b3f46f7ae5090c8fe4b99`입니다. 전체 feature 배열·private 계획·바이너리·로그는 Git에 넣지 않습니다. [실행 장부](actual/ROOT-ACTUAL-LEDGER-76.v1.json)와 [저장 배열 검토](runtime-qa/FINDINGS-RUNTIME-76.v1.ko.md)는 실제 실행과 검토를 구분합니다. 검토자는 준비 실행기 작성자와 다르지만 기존 claimfit 및 69/71 코드 작성 이력이 있는 비맹검 검토자입니다. 저장 값의 정합성을 확인했고 feature 의미를 새로 추출하지 않았습니다.

`preparation/execution-plan-76.v1.public-view.json`은 준비 당시 공개용 파생 보기입니다. 실제 frozen private 계획을 대체하지 않으며 그 SHA는 실제 장부에 있습니다. 당시의 준비 상태를 이후 실행 상태로 덮어쓰지 않습니다.

모델 fit·새 역할 지정·새 원래 정답·유료 모델 호출·보호된 최종 평가 읽기는 이 실행에서 모두 0입니다. 이후 첫 FP32 fit은 기존 설정과 동일한 검증 후보 전체로 평가하며 별도 기록합니다. 76개 요청은 원천 관계가 묶인 19그룹의 개발 자료이고, 도메인별 최소 2,400개 독립 요청을 목표로 하는 보호된 최종 골든셋을 대신하지 않습니다. 협업 AI 비용도 아직 측정하지 않았습니다.
