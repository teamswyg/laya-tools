# 37개 개발 요청의 후보 순서 비교

`riidolaya`의 작은 주장·힌트 모델은 검증할 후보의 순서를 제안하는 것이 목표입니다. 먼저 학습 없는 저렴한 방법을 기준으로 삼았습니다. **현재 어휘 순서 비교가 가장 좋은 기준이며, 새 모델이 이보다 유용하다는 증거는 아직 없습니다.**

| 학습 없는 방법 | 현재 순서의 첫 후보가 정답 | 첫 정답까지 단위 검사 수 | 순열의 요청별 평균 검사 수 |
| --- | ---: | ---: | ---: |
| 입력 순서 유지 | 6/37 | 71 | 1.9595 |
| BM25 | 26/37 | 51 | 1.3784 |
| 어휘 순서 비교 | 29/37 | 48 | 1.3378 |
| 제한된 규칙 | 26/37 | 51 | 1.3784 |

표는 보존한 Mac 실행의 결과입니다. Linux BM25·제한된 규칙의 순열 평균은 동점 반올림 영향으로1.3649였습니다. 양쪽 모두 어휘 순서 비교가 가장 좋았으며, 환경 차이를 성능 향상으로 계산하지 않습니다.

둘째 후보만 고르면 현재 자료에서 28/37입니다. 정답 위치가 `[6,28,3]`으로 치우쳐 있으므로 현재 순서의 적중률만 보고 학습 효과라고 말하면 안 됩니다. 제한된 규칙은 이 자료의 문장을 지원하지 않아 247회 모두 BM25로 되돌아갔습니다. 독립적인 규칙 성능이 아닙니다.

37개 요청의 기본 순서와 전체 순열210개를 각각 비교했습니다. 실제 호출247회, 순위988개, 활성 점수2,928개입니다. **독립 표본은247개가 아닙니다.** 2후보 요청과3후보 요청의 순열 수가 다르므로 요청별 평균을 동일하게 가중했습니다. 동점에서는 현재 표시 순서를 유지하고 후보를 제거하지 않습니다. 요청마다 유리한 방법을 골라 기준으로 삼지도 않습니다.

검사당 비용1을 가정한 진단입니다. 어휘 비교의 요청별 합계49.5와 완벽한 순서의 하한37 사이에는 약25.25%의 가상 여지가 있습니다. 완벽한 모델을 얻었다는 뜻이 아닙니다. 실제 검증기·전처리·추론·되돌아가기 비용을 모두 재야 전체 작업량5% 개선을 주장할 수 있습니다. 시간·토큰·금액·CPU/GPU 개선은 이 실험에서 측정하지 않았습니다.

실행 결과는 [results.json](results.json), 실행 후 파일 대조는 [POSTCLOSE](POSTCLOSE.actual.public.v1.json), 별도 Node 구현의 전체 행렬 재계산은 [INDEPENDENT-READBACK](INDEPENDENT-READBACK.actual.public.v2.json)에 있습니다. 별도 구현은 저장된 점수를 이용한 순서·순열·집계 검증입니다. BM25 점수 산출 자체나 실제 검증 비용을 독립 측정한 것은 아닙니다. 기존 조건별 미상 값은 원래 근거에 보존하며 부정 정답으로 바꾸지 않습니다.

Node 재계산이 확인한 집계와 확인하지 않은 JSON 필드는 [범위 보충](READBACK-SCOPE.ko.md)에 명시합니다.

Go1.27.1이 있는 저장소에서 재현하세요.

```sh
bash scripts/verify-next60-bias37.sh
```

이 명령은 자체 대조 사례를 검사하고, 공개37행을 읽어 학습 없는 비교를 한 번 실행합니다. 새 출력만 생성하며 원본 라이브러리·모델·Fit은 실행하지 않습니다. Linux/macOS 점수의 절대·상대 오차 기준은 각각1e-12입니다. 각 환경에서 저장한 실제 점수로 전체 순열의 순위·동점·비용·행렬 해시를 다시 계산해 정확히 대조합니다. 데이터·라벨·분모·학습 없음 등의 공통 사실은 동일해야 합니다. 오차 허용으로 실제 점수나 순위를 바꾸지 않습니다.

첫 Linux CI는 Mac 결과와 모든 집계까지 같아야 한다는 검사에서 실패했습니다. [Linux 실제 결과](LINUX-AMD64.actual.public.v1.json)의 최대 점수 차이는 약5.33e-15였지만, 한 요청의 BM25 두 점수가 같은 값이 되어 순열별 검사 횟수가 달라졌습니다. [독립 재계산](LINUX-INDEPENDENT-READBACK.actual.public.v1.json)은 Linux 자체 행렬과 집계가 정확함을 확인했습니다. [차이 기록](PLATFORM-READBACK.actual.public.v1.json)에 실패와 양쪽 결과를 보존합니다. 이 차이는 모델 성능 향상이나 실제 작업량 감소의 증거가 아닙니다. 점수가 충분히 떨어진 후보 쌍의 순서 일치는 계속 검사하고, 매우 가까운 점수의 순서 변화는 별도로 보고합니다.

결과 파일이 너무 크면 성공을 반환하지 않습니다. 저장이 정상적으로 끝난 경우에 한해 실패 원인·실행 횟수를 작은 기록에 보존합니다. 쓰기·동기화 실패는 별도 오류입니다. 이 유지보수 소스는 기본 CLI나 Codex에 자동 등록되지 않습니다.
