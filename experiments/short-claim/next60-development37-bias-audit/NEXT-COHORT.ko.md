# 다음 수집: 새 출처에서 다른 종류의 주장 확인하기

이 문서는 실행 전 제안입니다. **새 코호트 관측·라벨·역할·학습은 아직0**입니다. 기존37행에 변형을 더하는 대신 다른 코드 계보와 실제 구현 차이를 가진 사례를 수집합니다. 첫 제안은2부모·각5후보이며, 전체20개 목표를 충족하지 않습니다.

20→60 계획은 후보5개/8개와 정답 없음/하나/여러 개/미상 포함/해석 모호의10셀을 다룹니다. 처음20개에서는 각 셀2개를 목표로 합니다. 관측 후 실제 만족 후보 수로 셀을 정하며, 목표 수를 채우려고 요구사항이나 후보를 바꾸지 않습니다. 같은 코드·복사 함수·fork·번역·변형은 연결 가족으로 묶고 평가 역할을 섞지 않습니다. Bitset·GJSON은 이미 기존 개발 가족에 있으므로 새 독립 가족으로 세지 않습니다.

## 첫 두 제안

| 부모 계약 | 실제로 다른5개 구현 방식 | 확인할 입력·채널 |
| --- | --- | --- |
| xxhash의 짧은 상태를 검사한 뒤 원자적으로 복원 | 직접 바이트·lane 검사; public API로 재구성해 전체 바이트 비교; 기존 길이·magic 검사만 사용; decode→encode round-trip만 사용; 짧은 hash 결과만 비교 | seed0/7, 길이0/1/31/32, 미사용 tail·lane 변조, 잘못된 magic/길이, 실패 전후 수신 객체 |
| Chi가 raw 경로를 매칭한 뒤 opt-in 파라미터를 한 번 해독 | 매칭 후 PathUnescape; 매칭 후 QueryUnescape; 전체 경로를 먼저 해독; 반복 해독; 원래 인코딩 값 유지 | 명시한 RawPath/Path 쌍, `%2F`/`%252F`/`+`/`%20`, 일반 값·opt-out·미매칭·RawPath 없음, 응답·handler 횟수·두 파라미터 API·URL 전후 |

xxhash는 `total≤32` 범위를 제안합니다. `total<32`의 seed로부터 정해지는 lane과 미사용 tail을 확인하고 실패 시 기존 객체를 보존합니다. 경계32의 구조 규칙은 별도로 고정해야 합니다. 서로 다른 두 방식이 함께 맞을 가능성은 가설이며 정답2개로 미리 확정하지 않습니다. `purego` 빌드를 사용한다면 선택 소스와 빌드 설정도 고정하고 SIMD 성능 실험이라고 부르지 않습니다.

Chi는 `GET /u/{id}`, 빈 RoutePath override, opt-in 정책과 URL 필드를 명시합니다. RawPath가 없을 때 이미 해석된 Path를 다시 해독하지 않고, `+`는 문자로 남깁니다. 매칭 후 URLParam과 PathValue가 동일해야 하며 URL 원본과 opt-out 동작을 보존합니다. 잘못된 escape·regex·mount·context override는 첫 계약 범위에서 제외합니다. 등록 중 패닉 뒤 내부 노드 변화는 공개 API로 판별하지 못할 수 있으므로, 그것을 곧바로 부정 정답으로 만드는 별도 사례는 보류했습니다.

## 관측 전에 고정할 것

1. 원천 revision·선택 파일 SHA·라이선스 고지·실제 컴파일 범위를 확인합니다. 기존 자료 및 helper/fork의 연결 관계를 조사한 뒤 가족 전체 역할을 고정합니다. 관측 결과가 유리하다고 역할을 옮기지 않습니다.
2. 요청 해석·후보 코드/설명·표시 순서·모든 literal Wanted와 비교 채널을 별도로 검토하고 고정합니다. 코드 만족과 설명 충실성을 따로 검사합니다. 입력을 늘려도 부모 요청 수를 늘리지 않습니다.
3. 새5/8후보 Reader 권한·행/역할 핀을 고정합니다. T는 유한 범위의 모든 필수 조건 확인, F는 남겨 둔 알려진 반례, U는 판별 불가입니다. F와 조건별U가 함께 있어도 반례를 잃지 않습니다.
4. 후보U-only는 정답·가중치 null이며 지도 학습/정확도 분모에서 제외합니다. 정답0개는 모든 후보가 알려진F일 때만 확인합니다. 조건U가 있어도 알려진F인 후보를 제외할지는 새 정책에 명시합니다. 해석이 모호한 부모는 정답을 보류하고 clarification/abstain 대상으로 남깁니다.
5. 여러 정답과 전부 정답인 사례도 그대로 보존합니다. 대비 손실에 쓸 쌍이 없는 경우 억지 음성을 만들지 않습니다. 모든 후보를 되돌아가기 검증에 남기고, 정답0·U·모호한 요청은 성공 적중률에 섞지 않습니다.
6. 학습 없는 고정 기준과 실제 전체 비용 측정을 먼저 고정합니다. 전처리·추론·검증·되돌아가기 비용을 포함하고, 본 모델의 순위와 정답을 기준으로 유리한 비교 방법을 선택하지 않습니다.

이후 실제 관측→독립 비교→라벨 채택→Reader/변환/손실/평가의 미상 마스크 확인을 거쳐 학습 여부를 판단합니다. 이 두 개발 제안은 보호된2,400개 평가에 편입하지 않습니다. 새 최종 평가 자료와 성능·메모리 개선 검증은 별도 작업입니다.
