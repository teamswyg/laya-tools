# Native2 실행 전 검사 수정 v5

기존 검사는 Go 빌드 정보에서 세 개의 `-X` 선언을 찾았습니다. Root가 실제로 빌드해 확인하니 Go1.27.1은 `trimpath`를 사용할 때 이 선언 정보를 넣지 않았습니다. 실행 전 검사에서 막힌 것이며, 이 준비 시점까지 원본 관측 실행은 0회입니다. 이미 만든 Root 바이너리는 실행 없이 읽었습니다.

이제 macOS ARM64 바이너리 안에 저장된 closure·vector·readiness SHA 세 값을 직접 확인합니다. Go 문자열의 16바이트 헤더와 연결된 64바이트 소문자 16진수 데이터를 읽고 계획과 비교합니다. 심볼이 빠지거나 중복되거나, 주소·섹션·길이가 잘못되면 거절합니다. 원본 함수를 호출하거나 초기화하지 않습니다. 검사 범위는 심볼이 보존된 thin Mach-O64 little-endian ARM64 실행파일입니다.

파싱 전에 파일64MiB, 명령128개/128KiB, 섹션64개, 심볼10만개, 문자열 표8MiB, 심볼 이름별1024바이트/전체 복사량8MiB, relocation 전체10만개와 indirect symbol10만개 제한을 확인합니다. 표준 빌드 정보 검사도 Mach-O 파서를 호출하므로 이 제한 검사를 그 앞에 놓았습니다. Go1.27.1·모듈·CGO0·trimpath·darwin/arm64·VCS 정보 없음 조건은 유지합니다.

최종 25개 테스트가 통과했습니다. 합성된 잘못된 바이너리, 심볼 누락·중복, 범위와 길이 오류, 반복 이름 복사량, 표준 파서보다 앞선 차단, 실제 Root 바이너리의 세 값 일치와 잘못된 기대값 거절을 확인했습니다. 3차례 테스트 실행에서 가짜 자식 프로세스는 12회 시작·12회 대기했고, 의도한 실행파일 누락 실패3회에는 대기0회였습니다. 이는 원본 관측이나 모델 검증이 아닙니다.

실행 binding의 controller source 목록은 `main.go`, `pure/protocol.go`, `go.mod`, `bindings_macho.go` 네 개를 이 순서로 고정해야 합니다. 두 test 파일은 빌드 입력 목록에 넣지 않습니다. 기존 static reservation → readiness → native plan → 실행 binding → 내구성 있는 한번 실행 기록 흐름은 유지합니다. Root는 새 source/CI/resource 증명을 먼저 고정하고 새 readiness·worker·binding 연결을 별도로 만들어야 합니다. 기존 v4와 원본 observer 봉인은 그대로 남아 있습니다.

이 폴더의 소스는 리뷰용 `.go.txt` 정확한 바이트 복사입니다. Root가 CI와 권리·자원 조건을 확인한 뒤 프로덕션 controller를 빌드하고 원본을 한 번 실행합니다. 이 준비를 작성한 agent의 standalone production build·원본 실행·모델 API·외부 게시·보호 평가자료 접근은 모두0입니다. Root 소유의 기존 빌드·과거 학습 기록과 혼동하지 않습니다. 새 실제 결과는 별도 기록으로 붙입니다.

바이너리의 실제 데이터 확인은 컴파일러나 운영체제에 대한 독립 인증이 아닙니다. 초기화 이후의 런타임 값이나 의미적 정답을 입증하지 않습니다. Root proof는 바이트를 연결하며 그 내용의 권리·CI 의미 판독은 Root가 담당합니다. 테스트 성공은 23개 원본 관측의 성공, 정답·역할·학습 가중치 부여 또는 학습/배포 권리 승인이 아닙니다. 원본 벡터·후보·Want는 바꾸지 않았습니다.

`ACTIVITY.v5.json`은 소유 주체와 실제 검사 수를, `CORRECTIONS.v5.json`은 발견·수정 이력을, `PUBLIC-FINAL-PINS.v5.json`과 `SHA256SUMS`는 정확한 파일을 기록합니다. 공개 자료에는 호스트 경로·실행 바이너리·모델 가중치가 없습니다.
