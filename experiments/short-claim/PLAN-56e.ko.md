# 유한 입력 주장 감사56e: 결과 전 계획

작은 모델을 학습시키기 전에 **문장의 약속과 검사의 범위를 맞추고, 소스의 실제 동작에서 제한된 정답을 얻는 단계**다. 기존56c는 정해진 입력9개만 검사하는데 문구는 일반 동작을 말한다. 그 pending 상태를 승인으로 바꾸지 않는다. 별도 Go 패키지 `finiteproperty`와 명령 `riido-propertyaudit`에서 유한 입력 계약v2를 추가한다. 전체 목표인 초소형 힌트 모델의 학습·유용성 검증은 여전히 미완료다.

## 달라지는 계약과 공개 문구

새 요청에는 사전 직접 작성한 ASCII 입력의 hex 표현을 명시한다. 예를 들어 `0x22612c62222c63`은 `"a,b",c`의 바이트다. 문장 부호를 지우는 기존 정규화에서도 서로 다른 hex 단어는 남는다. 모델이 hex 의미를 이해한다거나 정규화 문제가 해결되었다고 단정하지 않는다. 기존56c의 “literal은 특징 금지” 정책은 그대로이며, 새v2는 **명시적 입력 집합이 요청의 일부인 별도 문제**다. 이는 구 문구를 보정한 동일 평가나 일반 함수 정확성 시험이 아니다.

문구는 AI-assisted 공개 합성 자료다. 독립 에이전트가 소스를 읽고 검토하며, 실제 사람 작성·승인으로 표현하지 않는다. 평가기가 숨은 literal/기대값을 문장에 자동 주입하지 않는다. 후보 설명에는 source ID, 기대 배열, 역할, 관측 후 성공/실패를 넣지 않는다. 요청·후보 문장만 후속 실험의 특징 후보가 된다. 이번 실행에는 순위·숫자 특징 인코더·학습 모델이 없다.

## 고정 범위와 정답

원본의 후보 ID·순서·code/source closure SHA를 유지한다. 부모4개×속성3개=12파생 행, 후보 설명36개다. 세 속성의 입력2/2/5개와 독립 authored 기대값은 `scopedproperty.Definitions()`의 기존9개를 그대로 사용한다. 그 안의 `pending`은 원본 기록이며 새 문구 검토 상태가 아니다. 공개 요청의 hex를 해석해 동일한 입력·순서·수인지 검사한다. 누락된 설명을 metadata로 채우거나 요청을 자동 생성하지 않는다.

오직 등록된 원천4개를 `typedbehavior.ObserveQuotedProperty`로 실행한다. 원천×입력=36실제 호출이며 같은 결과를12행의36후보 라벨에 참조한다. 후보 전체 함수의 correct/wrong 역할이나 기존 acceptable 집합은 새 정답으로 사용하지 않는다. `Error`, `Count`, 전체8개 `Tokens`, `Panicked`를 exact 비교한다. Syntax 입력은 정확한 syntax error가 필수라 OK+빈 출력도 불일치다. Count0에 잔여 token이 있어도 불일치, 관측된 panic도 불일치다. 관측기 지원 오류·변조는 정답 false로 바꾸지 않고 중단한다. 일치는 이 입력 집합에서만 유효하다.

모든 원천은 같은 `scanQuoted` helper 가족에 연결된다. 새 독립 부모/가족 증가0이다. 기존56b의72부모·17전체/16라벨 그룹과 delimiter unknown4를 변경하지 않는다. 12행이나36실행을 새로운 독립 요청 또는 보호 최종2400개로 세지 않는다.

## 실행 전에 봉인하는 순서

1. 코드·계획·독립 문구 검토·preparation 단위 검사·모듈·기존56c 기록을 source commit에 고정한다. 신규 단위 검사는 exact 비교/변조/길이/범위를 검증하며 후보 함수를 호출하지 않는다. 전체 기존 회귀 검사에는 역사적 후보 대조 실행이 이미 있으므로 “처음 본 소스”라고 주장하지 않는다.
2. Go1.27.1, CGO0, `-trimpath -buildvcs=false -p=1` 바이너리를 한 번 빌드한다. 실제 실행 파일 SHA와 크기를 계획에 넣고 본체는 Git 제외한다. 소스21개+support13개를 디스크와 실제 Git blob에서 확인한다.
3. `prepare`에서 후보 관측 없이 dataset/plan을 내보낸다. 두 파일을 `probes-56e.json`, `execution-plan-56e.json`으로 별도 input commit에 고정한다.
4. `audit --input-commit`은 동일 실행 파일·소스/support34개·입력2개, 총36 Git blob을 관측 전에 검증한다. JSON canonical byte 비교로 duplicate key, 숨은 extra fixed-array element, unknown field, null 변형, trailing object도 거절한다. 실패 시 자동 재시도0이다.
5. 공식 감사1회, 전체36호출의 입력·기대·관측과12행 결과를 공개 원문에 보존한다. 이후 CI replay는 동일 기록의 회귀 검사이며 새 표본이나 새 공식 시도가 아니다. 기존 출력 directory를 다시 쓰면 관측 전에 거절한다. 다른 directory로 재실행하는 것은 별도 시도이므로 공식 원장과 구분한다.

Go `GOMAXPROCS=1`, heap soft limit256MiB 설정이다. 이는 실제 RSS/CPU/GPU 측정이나 상한 보증이 아니다. 원문 파일은 각1MiB 이내로 제한한다. 준비·감사의 preflight는 typed24×4 + pending12×4 + finite12×4 =192번의 길이 검사 정규화를 각각 수행한다. 숫자 encoder/score/ranking은0이다. 원천·부모·literal metadata는 그 정규화 문장에 주입하지 않는다.
