# 작은 주장 모델: 요청 79개 실험의 준비 기록

이 묶음은 작은 모델이 검증 순서에 도움을 주는지 확인하기 위한 준비 자료입니다. 모델이 최종 결정을 내리기보다, 여러 후보 중 무엇을 먼저 확인할지 힌트를 주는 것이 목표입니다. 모델 출력만으로 코드를 승인하거나 배포하지 않습니다.

## 이번 실험에서 바꾸는 것

기존 공개 요청 76개에 새 공개 요청 3개를 학습용으로 추가합니다. 각 요청에는 후보 3개가 있어 새 학습 라벨은 9개입니다. 요구에 맞는 후보 3개는 양성, 나머지 6개는 음성입니다. UUID와 순서형 숫자의 공개 함수 동작을 먼저 실행해 확인했고, 원문 요청과 후보 설명의 의미도 별도로 검토했습니다. 제한된 입력 예시를 통과했다는 사실이 가능한 모든 입력에서 정답임을 증명하지는 않습니다.

학습 방식은 첫 FP32 실험과 같습니다. 특징 수 8,192, 초기 난수 seed 1,729, 50 epoch, batch 128, 학습률 0.1, L2 0.0001, pair loss 0을 고정하고, 이진 교차 엔트로피(BCE)의 검증 손실이 가장 작았던 최초 지점을 선택합니다. BCE는 후보가 요구에 맞는지를 양성·음성 라벨로 학습하는 손실입니다. 새로 초기화해 학습하며, 이전 모델의 가중치를 이어받거나 결과를 보고 조건을 바꾸지 않습니다. 이번 경로는 새 자료의 영향을 확인하는 실험입니다. 3진 가중치 실험은 별도 경로로 유지해야 하며, 둘의 결과를 섞지 않습니다.

새 요청은 학습에만 들어갑니다. 기존 검증 및 보정 자료, 역할·그룹·모호한 라벨의 마스크, 기존 요청의 특징 값은 보존합니다. 모르는 후보를 음성 정답으로 바꾸지 않습니다. 기존 검증 자료는 앞선 작업에서 이미 관찰했으므로 회귀 확인용입니다. 실제로 쓸 만하다는 결론을 내리려면 도메인별로 충분한 새 요청과, 최소 2,400개 규모의 별도 보호 최종 평가 설계가 필요합니다. 요청 3개나 입력 예시 수십 개를 그 평가와 동등하게 셀 수 없습니다.

## 평가 숫자를 읽는 방법

같은 검증 자료에서 기존 정렬 방식들과 모델이 제안한 순서를 비교합니다. 정답에 도달하기까지 확인할 후보 수를 줄이고 순위 품질을 지키는지를 봅니다. 여기서 검증 횟수는 저장된 정답 라벨에 따라 계산한 모의 횟수입니다. 실제 LLM 호출, Codex 토큰이나 요금 절감을 측정한 숫자가 아닙니다. 원본 Laya를 GPU로 실행한 실험도 아닙니다. 이 경로는 Go로 구현한 작은 특징 기반 CPU 모델입니다.

## 저장 공간을 정직하게 계산하기

옛 계획의 총 64 MiB 한도는 통과했다고 바꾸지 않습니다. 확인된 좁은 파일 묶음만으로도 67,943,460 B여서 64 MiB를 834,596 B 초과했습니다. 이 초과와 원본 파일을 그대로 보존합니다. 최신 제한된 파일 선택 스냅샷은 2,776개 경로와 206,707,066 B를 확인했습니다. 실제 학습은 두 번, 논리 모델 두 개이며 물리 모델 사본 경로는 여섯 개입니다. 같은 SHA나 같은 inode여도 서로 다른 경로는 각각 셉니다. 이 목록은 선택한 범위와 시점에 대한 목록이며, 컴퓨터 전체나 삭제된 과거 파일까지 포함한 평생 소비량 증거가 아닙니다.

다음 진행에서는 보관하는 파일 경로 합계 512 MiB와 새 단계의 데이터·모델·숫자 기록 합계 64 MiB를 별도의 버전 정책으로 확정할 계획입니다. 기존 8회 학습 및 16개 모델 한도는 그대로이며 기존 두 번·두 개를 차감합니다. 파일 정리나 같은 내용의 사본을 이용해 옛 초과를 소급해서 지우지 않습니다. 공개용 사본과 검사 기록도 새 파일의 보관량으로 추가해야 합니다. 자원 정책의 확정은 모델 활성화나 공개 업로드 승인과 다릅니다.

## 이 자료가 기록하는 시점

이 묶음은 실제 요청 79개 변환과 새 학습을 실행하기 전의 준비 상태를 고정한 기록입니다. 두 새 도구의 해당 실제 실행 횟수는 이 시점에 0입니다. 이후 Root가 실행한 결과는 별도의 결과·자원·검증 기록으로 추가해야 합니다. 이전 기록을 덮어써서 이미 실행한 것처럼 만들지 않습니다.

`loader79-guard-v2`에는 변환 도구의 소스·실행 파일 지문과 합성 검사, 독립 소스 검토의 연결 증거가 있습니다. `fit79-guard-v2`에는 고정 학습 방식과 학습 도구의 합성 검사 및 보호 장치가 있습니다. 공개 소스 CI와 이 준비 도구들의 로컬 합성 검사는 다른 근거입니다. 소스 사본은 `.go.txt`인 검토용 텍스트이고 실행 바이너리, 모델 가중치, 개인 절대 경로, 원본 데이터 본문은 포함하지 않습니다. 프로젝트의 Apache-2.0 LICENSE와 저장소 NOTICE도 함께 유지해야 합니다.

`plan56-consumption-audit/final-v3`가 최신 저장량 및 소비량 스냅샷입니다. `history`의 2,768개 경로와 206,581,572 B 목록은 선택 범위 누락이 발견된 이전 기록이며 실행의 기준으로 사용하면 안 됩니다. 당시 실패와 나중의 표시 숫자 정정도 원문 바이트를 보존합니다. 공개용 사본의 지문은 `PUBLIC-COPY-LEDGER.v1.json`과 `PUBLIC-FINAL-PINS.v1.json`으로 확인할 수 있습니다.
