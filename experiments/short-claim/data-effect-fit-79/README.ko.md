# 요청 3개를 추가한 학습 실험 79

**같은 학습 조건에서 데이터만 추가했지만, 실용 개선은 확인하지 못했습니다.** 새 모델은 비활성 실패 실험으로 보관합니다. 기존 모델 선택이나 기본 실행 방식은 바꾸지 않습니다.

작은 주장 모델의 목적은 정답을 확정하는 것이 아니라, 여러 후보 중 먼저 확인할 것을 제안하는 것입니다. 이번 시험에서는 공개 Go 코드의 동작을 설명하는 짧은 후보 문장을 정렬합니다. 실제 코드 실행으로 확인한 정답 위치까지 몇 후보를 검사해야 하는지를 비용의 대용 지표로 삼습니다. 실제 LLM 호출 수·토큰·Codex 요금 절감 측정은 아닙니다.

## 무엇을 바꿨나

기존 요청 76개에 UUID 파싱·불필요한 문자 처리·서수 접미사의 요청 3개를 **학습 구간에만** 추가했습니다. 각 요청의 후보는 3개입니다. 앞서 고정한 72개 유한 입력 관측과 코드·설명 검토로 정답 후보 3개, 오답 후보 6개를 확정했습니다. 실행 입력 72개를 독립적인 의미 요청 72개로 세지 않습니다.

기존 요청의 내용, 정답·모름 상태, 역할, 가중치와 마스크를 유지했습니다. 기존 학습 수치 데이터의 접두부와 검증·보정 구간도 유지했습니다. 변환 작업자는 부동소수점 비트와 빈 값 상태를 검사했고, 외부 검토는 저장된 JSON의 기존 요청·학습 접두부·검증 배열을 다시 비교했습니다. 변환은 1회, 학습도 1회입니다.

학습은 처음부터 시작했습니다. 조건은 FP32 계수 8,192개, seed 1729, 50 epoch, batch 128, 학습률 0.1, L2 0.0001, BCE입니다. 이전 모델의 가중치를 이어 쓰거나, 결과를 보고 임계값·seed·손실 함수를 바꾸지 않았습니다. validation NLL이 가장 낮은 최초 epoch를 선택하는 기존 규칙도 유지했습니다.

## 실제 결과

검증 요청 20개 중 정답을 아는 요청 15개를 비교했습니다. 나머지 5개의 정답은 모름이며 정확도 계산에서 제외합니다. 답이 있는 요청은 10개, 답이 없는 요청은 5개입니다.

| 같은 검증 구간의 방식 | 후보 확인 총횟수 ↓ | 첫 후보가 정답인 요청 / 10 ↑ |
| --- | ---: | ---: |
| 단순 문구·순서 기반 비교 기준 | 27 | 5 |
| 이전 76개 BCE 모델, 실험 71 | 31 | 2 |
| 새 79개 BCE 모델, 실험 79 | 31 | 2 |

새 모델은 비교 기준보다 확인 횟수가 약 **14.8% 많았습니다**. 통과 조건은 25회 이하이고 첫 후보 정확도를 유지하는 것이었으므로 실패입니다. 기존 모델 대비 개선도 없었습니다. validation NLL도 0.66579769에서 0.66623504로 소폭 나빠졌습니다.

새로 학습한 요청 3개만 본 진단에서도 모델은 6회·첫 후보 정답 1개, 단순 기준은 4회·정답 2개였습니다. 이 결과는 학습에 쓴 요청의 진단이며 일반화 평가로 쓰지 않습니다. 후보가 3개라 top-3에 정답이 들어가는 것도 유의미한 성공 증거가 아닙니다.

| Mac CPU 1개에서 실제 수행한 작업 | 전체 작업자 시간 | OS 최고 프로세스 메모리 |
| --- | ---: | ---: |
| 79개 입력 변환 | 2.090초 | 33.45 MiB |
| 입력 검증·학습·같은 검증 구간 비교·파일 저장 | 1.244초 | 35.08 MiB |

시간에는 파일 검증과 저장도 포함합니다. OS 메모리는 Go 힙 측정과 다릅니다. 이번 작업은 작은 Go 모델의 CPU 실험이며 원래 Laya의 GPU 실행·미세 조정이나 1.58-bit 학습이 아닙니다. 모델 파일은 32,792바이트지만 전체 프로세스가 그만큼의 메모리만 쓰는 것은 아닙니다.

## 메모리·저장량 관리

초기 계획의 64 MiB 보관 한도는 과거 사본까지 합산하면 넘겼습니다. 확인한 일부 파일만으로도 67,943,460바이트였고, 그 초과를 통과로 바꾸지 않았습니다. 정해진 범위의 기존 JSON·수치 데이터·작은 모델 사본 2,776개를 재검증하면 206,707,066바이트입니다. 이 숫자는 전체 Mac·원격 저장소·삭제 이력의 총량이 아닙니다.

실험 전에 [자원 계획을 별도 버전으로 고정](actual/RESOURCE-AMENDMENT.v1.json)했습니다. 해당 범위의 보관량 한도는 512 MiB, 새 실험 단계의 데이터·모델·수치 기록은 64 MiB입니다. CPU 1개, Go 힙 목표 256 MiB, 실제 OS 메모리 판정 256 MiB, 작업자별 300초 제한은 유지했습니다. 결과 원본 하나를 덮어 쓰는 체크포인트로 사용하고, 큰 변환 결과·stdout 사본을 따로 만들지 않았습니다. Go 힙은 소프트 제한이고 OS 메모리는 종료 후 관측 판정입니다.

## 다음 PDCA
