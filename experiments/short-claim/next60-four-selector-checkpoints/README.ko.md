# 다음 네 작업의 관측 기록 준비

다음 배치는 서로 다른 요청 4개, 입력 19개, 후보 12개로 구성합니다. 예정된 후보 호출은 57회입니다. **실제 원본 57회 실행이나 새 라벨 승인은 아직 아닙니다.**

원본이 반환한 값과 오류 존재 여부를 먼저 저장하고, 그 다음 오류 문자열을 읽습니다. 저장이 실패하면 이후 호출을 멈춥니다. 완료 뒤 저장 오류가 발생해도 과거의 완료 결과를 다시 승인하지 않습니다. 중단 후 남은 JSON 한 줄만으로 동기화 완료를 추정하지 않습니다.

[합성 검사 결과](root-tested/RESULT.v1.json)는 16개 상위 테스트와 5개 하위 사례, 총 21개 통과 기록입니다. `-race`와 `vet`도 통과했습니다. 원본 패키지를 가져오는 `nativebinding`과 실행 진입점은 검사 모듈에서 제외했습니다. 그 중 한 검사는 가짜 콜백 57회를 수행하며, 이를 원본 관측으로 세지 않습니다.

CI는 `scripts/verify-next60-development.sh checkpoint`로 [직접 작성한 두 패키지](root-tested/source)를 별도 모듈에 복사해 검사합니다. 사람과 에이전트 모두 같은 재현 방법을 사용할 수 있습니다. 실제 원본 실행은 고정 소스·컴파일러·라이선스·실행 파일·시간과 출력 제한을 확인한 별도 작업입니다.

[실행 통제 준비](../next60-four-selector-outside-preparation/README.ko.md)에는 가짜 시작·대기·시간 초과와 결과 메타데이터 검사 8개를 별도로 추가했습니다. 실제 원본 호출 57회는 이 합성 검사와 구분합니다.

[수정 전후 준비 자료](preparation-v2/README.ko.md)와 [원본 선택 검토](../next60-four-selector-selection/README.ko.md)를 보존합니다. 현재 새 라운드의 적격 요청은 여전히 3개입니다. 추가 학습은 30개·60개 점검 계획에 따릅니다.
