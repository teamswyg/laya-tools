# 개발용 유한 학습 자료 2개 확정

기존 20개 초안 중 두 요청을 **개발용 학습 자료로 적격화**했습니다. 후보 5개에 유한 정답 5개를 부여했습니다: 긍정 2개·부정 3개, 후보마다 가중치 1입니다. 입력 9개나 후보별 관측 23개를 독립 요청 또는 추가 가중치로 세지 않습니다. 기존 초안에 비해 새로 작성된 요청과 새 소스 가족은 모두 0개입니다.

IPNet 요청의 긍정 후보는 `ipNetValue.Set`, 정수 hook 조합 요청은 `OrComposeDecodeHookFunc`입니다. 나머지 후보는 이 요청의 고정된 입력에서 요구를 만족하지 못합니다. 이는 함수가 일반적으로 잘못됐다는 뜻이나 모든 입력에 대한 정답 보장이 아닙니다. 모델은 이런 유한 근거를 학습해 싼 힌트를 제안하고, 실제 실행 전 검증과 전체 후보의 fallback을 남깁니다.

원본 동작 확인, 설명 충실성, 학습 적격성을 나눠 검토했습니다. 빈 IP·hex-mask 등 실행하지 않은 설명을 빼고, nil 출력의 성공·빈 hook의 오류·각 실패 메시지 뒤의 줄바꿈을 명확히 했습니다. 새 설명 v3는 개발 관측 후 작성했으며 아직 어떤 모델의 점수 계산이나 학습에도 사용하지 않았습니다. 실제 Go 입력 검증 2회는 모두 통과했습니다. 각 문장은 512바이트·32단어 제한 안에 들고 잘라내지 않았습니다. [입력](INPUTS.v3.json) · [검증](INPUT-VALIDATION.v1.json).

새 역할은 `development_train`이며 Cobra/pflag 전체 계열을 그룹 77, mapstructure 계열을 그룹 78로 연결했습니다. 기존 79개 자료·21개 그룹은 그대로입니다. 실제 81개 corpus 변환은 아직 하지 않았으며 두 요청을 합치면 23개 그룹이 됩니다. 실제 공유 소스·alias·fork·template 연결이 기존 평가 역할과 충돌하면 해당 학습을 중단합니다. 비슷한 오류 처리라는 이유만으로 서로 다른 계약을 같은 요청으로 합치지는 않습니다. 처음 보는 소스나 보호 최종 평가 자료로 승격하지 않습니다.

공개 자료는 자체 작성한 요청·설명·유한 사실과 [정확한 고지](notices/)입니다. 원본 코드 본문·실행 파일·모델·개인 경로·원문 로그는 포함하지 않습니다. 미해결 Go2022 복사 계보는 제외·보존하며 포괄적으로 승인하지 않습니다. [조건부 권리 검토](rights-review/REVIEW.ko.md), [그룹 준비](group-review/README.ko.md), [독립 유한 정답 제안](FINITE-SUPERVISION-PROPOSAL.v1.json)은 **Root 적격화 전의 상태**를 그대로 보존합니다. 현재 결과는 [확정 자료](QUALIFIED-TRAIN-SUBSET.v1.json)와 [좁은 공개·사용 범위](MATERIAL-SCOPE.v1.json)를 보세요.

추가 학습·특징 계산·모델 점수 계산은 0회입니다. 실제 corpus Fit 누계 3/8회·논리 모델 3/16개이며 효용을 실패한 모델은 비활성입니다. 새 라운드의 적격 자료를 30개·60개로 늘린 뒤 조건을 고정한 별도 학습 비교로 진행합니다. 도메인별 보호 평가 2,400개, 기존 5% 효용 기준과 정답 보존 기준은 유지합니다. 두 요청의 정답을 확정한 것만으로 모델 개선이나 LLM 비용 절감을 주장하지 않습니다.
