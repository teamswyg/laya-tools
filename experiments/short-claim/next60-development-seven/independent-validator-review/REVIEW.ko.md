7행 검증기를 독립적으로 소스 검토했으며, 현재 범위에서 구체적인 차단 사유는 없습니다. 검토자는 이 검증기의 작성자가 아닙니다. 앞선 네 요청의 소스와 기대값을 읽었던 비맹검 검토이며, 여기서는 라벨을 다시 판정하지 않았습니다.

검증기는 기존 3행의 4,229바이트를 그대로 유지하는지 확인하고, 새 4행의 요청 문장과 후보 12개의 ID·원문·정규화 문장을 고정된 fixture와 비교합니다. 독립적인 공개 메타데이터 비교에서도 원문 대응과 이전 데이터 prefix의 SHA가 일치했습니다. 요청 7개, 라벨 20개(긍정 7·부정 13), 유한 입력 34개, 후보 관측 98개라는 수치가 데이터와 Root의 기록에서 일치합니다.

입력은 정규 파일, 읽기 크기, SHA를 검사합니다. 데이터 상한은 128 KiB이며 행당 상한은 16 KiB입니다. 빈 행·여덟 번째 행·잘못된 JSON·중복 키·미지정 필드·누락된 필드·잘못된 역할·단위가 아닌 가중치는 거부합니다. 연결된 소스 그룹 76·77·78을 기존 학습 역할로 재사용합니다. 새로운 미관측 소스 평가 그룹을 만들었다는 의미는 아닙니다.

성공 출력은 필드 순서와 값이 고정되어 있습니다. 소스로부터 구성한 예상 출력은 저장된 검증 기록과 일치합니다. 이 경로는 문장을 읽고 정규화하여 비교하며 모델·Features·Score·Project·Fit·원본 후보·oracle을 실행하지 않습니다. 7회 reader와 4회 fixture 입력 검사는 모델 추론 횟수가 아닙니다.

선택적인 사용성 개선 한 가지는 있습니다. CI의 data 모드는 저장소 루트에서 호출하면 일관되게 모듈을 찾지만, 다른 폴더에서 호출할 때를 위해 `data)` 바로 뒤에 `cd "$repo_root"`를 추가할 수 있습니다. 현재 CI 범위의 차단 사유는 아니며 실제 외부 폴더 실행은 하지 않았습니다.

이 검토에서 Go·테스트·원본·모델 실행, 라벨 재승인, 보호 데이터 읽기, 공유 저장소 수정, 네트워크 호출은 모두 0회입니다. 검증기 실행 성공이나 CI 통과를 새로 주장하는 기록이 아닙니다. 실제 관측의 의미 판정, 권리 확인, 평가 분리, 학습 허가는 각각 별도의 근거를 필요로 합니다.
