# JWT 후보 검색 비용 비교 준비

작은 주장 모델이 실제 작업을 줄이려면, 힌트를 계산하는 비용보다 줄어드는 작업 비용이 커야 합니다. 이 preview는 모델을 추가하기 전에 **저렴한 단어 검색만으로 후보 순서를 바꿔도 이득이 생기는지** 확인하기 위한 실험입니다. 순서만 제안하고, 최종 판정은 기존 JWT 검증기가 수행합니다.

[English](README.en.md) · [이전 캐시 실험](../cost-preview/README.md) · [실행 전 고정한 프로토콜](PROTOCOL.md) · [자체 코드 출처](SOURCE-DERIVATION.prospective.v1.json)

이 문서는 준비 상태를 설명합니다. 새 160쌍 판정 비교와 128개 비용 작업은 아직 실행하지 않았으며, 새 속도·메모리 개선을 주장하지 않습니다. Laya·다른 모델·학습·GPU 호출도 없습니다.

## 무엇을 비교하나

| 후보 순서 | 어떻게 정하나 | 비교 목적 |
| --- | --- | --- |
| 고정 순서 | 원래 선언된 후보 8개 순서 | 기본 비용 |
| 미리 정한 첫 후보 | 공개된 요청 계약에서 정한 `[4, 5, 2, 0]` | 맞는 후보를 이미 아는 이상적 대조군 |
| BM25 | 요청 문장과 후보 설명의 단어 빈도·문서 길이 | 단어 검색의 계산 비용과 효과 |
| Jaccard | 겹치는 고유 단어 수 / 전체 고유 단어 수 | 더 단순한 단어 겹침 방식과 비교 |

각 순서를 캐시 있음·없음으로 비교합니다. 공개 요청 4개를 4라운드 실행하며, 라운드마다 방식의 위치를 회전하고 홀수 라운드에서는 캐시 유무의 실행 순서를 뒤집습니다. 총 `4방식 × 2캐시 × 4요청 × 4라운드 = 128`개 비용 작업입니다. 이는 같은 개발 입력의 반복이며, 새 독립 표본 128개가 아닙니다.

먼저 기존과 같은 160개 판정 각각에서 캐시 유무의 수락 여부·오류 종류·claims 지문을 비교합니다. 이 현재 결과는 작업 중 일치 여부를 확인하는 데만 쓰며, 검색 점수를 계산하는 입력으로 전달하지 않습니다.

## 무엇을 결정하지 않나

검색 함수는 요청 문장과 후보 설명만 읽습니다. 정답·정책 옵션·기존 결과·시간 기록은 보지 않습니다. 점수가 0이거나 같은 후보도 삭제하지 않으며, 동점은 원래 순서를 유지합니다. 후보마다 실제 검증을 수행하고 기대 수락과 처음 다른 입력에서 그 후보의 검사를 멈춥니다. 예상하지 않은 오류나 결과 변형은 `unknown`으로 보존하고 작업을 중단합니다.

예를 들어 요청이 “alpha 또는 beta 허용”이라면 해당 설명을 가진 정책을 먼저 살펴보자는 힌트를 줍니다. 단어가 겹친다는 이유만으로 그 정책을 정답으로 승인하지 않습니다. 이 구분은 이후 작은 주장 모델을 붙일 때도 유지할 조건입니다.

## 비용을 어떻게 재나

문장 해석·단어 준비·점수 계산·정렬을 매 요청 안에서 다시 수행하고 전체 요청 시간에 포함합니다. 검색용 목록을 미리 만들어 놓고 그 준비 비용을 빼지 않습니다. 캐시는 요청마다 비우며 최대 5칸의 고정 배열을 사용합니다. 캐시 조회·깊은 복사·새 정책 검증·결과 지문과 일치 확인도 계산합니다.

저장된 시간·호출 수와 별도로 프로세스 전체의 CPU·최대 RSS·수명 시간을 기록합니다. 전체 프로세스 값으로 특정 검색 방식의 CPU나 메모리를 계산할 수는 없습니다. Go 메모리 목표도 OS 전체나 GPU 메모리 제한이 아닙니다.

## CI와 로컬 실행

이 실험의 로컬 보관 한도는 선언한 실험 작업·증거 경로의 512MiB입니다. 컴퓨터 전체의 저장 공간이나 메모리 한도가 아닙니다. 기존 증거를 그대로 유지하면 새 컴파일 캐시를 추가할 공간이 부족해, CI에서 테스트와 실행 파일 빌드를 수행하고 그 파일을 확인한 뒤 로컬 비용을 측정하는 경로를 준비합니다.

GitHub 공식 문서는 공개 저장소의 표준 runner가 무료이며 `macos-15`가 arm64라고 설명합니다. 실제 작업에서는 Go 버전·호스트 구조·소스 해시를 다시 확인합니다. [GitHub runner 문서](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)

CI 테스트는 합성 입력으로 수식·배열 소유권·unknown·출력 크기를 확인합니다. 빌드된 원본 작업 프로그램을 실행하거나 160/128개 실제 검증을 수행하지 않습니다. 실제 실행은 별도 단계이며, 첫 전체 응답·실패·상태를 저장한 뒤 해석합니다.

개발자가 직접 새 실행을 원하는 경우, Go 1.27.1과 충분한 빌드 공간을 준비한 macOS arm64에서 별도 모듈을 빌드할 수 있습니다.

```sh
cd experiments/short-claim/next-cohort-jwt-audit/retrieval-preview
GOTOOLCHAIN=local GOWORK=off GOPROXY=off GOSUMDB=off \
  CGO_ENABLED=0 go build -trimpath -buildvcs=false -ldflags='-s -w' \
  -o retrieval-preview .
GOMAXPROCS=1 GOMEMLIMIT=64MiB ./retrieval-preview \
  < ../OBSERVER-INPUT.actual.public.v1.json
```

이 명령은 새 원본 검증입니다. 준비·소스 확인이나 저장된 결과 재생과 다르며, 프로젝트가 사용하는 별도 캡처 도구의 시간 제한·CPU/RSS 기록을 자동으로 제공하지 않습니다. Codex나 riido 등록은 필요 없습니다. 사람은 이 설명과 요약을 읽고, 에이전트는 같은 JSON 기록과 소스 지문을 확인할 수 있습니다.

## 해석 범위와 라이선스

이미 공개된 같은 계열의 요청 4개만 사용합니다. 독립 2,400개 평가, 다른 저장소 선택, 실제 Agent 토큰·요금 절감, 학습된 모델의 일반화는 증명하지 않습니다. 이 결과는 다음 모델 실험의 준비·추론 비용을 얼마까지 감당할 수 있는지 판단하는 근거로만 씁니다.

자체 코드와 설명은 Apache-2.0이며 기존 Laya Tools 코드의 출처와 고지를 유지합니다. 복사한 JWT 25개 파일은 [고정 upstream](https://github.com/golang-jwt/jwt/tree/73c870b18e68b6e654b2b03f485aa3c9fab32cea)의 MIT 라이선스와 원 저작권 고지를 그대로 보존합니다. Go SDK 관련 BSD·특허 고지도 빌드 자료에 제공합니다. 이번 프로그램의 의존성은 Go 표준 라이브러리·고정 JWT·자체 검색 코드입니다. 모델 가중치나 ORT·Laya encoder를 포함하지 않습니다.
