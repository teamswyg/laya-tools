# 미상 후보를 보존하는 Go 학습 데이터 준비

이 초안은 “모르는 답을 오답으로 학습하지 않는다”는 원칙을 실제 Go 데이터
형식에 연결합니다. 학습할 수 있는 후보만 연속된 열에 저장하고, 검증용
정답과 학습용 정답을 구분합니다. 실제 코퍼스·모델에는 아직 연결하지 않았습니다.

Go 1.27.1을 사용해 저장소 루트에서 실행합니다.

```sh
bash scripts/verify-next60-mask-learning.sh
```

인터넷 없이 직접 만든 합성 입력으로 검사합니다. 새 원본 관찰, Golden 자료
읽기, 학습, 모델 다운로드·배포는 실행하지 않습니다. 소스는 `.go.txt`로 보존하고
검사할 때만 임시 모듈로 만듭니다. 별도 읽기 검토에서는 구체적인 로직 오류가
발견되지 않았습니다. Reader 연결도 별도 합성 초안으로 검사하며, 실제 의미 자료의
적격성과 학습 실행 권한을 검증하는 일은 남아 있습니다.

예를 들어 후보가 `[맞음, 틀림, 틀림, 틀림, 미상]`이면 처음 네 후보만 학습·평가
행이 됩니다. 미상 후보를 `정답=0, 가중치=0`으로 채워 넣지 않습니다. 가중치가
0이어도 다른 평가 함수가 그 행을 세면 결과가 왜곡될 수 있기 때문입니다.

검증 역할에서는 학습용 표시가 전부 꺼져 있어도, 알려진 정답 네 개에 각각
평가 가중치 1을 줍니다. 현재 Go `pairlearn.NLL`과 `pairlearn.AUC`를 직접 호출해
이 경로를 검사했습니다. 보정용 자료와 정책이 모호한 부모의 후보는 학습과
검증용 특징 추출에 들어가지 않습니다. 미상·보정 상태는 감사 기록에 남습니다.
평가 행이 비어 있으면 NLL을 호출하지 않습니다.
학습 역할의 EvaluationEligible은 현재 감사 카운터에만 반영합니다. 학습 열과
TrainingNLL의 행은 GradientEligible을 따릅니다. 모든 NLL에 평가 표시를
적용한다고 해석하면 안 됩니다.

준비 구조는 최대 60개 부모, 부모당 5개 또는 8개 후보를 받습니다. 이 숫자는
합성 구조의 한도이며 실제 60개 의미 사례를 확보했다는 뜻은 아닙니다.
기존 35개 개발 자료와 이전 실패 모델은 수정하지 않습니다.

후보의 상태·정답·역할·그룹은 특징 함수의 인자가 아닙니다. 원래 요청과 후보
문장만 특징을 만듭니다. 어댑터 초안은 strict Reader가 검증한 값과 이 구조를
연결합니다. 별도로 고정한 평가 설정의 SHA-256과 표준 바이트 형식을 먼저 확인하고,
동일한 row·정답 근거·역할 설정에 연결한 뒤 Reader를 읽습니다. 전체가 틀린 후보에도
일부 조건이 미상이면 그 근거를 별도 고정 배열에 남깁니다. 이 연결도 구조 검사이므로
출처와 의미의 적격성을 입증하지는 않습니다. Reader의 기존 전부 정답 코호트 제한도
유지합니다.

배열로 행을 계획하고, 특징 수와 SHA-256을 먼저 확인한 뒤 정확한 크기의 연속
열을 할당합니다. 두 번째 특징 추출의 값이 첫 번째와 달라도 거절합니다.
이 초안에는 map이나 lock이 없습니다. 기존 특징 함수는 단어 조합을 먼저 전부
만들므로, 문장당 단어 32개를 넘으면 특징 추출 전에 거절합니다. 조용한 자르기는
없습니다. 이 새로운 한도는 초안 전용이며 기존 모델 입력 정책을 바꾸지 않습니다.

반환하는 열·배열·헤더의 계산상 한도는 8MiB입니다. 임시 특징, 준비 구조,
할당기, 프로세스 전체 메모리 및 GPU 메모리는 이 수치에 포함되지 않습니다.
초소형 추론 모델의 실행 메모리를 측정한 값도 아닙니다.

로컬 arm64에서 합성 입력을 각 100번 준비한 진단 결과:

| 입력 | 시간/회 | 할당량/회 | 할당 횟수/회 |
|---|---:|---:|---:|
| 알려진 후보 5개 | 41.8μs | 12,360B | 178 |
| 알려진 후보 4개 + 미상 1개 | 29.8μs | 9,832B | 144 |

이 비교는 작은 입력의 준비 비용만 다룹니다. 표본이 작고 측정 순서·환경의
영향을 받으며, 추론 속도·실제 검증 작업량·Codex 요금 절감을 입증하지 않습니다.
CI에서는 시간 기준을 통과 조건으로 사용하지 않습니다.

[PR #127](https://github.com/teamswyg/laya-tools/pull/127)은 네 CI 조건 통과 후
자동 병합됐습니다. 그 CI는 앞선 Reader·보관 소스 검사를 포함하며, 이 새 초안의
CI 결과와 구분해야 합니다. 기존 native 추론 검사도 별도이며 GPU 사용은 미확인입니다.

Hugging Face의 현재 shortclaim 모델 세 개는 실패 실험으로 비활성 상태입니다.
79번 모델은 처음부터 학습한 선형 특징 해시 모델이며 Laya 파인튜닝이나 1.58-bit
학습 결과가 아닙니다. 이번 35개 자료로 새로 학습한 모델도 아닙니다.
전체 JooYoon 모델 수와 이 세 개의 범위를 혼동하지 않습니다.

Reader 연결 합성 검사 6개와 별도 읽기 검토에서 구체적인 오류는 발견되지 않았습니다.
초기에는 합성 입력의 빈 predicate 배열을 null로 써서 세 검사가 실패했습니다.
원래 Reader의 엄격한 검사는 유지하고 입력을 고쳤으며, 실패 기록도 보존했습니다.
단일 Reader 연결 성공은 전체 부모의 그룹·역할 검증이나 비어 있지 않은 학습·검증
구간을 입증하지 않습니다. 전체 Project 검사를 추가로 적용해야 합니다.

다음 순서는 실제 적격성·계보·역할·그룹과 미상 의미 검토, 새 의미 사례,
보호된 2,400개 평가 자료, 실제 전체 검증 비용에서의 개선 확인입니다. 전부 맞는
후보를 구조적으로 표현할 수 있어도 기존 Reader의 코호트 정책은 바뀌지 않습니다.
GitHub에는 자체 작성 Apache-2.0 소스와 공개 진단 기록만 둡니다. 새 모델을 올릴
때는 데이터·소스·라이선스·CI를 연결한 별도 고정 버전으로 Hugging Face에 공개합니다.
