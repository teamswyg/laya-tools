# 짧은 주장 실험56b: 동작 정답과 연결 그룹 준비

[English](PLAN-56b.en.md) · [다음 확보 방향](NEXT-56b.ko.md) · [확정된56a 결과](RESULTS-56a.ko.md) · [준비 입력](../../internal/typedbehavior/fixtures.go)

**이번 단계는 정답·그룹 감사 준비다. 공식 감사 결과는 아직 관측하지 않았다.** 실행 계획의 schema는 `riido-typed-truth-execution-plan-v1`, state는 `preparation_truth_groups_only`, policy는 `truth_groups_only_no_roles_no_fits_no_models`다. 입력·원천·실행 계획을 결과 전에 봉인하고, 그 뒤 단일 공식 감사와 CI 재생을 진행한다. 역할 분할·학습·모델 호출·성능 측정은 이번 범위에 없다.

56a에서는 큰 인코더 없이 작은 Go 도구를 구현했지만, 자체 작성48요청이11연결 그룹에 그쳐 준비 하한15에 못 미쳤다. 이번 목적은 문장 수를 늘리는 것만으로 그 실패를 지우는 것이 아니다. 정수 배열만으로 표현하기 어려웠던 오류 정체성, 상태 반영, 메모리 소유권, 수명과 그래프 동작을 별도 계약으로 준비한다. 56a 원문·정답·관측값은 유지한다.

| 사전 고정 범위 | 의미 |
|---|---|
| 새24요청 + 기존48요청 = 합계72 | 같은 자체 작성 준비 흐름의 원본 요청. 독립 표본72개라는 뜻이 아님 |
| 새 동작6가족 | 서로 다른 Go 함수 타입과 관측값. 독립 모집단6개라는 뜻이 아님 |
| 새 원천 함수24개 | 올바른 대조군6개와 잘못된 대조군18개, 가족마다4개 |
| 새 literal 벡터80개 | 상태 가족35개 + 흐름 가족45개. 요청 수나 학습 표본 수가 아님 |
| 새 대조 검사320개 예정 | 가족별 벡터를 그 가족의4개 원천에 적용. `80 × 4`; 공식 결과는 아직 없음 |

새 자료와 기존 자료는 하나의 조정된 합성 작성 흐름에서 나왔다. 여러 사람의 실사용 코드나 다양한 작성 분포를 확보한 자료로 해석하지 않는다. 영어 요청의 문장 충실성을 검토하며, 이 한글 설명이 추가 한국어 평가 자료를 만드는 것도 아니다.

요청과 각 후보는 각각 원문·정규화512바이트 이하, 정규화32단어 이하를 지킨다. 자동 요약이나 묵시적 잘림으로 범위를 숨기지 않는다. 무학습·CPU-only Go1.27.1로 준비하며 Go heap256MiB soft limit은 OS 전체 RSS의 hard cap이 아니다. 작은 요청 도구의 고정 배열과, 오프라인 `go/types` provenance 검사가 쓰는 metadata map을 구분한다. 정답 라벨·원천 정보를 순위 특징으로 넣지 않는다.

| 가족 | 독립 literal 표로 확인할 동작 |
|---|---|
| 원자적 설정 반영 | 정상 결과만 대상에 반영하고, 잘못된 입력은 오류·제로 결과·기존 대상 보존으로 구분 |
| 오류 정체성 | wrapping/joining을 통한 Is/As와 원래 원인 값을 관측. 같은 오류 문자열만으로 정체성을 인정하지 않음 |
| 소유한 snapshot | 값·길이·nilness와 양방향 변경 격리. 복사 중 입력 변경과 뒤의 aliasing도 관측 |
| 취소·자원 수명 | 획득·결과·정리 순서와 횟수, 사전 취소, 반복·종료 뒤 이벤트와 상태 |
| 인용·이스케이프 구분자 | quote/escape, 빈 토큰, 입력·토큰 한도, 오류 종류와 부분 출력 |
| 순환·공유 DAG | 도달 가능한 ancestor cycle과 공유 노드 구분. 중복 edge·도달 불가 cycle·입력 불변성 |

실제 정답 관측과 짧은 문장의 충실성은 별도 검사다. 후보 함수가 기대값을 생성하지 못하도록 literal 정답을 독립적으로 작성했다. 후보의 안전하게 관측된 panic은 no-panic 계약 위반이며, 관측기나 지원 범위에 문제가 있으면 `unknown`이다. unknown을 실패·성공 라벨로 바꾸지 않는다.

문장 독해에서는5가족이 개발 caption READY다. 구분자 가족은 코드 대조 검사를 유지하되 **4요청 모두 unknown**으로 준비한다. 세 요청은 전체 계약을 표현하지 못한 `unknown-incomplete-caption`, 하나는 정책이 모호한 `unknown-ambiguous`다. 이 준비 결정으로 합계 known·no-answer·unknown 수나 실제 그룹 수를 예상하지 않는다. 공식 감사에서 원래 분모와 제외 이유를 함께 보고한다.

원천은 [소스 closure 검사](../../internal/typedbehavior/source.go)로 함수 본문뿐 아니라 참조한 자체 타입·전역 값·메서드·helper까지 고정한다. 해석되지 않는 자체 참조나 허용하지 않은 초기화는 감사를 중단한다. 표준 라이브러리·관측 지원 부분은 명시된 정책에 따라 그룹 관계에서만 제외하고, provenance에서는 보존한다. 같은 helper·복사된 동작·원형·반례·후보·부모/형제 관계는 전이적으로 합친다. 새 그룹 계산이 더 보수적이어도 역사적56a 결과를 덮어쓰지 않는다.

전체 연결 그룹과 라벨을 가진 연결 그룹에 **각각 최소15**를 요구한다. 라벨 그룹은 명확한 known/no-answer 자료를 포함해야 하며 unknown-only 그룹은 세지 않는다. 두 gate를 따로 공개한다. 부족하면 그룹을 쪼개거나 기준을 낮추지 않고 준비를 중단한다. 둘 다 넘더라도 통계적 독립성·학습 적격·일반화·성능 증명이 아니며 이번 단계의 역할·fit은 계속0이다.

실행 순서는 다음과 같다.

1. 새 원천 closure·literal 표·입력·문장 검토·그룹 정책과 실행 계획을 commit으로 먼저 봉인한다.
2. 고정 Go 실행기로 단일 공식 truth/group 감사를 수행한다. 기존48요청의 기록과 합계72요청의 새 관계 보고를 구분한다.
3. 정수·허용 집합·unknown 이유·관계와 그룹·입력/원천 해시를 공개 결과로 기록하고 CI에서 재생한다. 실제 commit·manifest 해시·CI 링크는 후속 결과 문서에 남긴다.
4. 검사 실패를 수정할 때에는 원인과 새 동결 경계를 기록한다. 관측에 맞춰 정답·주 기준·최소 그룹 수를 바꾸지 않는다. CI를 검증 기준으로 삼고 별도 사람 승인 흐름을 추가하지 않는다.

준비·감사가 완료되어도 학습 역할0, fits0, 새 가중치0, 실제 Codex 호출0을 유지한다. 기존 유료 호출 원장 누적을 바꾸지 않는다. 이번 자료는 최종 평가 적격이 아니며, 별도 최소2,400요청의 기존 최종 평가 목표와 protected final·CoSQA reserve를 그대로 둔다. 그 자료를 읽거나 채점하지 않는다. 이번 단계에서는 모델 본체·비공개 코드·실제 업무 입력·개인 경로·원시 trace를 공개하지 않는다.

전체 함수 계약을32단어에 담으려 하면 예외·오류 종류·지원 범위가 빠질 수 있다. 다음 가설은 함수를 통째로 설명하는 대신 **범위를 고정한 한 속성**을 묻는 것이다. 예를 들어 “유효 입력에서 공유 child를 cycle로 거절하지 않는가” 또는 “구분자가 quote 안에 있을 때 값을 보존하는가”만 별도 계약으로 다룰 수 있다. 이것은 아직 제안이며 새 입력 계약·독립 정답·unknown 조건·원천 closure·문장 검토·그룹 관계를 먼저 봉인해야 한다. 부분 속성의 통과를 함수 전체 정답으로 승격하지 않는다.

원형 부모와 번역·바꿔 쓴 문장·반례·형제 요청의 그룹 관계를 유지한다. 학습을 준비할 수 있는 이후 단계에서도 같은 부모 fit의 INT8/PTQ 자식과 다른 seed/STE 형제를 독립 데이터로 세지 않는다. [기존56계획](PLAN-56.ko.md)의 최대8 fits·최대16파생 산출물 제안은 별도 학습 실행 계획이 준비되기 전까지 집행하지 않는다.

상주 `--stream`, 동일/서로 다른 요청, pipe·대기열·open-loop·캐시 비용은 **별도 자원 단계**에서 검토한다. 56a의 순차16 child replay를 동시성이나 상주 부하 결과로 재해석하지 않는다. `kevent` 프로파일 귀속도 미해결이며 이 계획은 새로운 CPU/RSS·속도·LLM 비용 절감 증거를 만들지 않는다.
