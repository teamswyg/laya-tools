# 학습에 넣기 전, 설명과 코드를 맞추기

[English](README.en.md) · [원문·지문·수정안 전체](REVIEW.public.v1.json)

작은 힌트 모델은 요청과 후보 설명만 읽습니다. 코드가 올바르더라도 설명이 중요한
검사를 빠뜨리면 학습 기준이 잘못될 수 있습니다. 기존 xxhash 감사의 설명을 코드와
대조했고, 원본을 유지한 채 별도 설명 수정안을 만들었습니다. 학습 데이터 편입이나
새 모델 학습을 수행한 기록은 아닙니다.

xxhash는 부모 요청1개입니다. 고정 입력15개×구현5개=기존75회 검증이며, 이를
75개 독립 사례로 세지 않습니다. 구현 direct/reconstruct는15/15 조건 일치,
legacy7/15·roundtrip10/15·digest7/15였습니다. 이 값은 고정 유한 검사 범위의
동작 관측이며 보편적 정답이나 학습 라벨이 아닙니다.

| 발견한 부분 | 별도 수정안 |
|---|---|
| total32에서 구조만 검사한다는 요약 | 재직렬화한 전체 바이트가 입력과 같아야 함을 명시 |
| digest의 “긴 상태” fallback | total32부터 추가 검사가 없음을 명시; 크기/magic 검사는 모든 입력에 먼저 적용 |
| 입력 보존·수락 후 commit이 빠진 설명 | 각 후보의 실제 검사와 임시 상태 commit·입력 보존을 명시 |
| 검사 없는 조건이 불명확한 요약 | total 상한·lane 일관성·unused tail 검사와 단순 바이트 비교를 구분 |

수정된 문장5개는 별도 source-only 검토자가 다시 읽어 고정15입력의 코드 범위에서
중대한 불일치가 남지 않았음을 확인했습니다. 이미 결과를 본 뒤 만든 개발용
제안입니다. 원래 frozen 요청·설명·실행 결과·모델 반례를 덮어쓰지 않았습니다.
ASCII 단어 수/512B 사전검사만 했고 실제 제품 입력 검증·행동 재실행·모델 점수
계산은 이 준비 과정에서 수행하지 않았습니다.

기존 authored atomic-commit과 Bitset의 최종 구현도 제한적으로 대조했습니다.
Bitset 최종 본체1870B의 지문은 실제 고정 plan/manifest와 일치합니다. 세 본체의
검증 후 commit 흐름은 비슷하지만 이 범위에서 복사된 helper/template 대응을
확립하지 못했습니다. 이것은 전체 외부 fork/출처 관계가 없다는 증명이 아닙니다.

다음에는 남은 출처 관계·목적별 공개/학습 권리·전체 관계 그룹의 개발 역할을
닫아야 합니다. 현재 역할/학습 라벨/가중치는 배정하지 않았고 Fit0, 기본 활성화0,
보호 최종셋 읽기0입니다. 입증되지 않은 후보를 음성으로 바꾸지 않습니다. 출처
관계가 기존 다른 역할에 걸치면 해당 학습을 보류하고 역할을 옮겨 해결하지 않습니다.

편입 가능해져도 이 부모는 이미 노출된 개발 사례입니다. 검증/최종셋으로 옮기지
않습니다. 다른 독립 부모를 관측한 뒤 BM25와 실제 검증 횟수·전체 작업 비용으로
비교해야 합니다. 빠른 점수 계산이나 이 한 사례의 암기는 의미 품질/LLM 절감
증거가 아닙니다. 기존37개와 독립2400 최종 계획은 별개입니다.

상위 [감사](../README.en.md)와 [실패한 모델 비교](../posthoc-hint-preview/README.en.md)는
그대로이며, 포함된 MIT notice와 owned Apache-2.0 observer도 유지합니다.
소스 실행 권한만으로 미래 데이터/가중치 재배포 전체 권리를 인증하지 않습니다.
