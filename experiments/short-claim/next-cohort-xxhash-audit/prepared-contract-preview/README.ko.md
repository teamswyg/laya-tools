# 준비본을 안전하게 재사용하기

[English](README.en.md) · [검증 범위](SCOPE.md)

앞선 [실제 비용 시험](../prepared-storage-preview/README.ko.md)에서는 같은
요청을 반복하면 특징을 한 번만 준비하는 방식이 계산과 할당을 줄였습니다.
이 폴더는 그 방식을 도구에 넣기 전에 **잘못된 입력 재사용과 오래된 결과**를
잡는 연구용 검사입니다. 새로운 공개 API나 기본 라우팅 정책은 추가하지 않습니다.

재사용 기준은 요청 원문과 후보 수, 순서대로 나열된 텍스트가 모두 같은지입니다.
후보 ID만 바뀌면 현재 ID를 반환하고, 모델이 바뀌면 새 점수를 계산합니다.
후보를 줄인 뒤 결과 버퍼에 이전 후보가 남지 않는지, 실패한 호출이 이전
결과를 지우지 않는지도 검사합니다. 동시 호출은 결과 버퍼를 각각 소유해야 합니다.

Go1.27.1과 race 검사용 C 컴파일러가 있는 저장소에서 실행합니다.

```sh
bash experiments/short-claim/next-cohort-xxhash-audit/prepared-contract-preview/verify.sh
```

실행기는 고정 소스 해시를 먼저 검사하고 임시 Go 모듈에서 race 테스트와 vet를
실행합니다. 네트워크, Python, 다운로드된 가중치는 필요 없습니다. 임시 파일은
정리합니다. FP32·int8·ternary PTQ 숫자 가중치를 메모리에서 만들어 실제 Go
계산을 검사하므로, 학습된 Laya 모델 추론이나 3진 모델 학습과 구분해야 합니다.

검사에는 후보 1·5·8개, 한글·반복 단어·문장부호·빈 문자열·입력 경계,
정확한 특징/점수 비트, 동점 순서, 텍스트 변경, ID 변경, 모델 변경,
버퍼 축소/증가, 논리 예산, 중복 특징과 동시 읽기가 포함됩니다.
마지막 index0 특징은 단어 겹침 비율이며 상수 bias가 아닙니다.
합성 입력은 독립 Golden 사례나 모델 품질 점수로 세지 않습니다.

연구 내부 입력은 빈 문장도 검사하지만 기존 제품 입력 검증은 그대로입니다.
공개 API 통합에는 기존 검증과의 연결이 별도로 필요합니다. 보유량 예산은
구조체·복제한 문자열 길이·배열 capacity를 중복 없이 계산한 논리값입니다.
특징 생성 뒤 예산을 검사하는 부분이 있어 순간 최대 메모리 제한은 아닙니다.
모델·호출자 버퍼·임시 할당·RSS·GPU 메모리는 이 값에 포함하지 않습니다.

현재 추천 품질 실패와 미확인 계보는 그대로 남습니다. 이 검사는 품질 개선,
SIMD·캐시 적중률, 전체 작업이나 Codex 사용량 절감을 입증하지 않습니다.

실제 첫 실행에서 race 테스트 7개와 이름 있는 입력 하위 검사 8개, vet가 모두 통과했습니다. [실행 기록](EXECUTION.actual.public.v1.json) · [결과 대조](READBACK.actual.public.v1.json) · [전체 출력](STDOUT.actual.public.txt). 전체 저장소 race 검사도 통과했으며 기존 검사 결과는 모두 캐시였습니다. 컴파일 포함 2.292초는 추론 성능 수치가 아닙니다.
