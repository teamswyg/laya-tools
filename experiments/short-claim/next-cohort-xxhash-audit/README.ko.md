# xxhash: 다음 코호트의 단일 부모 감사 실험

이 실험은 작은 주장 모델을 학습시키기 전에, 후보 설명의 실제 동작을 확인하는 자료입니다. 모델을 학습하거나 Codex 모델을 변경하지 않습니다. 다섯 설명이 비슷해 보여도, 일부 내부 상태를 놓치는 구현이 있는지 살펴봅니다.

부모 요청은 하나입니다: **제한된 xxhash 상태를 원자적으로 가져오되, 짧은 상태의 lane 관계와 미사용 tail을 검사하고, 거절 시 기존 객체와 입력을 보존한다.** 입력 15개 × 후보 5개는 75회 관측이며 독립 학습 사례 75개가 아닙니다.

## 실행과 확인

Go 1.27.1을 설치한 뒤 저장소 루트에서 실행합니다.

```sh
bash experiments/short-claim/next-cohort-xxhash-audit/verify.sh
```

모델 다운로드와 Python은 필요 없습니다. 공개한 원본 소스와 관측기를 임시 작업 공간에 복사하고, 네트워크를 끈 상태에서 Go CPU `purego` 경로로 실행합니다. 결과를 저장된 전체 관측과 바이트 단위로 비교합니다. Linux와 macOS CI도 이 명령을 사용합니다. CI 통과 여부는 해당 PR의 실제 검사 결과를 확인해야 합니다.

## 무엇을 비교하나

| 후보 | 검사 방식 | 실제 계약 일치 |
| --- | --- | --- |
| direct | 길이·magic·범위·lane 식·미사용 tail을 직접 검사 | 15/15 |
| reconstruct | 짧은 상태를 공개 API로 재구성한 뒤 전체 직렬화와 비교; total32는 구조 검사 | 15/15 |
| legacy | 원본 Unmarshal의 길이와 magic 검사 사용 | 7/15 |
| roundtrip | 가져오기와 재직렬화의 전체 바이트 비교 | 10/15 |
| digest | 짧은 상태는 해시값 비교; total≥32는 기존 가져오기 방식 | 7/15 |

75회 모두 관측이 완료됐고 패닉·입력 변경은 없었습니다. 실제 API 호출587회와 오류 반환9회를 기록했습니다. 후보의 거절34회는 공개 직렬화 상태와 Sum64를 보존했습니다. 전체 값과 방식별 결과는 [별도 재독 확인](READBACK.actual.public.v1.json)에 있습니다. 이 수치는 후보의 유한 계약 검사이며 학습 모델의 정확도가 아닙니다.

첫 시도는 96KiB 출력 상한 때문에 JSON을 내보내지 못했습니다. [실패 기록](INITIAL-OUTPUT-BOUND-FAILURE.actual.public.v1.json)과 기존 소스·실행 계획을 보존합니다. 후보 본체·입력·Wanted를 바꾸지 않고 출력만 gzip으로 바꾼 두 번째 시도에서 전체102,643B JSON을4,219B로 보관하고 완전히 해제해 확인했습니다. 누락 필드·잘못된 호출 합계·관측 삭제 등을 검사하는 저장 자료 대조도 실행합니다.

전체 관측을 직접 읽을 때는 다음 명령을 사용할 수 있습니다.

```sh
gzip -dc experiments/short-claim/next-cohort-xxhash-audit/observations.actual.json.gz
```

모든 후보는 임시 객체를 검사한 뒤 가져온 상태를 commit합니다. 공통 관측기는 후보 대신 lane·tail·범위를 검사하지 않습니다. 각 실행은 seed19와 `old`로 만든 새 receiver에서 시작합니다. 거절 시 전후 Marshal 전체와 Sum64를 대조하고 입력 변경 여부도 확인합니다. API 호출별 시도·반환·오류·패닉 기록은 [전체 관측](observations.actual.json.gz)에 남깁니다. 해시값은 정밀도를 잃지 않도록 16진수 문자열로 기록합니다.

객체 보존 측정은 공개 API로 관찰하는 직렬화 상태와 해시값에 한정됩니다. 내부 메모리 전체나 미사용 tail의 숨은 바이트 보존을 측정한 것은 아닙니다. `purego`는 이 소스의 assembly 경로를 제외하며, unsafe 소스가 없다는 뜻은 아닙니다.

## 계약의 범위

원본은 [cespare/xxhash의 고정 리비전](https://github.com/cespare/xxhash/tree/ab37246c889f9db16b606fda1c232d659df9271d)입니다. 이 실험의 계약은 원본 API보다 강합니다. `total≤32`, 미사용 tail의 zero, `total<32`의 lane 관계를 추가로 요구합니다. 기존 API가 이 추가 조건을 검사하지 않는 것을 원본 라이브러리의 결함으로 주장하지 않습니다.

total32에서는 zero tail과 임의의 lane을 허용합니다. 원래 입력·seed 복원이나 실제 Write로의 도달 가능성은 증명하지 않습니다. seed0, 동시성, alias, 긴 상태, 정확한 수치적 digest 정답도 이번 범위에 포함하지 않습니다.

## 학습과 분리

Wanted는 실행 전에 literal 입력 및 계약과 함께 고정하고, 다른 검토자가 소스만 읽어 확인했습니다. 검토자와 작성자는 후보를 알고 있으므로 맹검 실험이 아닙니다. 입력·후보·소스·관측기 핀은 [실행 계획](FREEZE.public.v2.json)과 [파일 해시](SHA256SUMS)에 있습니다.

기존 79/37 사례와 helper·fork를 포함한 계보 연결은 아직 미해결입니다. 이번 부모에는 train/validation/calibration 역할이나 학습 라벨·가중치를 부여하지 않습니다. 기존 37개 데이터와 모델도 변경하지 않습니다. 구조적 Reader 통과는 이 계보 검증을 대신하지 않습니다.

## 라이선스와 성능 해석

동봉한 upstream 세 Go 파일은 원본 바이트와 [MIT 고지](source/xxhash/LICENSE.txt)를 유지합니다. 자체 관측기는 Apache-2.0입니다. 원본 코드를 실행하는 허용 범위와 향후 모델·데이터 재배포의 권리 검토는 별개입니다.

이번 결과는 유한한 동작 검사입니다. SIMD/GPU 실행, 모델 품질 개선, 전체 작업 시간 또는 토큰 비용 절감을 측정하지 않습니다. Go 실행 임시 파일과 보관 모델 바이너리를 혼동하지 않으며, 연구 보관 한도를 새로 시작하지 않습니다.
