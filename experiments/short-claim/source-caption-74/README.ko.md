# 모델이 읽는 설명에 필요한 정보가 있는가

다음 튜닝에서는 모델 크기나 loss만 바꾸기 전에 **입력 문장으로 답을 구분할 수 있는지** 확인한다. 기존 두 작은 모델은 후보 확인 횟수를27→31→33으로 늘렸다. 따라서 같은 실패 자료를 다시 학습하기보다 공개 소스의 실제 동작을 설명에 담는 별도 실험을 준비했다.

기존3개 요청·9개 후보의 upstream 설명을 A로 보존하고, 같은 후보의 공개 소스에서 작성한 짧은 설명을 B로 준비했다. 원래 요청·후보 순서·정답 미정 상태는 바꾸지 않았다. B에는 receiver 오류 후 상태, slice 중복·순서·빈 값, 미완성 token 처리처럼 후보를 구분하는 조건을 넣었다. 최대203B/31단어이며 기존512B/32단어 한도를 지킨다. [제안 원문](CAPTION-ABLATION-DRAFTS.v1.json)은9개 짝과26개 정확한 소스 구간을 연결한다. 소스와 전체 라이선스는 [앞선 공개 보관](../source-observation-73)에 있다.

[독립 검토](independent/REVIEW.ko.md)는9개 짝·26개 구간·원본 보존을 확인했다.8개 새 문구는 해당 범위의 소스가 지원하며, query Values 문구는 옵션·custom encoder·nil·time·생략 조건을 요청에서 한정해야 한다. datasize의 “서로 다른 오류 후 상태”도 syntax/bits가 모두0이라는 사실을 숨기지 않고 새 요청 버전에서 명확히 해야 한다. [전체 함수의 요청 충족 제안](SATISFACTION-PROPOSAL.v1.json)은 설명 충실도와 별도다. 정보 부족을 음성 정답으로 바꾸지 않는다.

아직 정답·역할·가중치는null이며 실제 새 학습은0회다. 다음에는 요청 범위를 먼저 고정하고, 코드가 요구를 만족하는지와 **모델에 보이는 설명이 그 사실을 담는지** 따로 검토한다. 실제72 구현은 같은 SampleWeights를 사용하며 한 endpoint의 가중치가0이면 pair 가중치도0이고 순위 손실·gradient에서 제외한다. 감사 목록에 쌍을 남기는 것과 학습 기여는 다르다. pair 적격성은 의미 정책으로 별도 기록할 수 있지만 이를 차단하려면 현재 코드의 새 기능이 필수라는 설명은 잘못이었다. [정정 기록](PAIR-WEIGHT-CORRECTION.v1.json)을 보존한다. 문구와 학습 제외 조건을 동시에 바꾸면 두 요인이 섞인다. 공통 적격 후보로 문구만 비교할 수 없는 경우 그 사실을 기록하고 억지로 비교하지 않는다.

3개 부모의 A/B·번역·입력 사례는 새 독립 요청으로 세지 않는다. 새 전체 그룹·역할·특징 배열·학습·2,400개 보호 final·기본 모델 변경은 아직 없다. 문구는 AI 도움을 받은 소스 요약이며 독립적인 사람 저작 다양성을 입증하지 않는다. [작성 당시 준비 계획](PLAN.ko.md)과 인계 기록의 pending 상태는 그때의 사실로 남겨두고 후속 독립 검토를 덧붙였다.
