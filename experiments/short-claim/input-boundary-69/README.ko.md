# 기존 입력 한도를 확인한 실제 검사69

[English](README.en.md) · [실제 결과](results-69-input-boundary.v1.json) · [독립 검사](FINDINGS-BOUNDARY-69.v1.ko.md)

작은 주장 힌트의 기존 한도는 각 요청·후보 설명512bytes, 정규화 후32단어, 후보 최대8개다. 원래 72개 요청과216개 설명을 한 번 검사했으며 모두 지원된다. 최대 단어 수는 요청32·설명32로, 한도를 넘는 문장은 없다. 문장을 줄이거나 한도를 늘리지 않았다.

한 프로세스에서 명시적 `Validate`72회와 길이 대조용 `Normalize`288회를 호출했다. `Validate` 내부 정규화 횟수는 개별 계측하지 않았다. 이 결과는 입력 지원 확인이며, 학습 변환·모델 학습·후보 순위 관측을 수행하지 않는다. 같은 코드를 복사한 독립 정규화 계산과 원문 SHA 대조를 별도로 보존한다.

[동결 계획](frozen-plan-69.v1.json), [실행 전 예약](INVOCATION-69.v1.json), [독립 검사 장부](LEDGER-BOUNDARY-69.v1.json)는 변경 없이 복사했다. [복사 장부](QA-COPY-LEDGER-92.v1.json)는 root가 별도로 새 작성했다. 로컬 실행기와 원시 로그는 공개하지 않는다. 계획에는 그 실행기의 상대 이름과 해시만 있으며, 이 폴더는 전체 실행기를 재배포하는 패키지가 아니다. 이후 Go 투영은 원래 문장을 사용하여 별도로 실행한다.
