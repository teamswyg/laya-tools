# 60단계: 원본 소스 연결 결과

원본 검증 **1회, 재시도 0회**가 성공했습니다. 소스 정의 60개와 작성 구성 요소 관계 204개가 기존 해시와 일치했습니다. 이는 앞으로 문장의 근거를 검토할 때 정확한 원본 구간을 가리킬 수 있다는 결과입니다. **설명 승인이나 모델 학습·성능 개선 결과는 아닙니다.**

| 실제 관찰 | 결과 |
|---|---:|
| 원본 파일 / 파싱 성공 | 4 / 4 |
| 루트 정의 / 연결 완료 | 60 / 60 |
| 구성 요소 관계 / 연결 완료 | 204 / 204 |
| 원문 구간 해시·서식화 호출 | 각각 264 |
| 정규화 / 묶음 호출 | 112 / 24 |
| 원본 실행 전 Git blob 검증 | 27 |
| 서로 다른 구성 요소 ID | 70 |
| 전체 264개 참조의 서로 다른 원문 구간 | 89 |

89개는 결과에서 경로·시작·끝 바이트를 묶어 센 구간 수입니다. 원문 SHA와 서식화 SHA의 서로 다른 값도 각각 89개였습니다. 중복 관계를 합쳐서 실제 호출 264회를 89회로 보고하지 않습니다. 이 중복은 이후 캐싱 실험의 근거가 될 수 있지만 속도나 메모리 절감은 아직 측정하지 않았습니다. 현재 실행 방식은 관계마다 다시 처리하는 `no_cache_each_relation_v1`입니다.

## 어떤 실행이었나

[계획](execution-plan-60.json)의 source freeze는 `cc8502f872b047e02961322ff1fcdce4af46e59c`, input freeze는 `c0f279da4c2410699977b502ae4ca2fddd3d3ca8`입니다. Go1.27.1·darwin/arm64·CGO0·trimpath·VCS 정보 제외 빌드의 실제 바이너리는 5,432,642바이트, SHA `831b73221b06dd757572521979e4f6fe0e15f1f5ccb4801dc0eddecaf05390c2`입니다. 크기는 실행 파일의 크기이며 추론 모델 크기나 메모리 사용량이 아닙니다.

[원본 결과](source-inventory-60.json)는 **174,651바이트**, SHA `d99d635929555d4123bbaa84aac99d0fb29db345f8b813ed70074dd3e09cdbd4`입니다. 계획은 5,643바이트, SHA `555dd524cfa5da5b0bc6eecbd9e13a21dfab2a7683978fa4b949765077779a4c`입니다. 실제 반환·파일·루트·구성 요소·해시·카운터를 검증한 후 성공 상태를 기록했습니다. 객체 바인딩과 의미론적 의존성 탐색은 수행하지 않았습니다.

## 실패와 검증도 보존

준비 호출은 2회였습니다. 첫 호출은 빌드 문서의 `<private_binary>`와 Go 표준 JSON의 HTML escape 표기가 달라 `inventory60_build_recipe_invalid`로 종료했습니다. 원본 연결과 AST·formatter는 0회였고 계획 출력도 없었습니다. 지원 파일의 JSON 표기만 수정하고 같은 바이너리로 두 번째 준비를 성공시켰습니다. 이 실패를 원본 실행 재시도로 세거나 숨기지 않습니다.

별도의 참조 검토기는 2회 실행됐습니다. 첫 검토에서 “부모마다 후보 3개”라는 잘못된 가정을 수정했고, 두 번째 검토의 14,338개 메타데이터 확인에서 실패가 없었습니다. 실제 2개·4개 후보 부모를 포함한 원래 순서와 위치를 유지했습니다. 설명의 의미 판단은 이 메타데이터 검토에 포함하지 않았습니다. [실행 기록](execution-ledger-60.json)과 [준비 검토](runner-review-60.json)에 각 작업을 나눠 기록합니다.

원본 결과 관찰 후 추가한 회귀 검사는 저장된 결과·입력·지원 파일 SHA와 원문 구간 264개의 SHA·물리 줄 위치를 확인합니다. 이 검사는 원본 inventory·AST·formatter를 다시 실행하지 않습니다. 합성 제어, 과거 단계의 검증, 이후 CI를 최초 원본 실행 횟수에 소급해 합치지 않습니다. 작성 시점의 CI 병합은 아직 진행 전입니다.

## 학습으로 이어지는 다음 작업

독립적인 내용 검토는 [고정한 규칙](CONTENT-REVIEW-PROTOCOL-60.ko.md)과 [검토자 범위](content-reader-plan-60.json)로 `stable-odd`, `atomic-commit`, `error-identity` 세 계열에서 시작했습니다. 기존 738개 항목 중 123개를 대상으로, 설명 충실도·요청 조건·관찰 필드·제외 범위를 나눠 검토합니다. 반복 문장·후보 위치는 독립적인 새 요청이 아닙니다. 결과가 이 문서에 포함됐다고 가정하지 않습니다.

현재 단계의 모든 설명 검토 상태는 pending이며 `training_ready=false`입니다. 기존 부모 72개·후보 위치 216개·unknown 21개·연결 그룹 17개를 유지합니다. 새 라벨·분할·학습·모델 시험·유료 평가·가중치·보호 최종 데이터 접근은 0입니다. Hugging Face의 기존 적격 배포는 유지하고, 이 소스 연결 결과를 새 모델 성능으로 게시하지 않습니다. 사용 방법은 [실행기 사용법](USAGE-INVENTORY-60.ko.md)을 참고하세요.
