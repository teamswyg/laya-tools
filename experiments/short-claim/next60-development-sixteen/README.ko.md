# 16개 개발 작업 데이터

작은 모델이 코드 작업의 후보 설명에 힌트를 줄 수 있는지 확인하기 위한
공개 학습 자료입니다. 한 작업은 요청 문장 하나와 후보 설명 2~3개입니다.
여기서 16개는 **서로 다른 작업 요청의 수**이며, 입력 변형이나 후보 수를
작업 수로 부풀리지 않습니다.

| 항목 | 현재 값 |
|---|---:|
| 서로 다른 작업 요청 | 16 |
| 후보 정답 | 47: 양성 16, 음성 31 |
| 고정한 입력 / 후보 실행 관측 | 80 / 236 |
| 데이터 파일 | 22,097바이트, 약 22KB |
| 이번 생성 / 실제 Go reader 검증 | 1회 / 16행 통과 |
| 이번 모델 학습·추론 | 0회 |

기존 7행을 한 바이트도 바꾸지 않고 새 9행을 추가했습니다. 새 행의 요청과
후보 설명은 실행 전에 준비한 catalog의 문구를 그대로 사용합니다. 정답은
최초 실제 코드 실행, 저장된 결과의 독립 비교, Root의 유한 범위 채택을
차례로 거쳐 옮겼습니다. 모르는 비교 항목을 거짓으로 처리하지 않습니다.

`data/train.jsonl`은 학습 입력 형식입니다. `ROOT-QUALIFICATION.v1.json`은
새 9개를 채택한 근거이고, `MATERIALIZATION.v1.json`과
`INPUT-VALIDATION.v1.json`은 실제 생성·읽기 결과입니다. 코드·라이브러리의
모든 입력에서 맞는다는 뜻은 아닙니다. 기존 세 소스 그룹을 재사용했으므로
새 소스에서의 일반화나 모델 개선도 증명하지 않습니다.

모델에 들어갈 문장은 요청과 후보 설명뿐입니다. ID, 라이브러리 revision,
정답, 그룹, 관측 결과와 가중치는 특징으로 사용하지 않습니다. 실행 환경의
경로, 인증 정보, 사용자 실제 업무나 바이너리는 포함하지 않습니다.

**다음 학습에서 특히 확인할 문제:** 16개 중 14개는 두 번째 후보가 양성이라,
항상 두 번째 후보를 고르는 단순 규칙도 이 자료에서는 87.5%를 맞춥니다.
또한 후보 47개를 전부 음성으로 부르면 31/47, 약 66.0%가 맞습니다.
두 수치는 서로 다른 단위로 계산한 데이터 편향이며 모델의 측정 정확도가 아닙니다. 후보 순서를
바꾸고 위치·키워드 기준과 비교해야 합니다. 독립적인 검증 자료와 장차
도메인별 2,400개 수준의 보호 평가를 별도로 확보해야 합니다.

다음 학습은 서로 다른 검증된 요청 **30개 체크포인트**를 확보한 뒤 시작합니다.
현재의 16개를 2,400개 평가로 부르거나 같은 작업의 말바꾸기로 수를 채우지
않습니다. 실패한 모델을 활성화하거나 기존 79개 이력을 수정하지 않습니다.

CI는 `bash scripts/verify-next60-development.sh data`로 이 파일을 Go에서
다시 만들고, 원문·정답 근거와 기존 reader의 읽기를 확인합니다. 생성·검증기
합성 오류 검사는 `sixteen` 모드입니다. 원본 코드 검사 worker와 모델 학습은
이 CI 단계에서 실행하지 않습니다.

실제 코드 실행 근거와 전체 라이선스 고지는
[`next60-nine-actual-observation`](../next60-nine-actual-observation/)에 있습니다.
이 자료는 아직 로컬·PR 준비 상태입니다. Hugging Face에는 검증된
[`next60-7-finite-v1`](https://huggingface.co/datasets/JooYoon/riidolaya-shortclaim-next60-development/tree/next60-7-finite-v1)이
게시돼 있습니다. 16개 버전은 이번 변경의 CI 통과 뒤 새 불변 버전으로
배포하고 파일별 재다운로드를 확인합니다.
