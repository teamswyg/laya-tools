# 23개 요청을 Go로 재현하고 읽기

검증된 개발용 요청 **23개·후보 라벨 67개(+23/−44)**를 Go로 실제 생성했고, 프로젝트 데이터 reader가 23행 모두의 문장·라벨·가중치·출처 정보를 그대로 읽는지 확인했습니다. 데이터는 [data/train.jsonl](data/train.jsonl), 크기는 **31,493바이트**입니다. 기존 21행의 28,800바이트 prefix는 한 바이트도 바꾸지 않았습니다.

이 데이터의 목적은 작은 모델이 후보 검증 순서에 힌트를 주는지 시험하는 것입니다. 최종 승인, 정답 인증, 문장 생성 능력을 학습했다는 뜻은 아닙니다. 라벨은 앞서 Root가 실제 유한 실행 근거로 편입한 값을 복사했습니다. 생성기와 reader는 새 라벨을 판단하지 않습니다.

## 사용

저장소 루트에서 실행하세요.

```sh
bash scripts/verify-next60-extra-two.sh
bash scripts/verify-next60-twentythree.sh
```

첫 검사는 추가 두 요청의 저장 관측과 조건을 다시 비교합니다. 두 번째 검사는 작성한 Go 모듈을 임시 디렉터리에 복원해 합성 검사 → 기존 21행에 두 행 추가 → 저장 데이터와 바이트 대조 → 실제 프로젝트 reader로 23행 읽기 → 저장 reader 결과 대조를 수행합니다. 사람과 에이전트가 같은 명령을 사용할 수 있고, 종료 코드가 실패를 알립니다. Python, 원본 후보 실행, Laya 모델 다운로드·추론·Fit은 이 두 검사에 필요하지 않습니다. Go 1.27.1과 race 검사를 위한 시스템 C 도구가 필요합니다.

| 실제 확인한 항목 | 값 |
| --- | --- |
| 서로 다른 요청 | 23개 |
| 후보 라벨 | 67개(+23/−44), 각 가중치 1 |
| 고정 입력 변형 | 113개 |
| 보존한 원 관측 / 라벨에 선택한 관측 | 335개 / 331개 |
| 실제 reader 호출·반환·값 일치 | 각각 23회 |
| reader 호출 전·후 저장 확인 | 46개 |
| 유지한 추가 두 요청의 미상 조건 | 1개(`B_code`) |
| 이번 새 Fit·모델 호출 | 0회 |

[ROOT-ACTUAL-CORRESPONDENCE.v1.json](ROOT-ACTUAL-CORRESPONDENCE.v1.json)은 최초 실제 생성·reader 확인입니다. [MATERIALIZATION.v1.json](MATERIALIZATION.v1.json)과 [INPUT-VALIDATION.v1.json](INPUT-VALIDATION.v1.json)은 각각 도구의 반환값입니다. reader 결과의 `output_*` 값은 생성기 전용 필드여서 false입니다. reader는 별도 `ReaderRecorder`의 새 파일 예약·46개 checkpoint·최종 Sync/Close/디렉터리 Sync 계약으로 저장을 확인했습니다. 이 값들을 reader 저장 실패로 해석하지 않습니다.

`source/`는 실행 시 복원하는 작성한 Go 소스입니다. [SOURCE-ARCHIVE.v1.json](SOURCE-ARCHIVE.v1.json)은 보관 경로와 원 소스 지문을 연결합니다. `preparation/`과 `peer/`에는 **실제 생성 이전**의 준비·별도 소스 검토 기록을 보존했습니다. 그 기록의 실제 생성 0회는 당시 상태이며, 위 최초 실행 기록과 구분합니다. 원시 reader 저널과 로컬 실행 경로·바이너리·모델은 공개 묶음에서 제외했습니다.

## 아직 입증하지 않은 것

참조 후보가 2번 위치인 요청은 20/23개이고, 음성 후보 라벨은 44/67개입니다. 분모가 다른 위치·클래스 편향이며 모델 정확도가 아닙니다. 기존 연결 의미군 77을 재사용했으므로 요청 증가를 새 도메인 증가로 세지 않습니다. 학습에서는 텍스트만 특징으로 사용하고 라벨·출처 ID를 입력 특징으로 넣지 않습니다.

30개 검증 요청에 도달한 뒤 새 학습 체크포인트를 시작합니다. 60개 개발 체크포인트와 도메인별 2,400개 보호 평가 계획은 별도입니다. 이 23개 데이터는 보호 평가 세트가 아니며, 사용자 작업에서 비용·시간을 줄였다는 근거도 아닙니다. 이 최초 기록은 CI119 및 HF23 배포 **이전** 상태입니다. 실제 배포 여부는 해당 게시 증거로 확인해야 합니다.
