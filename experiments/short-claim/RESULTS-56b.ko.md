# 짧은 주장 실험56b: 동작 정답과 연결 그룹 감사 결과

[English](RESULTS-56b.en.md) · [사전 계획](PLAN-56b.ko.md) · [사용법](USAGE-56b.ko.md) · [숫자 결과](results-56b.json) · [다음 실험56c](NEXT-56c.ko.md)

**72개 자체 작성 요청을 감사해 전체17그룹·라벨16그룹을 확인했다. 각각 준비 하한15를 넘었지만 학습 준비는 완료되지 않았다.** 답 있음34개·답 없음17개·판단 보류21개이며, 이번 단계의 역할 분할·학습·가중치·모델 호출·순위·성능·최종 평가는 모두0이다. 한 합성 작성 과정의 개발 자료이므로 일반 의미 이해나 실제 LLM 절감의 증거로 확대하지 않는다.

## 무엇이 달라졌나

[56a](RESULTS-56a.ko.md)의 정수 배열 검사에 더해 오류 정체성, 상태 반영, 메모리 소유권, 취소·정리 순서, quote/escape, 그래프 동작을 관측하는 유지보수용 `riido-typedaudit`을 구현했다. 예를 들어 처음 반환된 값이 같아도 원본을 바꿨을 때 snapshot까지 바뀌면 소유권 계약을 위반한다. 오류 메시지가 같아도 실제 원인이 다르면 같은 오류로 인정하지 않는다.

이 감사기는 후보를 추천하는 [작은 힌트 도구](USAGE-56.ko.md)와 별도다. 실제 Go 함수의 동작과 독립적으로 작성한 literal 정답 표를 비교하고, 관계를 공유하는 자료를 같은 그룹으로 묶는다. 큰 인코더·Laya 추론·Python·유료 서비스는 사용하지 않는다.

## 관측 전에 고정한 범위

라벨이 있는51개는 **답 있음34개 + 답 없음17개**다. JSON의 `known_parents`는 답 없음을 포함하므로 기존36·새15를 답 있는 요청 수로 읽으면 안 된다. 답 없음은 유한 계약에서 허용 후보가 없는 경우이며, 판단 보류는 요구가 모호하거나 전체 동작을 짧은 문구로 충실히 표현하지 못한 경우다. 보류21개도 원래 분모72와 관계 감사에 남긴다.

코드 실행 검증과 자연어의 충실성 독립 독해를 분리했다. 요구와 각 후보의 원문·정규화는 각각 최대512바이트, 정규화 단어는 최대32개이며 내용을 자르지 않는다. 다섯 가족은 개발용 문구 검토를 통과했지만 구분자 요청4개는 **불완전한 설명3개·모호한 정책1개로 모두 unknown**을 유지했다. 코드 대조 검사가 통과해도 ASCII·오류 종류·용량·부분 반환 등 전체 예외를32단어로 전달했다는 뜻은 아니다. 문서 번역은 새 평가 요청을 추가하지 않는다.

## 그룹 하한을 넘었는데 왜 학습하지 않나

| 별도 준비 gate | 관측 | 사전 하한 | 결과 |
|---|---:|---:|---|
| 전체 연결 그룹 | 17 | 15 | 통과 |
| 라벨이 있는 연결 그룹 | 16 | 15 | 통과 |

18개 원형이17개 그룹으로 묶였다. 같은 원형·핵심 동작·요청/후보 문구·오답 소스·복사된 함수·공유한 자체 작성 helper/타입/전역을 전이적으로 연결한다. Unknown-only 그룹은 전체에는 남지만 라벨 하한을 채우지 않는다. 표준 라이브러리와 관측 기반은 그룹 연결에서만 사전 정책으로 제외하고 원천 기록에서는 보존한다. 그룹을 쪼개거나 하한을 낮추지 않았다.

이 수치는 통계적 독립성·다양한 작성자·학습 적격을 증명하지 않는다. 자료는 한 협업 합성 작성 과정의 영어 요청이며, `no_roles_plan`과 `synthetic_single_pipeline`으로 학습 준비를 중단한다. 학습/개발/최종 역할과 분할0·fit0·새 가중치0·모델 호출0·순위0·성능 실행0·운영 활성화0을 유지한다. 기존 유료 코딩 ledger의20기록·서로 다른7요청도 변하지 않았다.

## 실행 파일 검증에서 찾은 문제

실제 `-trimpath` 실행 파일에서 `source_typecheck_failed`가 발생했다. 테스트 실행기가 제공하는 GOROOT 정보에 의존하면 배포된 실행 파일의 표준 라이브러리 타입 정보를 찾지 못할 수 있었다. 오프라인 원천 감사는 설치된 Go 또는 이미 캐시된 **정확한 Go1.27.1**에서 export 정보를 얻도록 수정했다. 다운로드는 비활성화하고 전역 `build.Default`는 바꾸지 않는다. GOROOT 힌트를 제거한 CGO0·trimpath 실행 파일의 준비 smoke 검사가 통과했다.

로컬 전체 race·vet·CGO0 패키지 검사·문서/PDCA guard·형식·diff·redacted 전체 Git 비밀 스캔은 통과했다. **이 문서 작성 시점의 CI는 아직 실행 전**이며 성공 링크나 성공 상태를 부여하지 않는다. 후속 CI는 같은 봉인 결과를 재현하는 gate로 기록한다.

감사는 CPU만 사용하며 Go1.27.1·GOMAXPROCS=1·Go heap256MiB soft limit으로 준비했다. 이는 OS 전체 thread 수·RSS hard cap·GPU 사용량·실측 지연이 아니다. 오프라인 `go/types` 메타데이터 처리 비용을 작은 고정 배열 힌트 도구의 resident 비용으로 간주하지 않는다. 새 성능·캐싱·동시성 관측은 없다.

## 재현과 다음 실험

봉인 원천이 있는 저장소 루트에서 설치되거나 캐시된 Go1.27.1로 실행한다. 출력 폴더는 존재하지 않는 새 이름이어야 한다. 이 명령은 유한 감사의 재생이며 학습이나 모델 호출이 아니다.

```sh
mkdir -p .cache
GOTOOLCHAIN=go1.27.1 GOPROXY=off GOSUMDB=off CGO_ENABLED=0 go build -trimpath -buildvcs=false -o .cache/riido-typedaudit-56b ./cmd/riido-typedaudit
./.cache/riido-typedaudit-56b --stage audit --plan experiments/short-claim/execution-plan-56b.json --plan-sha256 2fe7aeccd72198fda67f2b0ad9e067a2092b465bef252ba72fb464662cf40a82 --input experiments/short-claim/probes-56b.json --legacy experiments/short-claim/probes-56.json --out .cache/my-typed-audit-56b
```

다음 가설은 전체 함수 설명 대신 **범위를 고정한 속성 하나**를 묻는 것이다. 예를 들어 “유효한 그래프의 공유 child를 순환으로 거절하는가”만 검사할 수 있지만 이를 전체 함수의 정답으로 확대하지 않는다. 새 입력 계약·literal 정답·보류 조건·문장 충실성·소스 관계를 먼저 봉인하고, 공개 원천의 다양성과 별도의 무학습 효용·역할 분할 계획을 준비한다. 부모/번역/반례/형제 관계와 같은 fit에서 나온 INT8·PTQ child 관계는 유지한다. 미래1.58-bit 비교도 현재 fit0이다.

학습·개발 자료와 별도로 **도메인별 서로 다른 최종 평가 최소2,400요청**을 확보하는 목표는 유지한다. 이번 final 적격·protected final/CoSQA 접근·채점은0이다. 새 가중치가 없어 HF에는 새 모델을 게시하지 않으며 기존 collection 참조 관리만 예정한다. 모델 본체·개인 경로·실제 업무 원문·인증 정보·원시 프로파일은 Git에 올리지 않는다. Resident stream·부하·전체 CPU/RSS·캐시 무효화는 별도 자원 단계에서 검토한다.
