# 작은 주장 모델을 위한 공개 코드 과제 30개

이 자료는 매우 적은 메모리로 여러 번 실행하는 작은 모델에, 코드 작업의 후보가 도움이 되는지 학습시킬 **다음 개발 학습 자료**입니다. 모델의 제안은 힌트이고, 최종 판단은 테스트와 관측 근거에 맡깁니다. 여기에는 새 학습 모델이나 모델 가중치가 없습니다. 새 학습·추론을 실행한 결과나 Codex 비용 절감 실적도 아닙니다.

## 무엇이 들어 있나요?

| 항목 | 현재 자료 |
|---|---:|
| 부모 요청 | 30 |
| 선택된 후보 라벨 | 88: 적합 30, 부적합 58 |
| 고정한 유한 입력 | 146 |
| 전체 후보 관측 | 434 |
| 학습에 선택한 후보의 관측 | 430 |
| 그대로 보존한 미상 항목 | 8 |
| 실제 Go Reader 요청 반환·값 일치 | 30 / 30 |
| Root가 확인한 Reader 저장 체크포인트 | 60 |
| 연결된 개발 소스 그룹 | 6 |

요청마다 후보가 2개 또는 3개입니다. 오류 쓰기 요청의 원래 후보 1개는 필요한 채널이 미상이어서 학습에서 제외했습니다. 그래서 전체 관측 434개와 선택된 후보 관측 430개가 다릅니다. 미상은 부적합으로 바꾸지 않습니다. 알려진 반례와 미상이 동시에 있어도 반례와 미상을 함께 보존합니다.

앞선 23개·27개 JSONL은 현재 파일의 바이트 그대로 접두부입니다. [접두부 확인](evidence/PREFIX-CORRESPONDENCE.v1.json)을 읽을 수 있습니다. [데이터](data/train.jsonl)의 `request`와 후보 `text`만 모델 입력으로 사용합니다. ID, 라벨, 소스 이름·리비전, 그룹 번호, 역할, 관측 근거는 학습 특징으로 사용하지 않습니다.

## 어떻게 읽고 사용할까요?

1. 먼저 JSONL의 요청과 후보를 읽습니다. 라벨은 **그 요청의 고정 입력들에서만** 채택한 판단입니다. 모든 입력·다른 저장소에 대한 정답 보장이 아닙니다.
2. [실제 자료 생성 요약](MATERIALIZATION.v1.json)과 [실제 Go Reader 요약](READER.v1.json)을 확인합니다. 두 파일은 안전한 원본 요약을 그대로 복사했습니다. 자료 생성기와 Reader는 서로 다른 단계여서 `LoadDevelopmentRow` 호출 수 등도 다릅니다.
3. 새 마지막 3개 요청은 [111개 기대값·관측값](evidence/REMAINING-THREE-PREDICATES.v1.json)에서 확인합니다. `satisfied`, `unsatisfied`, `unknown`을 구분합니다. 전체 Got 흔적과 원 저널은 공개하지 않습니다.
4. [Root 채택 근거](qualification/REMAINING-THREE.v1.json)와 [소스 그룹 결정](qualification/GROUP-DECISION.mode30.v2.json)을 함께 읽습니다. 앞서 추가한 두 묶음의 [Sub/body](qualification/SUB-BODY.v2.json), [INI 2개](qualification/INI-TWO.v1.json) 근거도 보존했습니다.

그룹 결정과 소스 준비 보관본의 `pending` 등 상태는 각 파일을 봉인한 시점의 기록입니다. 바이트를 고쳐 최신 상태처럼 만들지 않았습니다. 자료 30개의 현재 완료 범위는 [공개 대응 요약](evidence/ROOT-DATA30-PUBLIC-CORRESPONDENCE.v1.json)으로 구분합니다. 이 새 묶음에 대한 GitHub CI 통과나 공개 완료는 아직 주장하지 않습니다.

현재 공개 저장소의 `pkg/shortclaimdata.LoadDevelopmentRow(io.Reader)`는 한 JSONL 행씩 읽는 Go 인터페이스입니다. 자세한 자료 생성·검증 과정은 [보관한 Go 소스](source/)와 [소스 대응표](SOURCE-DERIVATION.v1.json)에 있습니다. `.go.txt`·`go.mod.txt`는 실행되지 않는 소스 보관본입니다. 현재 작업 공간의 실제 모듈 연결을 대신하지 않습니다. 물리적 로컬 경로가 있는 Reader 모듈 파일과 원본 의존성 본문은 포함하지 않았습니다.

## 무엇을 검증했고 무엇이 남았나요?

마지막 3개 요청의 실제 수집은 후보 관측 42개를 한 번 수집했고, 저장된 값만 비교했습니다. 관측 행은 적합 29·부적합 11·미상 2, 세부 항목은 적합 89·부적합 20·미상 2입니다. 이는 새 요청 3개의 최종 라벨 9개와 다른 단위입니다. 참고 후보 3개는 각각 필요한 항목 모두 알려진 적합이고, 다른 후보 6개에는 알려진 반례가 있습니다. [수집 요약](evidence/NATIVE42-PUBLIC-SUMMARY.v1.json)의 최대 RSS 18,268,160바이트와 약 2.52초는 시작·소스 확인을 포함한 전체 자식 프로세스 측정입니다. Laya·GPU·작은 모델의 추론 성능을 측정한 값이 아닙니다.

Reader가 자료 30개를 반환하고 값이 일치한 것은 확인했습니다. Root는 비공개 Reader 저널에서 번갈아 저장한 체크포인트 60개도 확인했습니다. 공개 요약은 그 사실을 인용하며, 저널을 재실행하거나 독립적으로 재구성하지 않습니다. `READER.v1.json`의 데이터 파일 쓰기 관련 0/false 필드는 Reader가 데이터를 생성하지 않았다는 뜻이며, Reader 체크포인트 저장 실패를 뜻하지 않습니다.

선택된 정답 후보가 두 번째 위치인 요청이 27/30개입니다. 단순히 두 번째 후보를 고르면 부모 요청 기준 90%가 나오는 **순서 편향 대조**입니다. 모델 정확도가 아닙니다. 이후 순서·문구 대조와 소스 가족 전체 단위 분리 없이 일반화나 이득을 주장할 수 없습니다.

현재 Hugging Face 공개판은 [23개 자료](https://huggingface.co/datasets/JooYoon/riidolaya-shortclaim-next60-development/tree/next60-23-finite-v1)이고, 이 30개 묶음의 공개는 아직 준비 중입니다. 새 Fit·새 모델은 0개입니다. 기존 누적 Fit 3회·논리 모델 3개와 전체 한도 Fit 8회·모델 16개를 별도로 유지합니다. 30개는 수집 체크포인트이며, 약 60개 수집·그룹/역할 고정·별도 준비 판단이 다음 본 학습의 조건입니다. 30개만 사용하는 탐색 학습도 별도 판단 전에는 시작하지 않습니다. 보호 평가 2,400개를 완료했다거나 비용·효용 5% 개선을 입증했다는 뜻이 아닙니다.

## 기록과 라이선스

[실패 기록](history/FAILED-ATTEMPTS.public.v1.json)은 예쁜 JSON 설정이 엄격한 비교기 입력에서 거절된 첫 시도와, 앞선 27개 자료 생성의 단계 연결 실패를 보존합니다. 이후 성공과 실패를 합쳐 성공 횟수로 계산하지 않습니다.

이 보관 작업은 앞서 일부 writer·자료 helper·검증기를 작성한 비눈가림 작업자의 공개 파일 준비입니다. 새 독립 정답 판정이나 본인 코드의 독립 검증이 아닙니다. 비교·학습·원 API 실행을 다시 하지 않았습니다. 원본 소스 본문, 바이너리, 모델 가중치, 개인 경로, 토큰, 원 저널은 제외했습니다. 파생 요약은 새 스키마와 원본 해시로 구분하며, 편집 후 옛 봉인과 바이트가 같다고 주장하지 않습니다.
