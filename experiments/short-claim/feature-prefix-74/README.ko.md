# 같은 특징을 더 적은 반복으로 계산하기

요청 단어와 후보 설명 단어의 조합을 특징으로 만들 때, 기존 코드는 조합마다 `요청 단어 + 구분자 + 후보 단어` 전체를 해시했다. 요청 단어 하나에 후보 단어가 여러 개 연결되므로 같은 요청 부분을 반복해서 계산한다.

변경은 요청 부분과 구분자의 FNV 상태를 한 번 계산하고 각 후보 단어의 바이트를 이어서 처리한다. 해시 바이트 순서·특징 순서·충돌 합산·부호·차원·점수는 유지한다. 새 map, lock, 공유 캐시, SIMD 또는 모델은 추가하지 않는다. 따라서 자료나 가중치를 다시 학습해야 하는 변경이 아니다.

Go1.27.1/Apple M4 Pro/CPU1/soft Go heap256MiB에서 공개 합성 예제 두 개를 비교했다. 한 benchmark 실행 안에서 경로별200ms, 각5회 측정했다.

| 특징 계산 예제 | 기존 중앙값 | 새 중앙값 | 관찰된 시간 감소 | 두 경로의 동일 할당량 |
|---|---:|---:|---:|---:|
| 짧은 요청·설명 | 4,240ns | 3,214ns | 24.20% | 2,216B·19회 |
| 각각32단어 | 351,653ns | 282,633ns | 19.63% | 70,792B·72회 |

[고정 수치 기록](METRICS.v1.json)은 원래·새 소스와 benchmark 소스의 SHA,20개 측정값과 제한을 보존한다. 비교 경로는 원래 FNV 반복문을 정적으로 호출해 추가 간접 호출 비용을 넣지 않는다. 호스트의 다른 부하는 계측하지 않았고 고정된 실행 순서를 사용했으므로, 모든 입력·장치·운영 환경에서 같은 개선을 보장하지 않는다.

공개 전 독립 검토에서32단어 새 경로의 중앙값을 중간 샘플로 잘못 고른 기록 오류를 발견했다. 정렬한 중앙값282,633ns로 고쳤고 처음 기록은 private history에 보존했다. 측정값 변경이나 benchmark·특징 재실행은 없었다.

독립적인 표준 라이브러리 FNV와 empty·UTF8·NUL·긴 문자열의 바이트 조합을 대조한다. 별도로 공개 예제7개의 희소 배열과 FP64 점수 비트가 기존 조합 방식과 같은지 검사한다. 마지막 예제의 source-derived 요청 문장은 기존 공개 초안에서 가져온 것이며, 새 학습 정답이나 모델 실행에 쓰지 않는다.

이 결과는 **특징 계산 시간**에 한정된다. 할당량은 줄지 않았고 전체 RSS·GPU·모델 정확도·LLM 비용은 측정하지 않았다. 기존 두 모델의 비용 절감 실패 결과, 정답·역할·학습 목적·임계값·최종 자료는 그대로 유지한다. 공개 Go 코드 변경은 필수 CI를 통과해야 자동 병합된다.

재현: 저장소에서 `go test ./internal/hintlearn -run '^$' -bench '^BenchmarkFeaturePrefix$' -benchmem -benchtime=200ms -count=5 -cpu=1`을 실행한다. 공개 합성 예제만 사용하며 모델 다운로드나 원본 API 실행을 요구하지 않는다.
