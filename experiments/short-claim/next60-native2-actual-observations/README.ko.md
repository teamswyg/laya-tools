기존 20개 초안에 있던 요청 2개에 입력 9개를 고정하고, 실제 Go 원본 함수의 후보 5개를 한 자식 프로세스에서 23번 관측했습니다. 이번 실행 안의 서로 다른 요청 2개이며 새로 만든 요청이나 새로운 소스 가족 2개는 아닙니다. 시작·대기 각 1회, 정상 종료, 패닉 0, 확인 불가 0입니다. 수정본 PR108은 필수 CI 네 개를 첫 시도에 통과해 자동 병합됐고 검사 head와 병합 tree도 일치합니다.

이 자료가 작은 주장 모델에 필요한 이유는 이름이 비슷해도 중요한 동작이 다르기 때문입니다. `OrCompose`는 반환값이 `nil`이어도 오류가 없으면 성공으로 보고 멈춥니다. 훅이 없으면 오류 메시지가 빈 문자열인 **실제 오류**를 반환합니다. `Compose`는 첫 오류에서 멈추며 이전 훅의 `nil` 반환을 다음 훅의 invalid 입력으로 전달할 수도 있습니다. 오류 문자열만 보거나 함수 이름만 보고 결론 내리면 이 차이를 놓칩니다. 직접 `Value.Set`을 호출한 뒤의 `Flag.Changed=false`는 진단이며 새 정답 조건으로 추가하지 않았습니다.
