# Native2 v5 독립 검토

최종 v5 소스를 정적으로 검토한 결과 남은 구체적 장애는 없습니다. Root가 다음 준비를 진행할 수 있다는 범위의 판단이며, 실행 자격·CI 통과·의미적 결과를 제공하지 않습니다.

Root의 실제 Go1.27.1 빌드가 v4의 빈틈을 드러냈습니다. trimpath를 사용하면 빌드 정보에서 링커 선언을 의도적으로 제외합니다. 가짜 테스트15개와 이전 소스 검토는 실제 바이너리 호환성을 입증하지 못했습니다. 기존 v4 봉인은 유지합니다. v5는 심볼이 보존된 thin little-endian ARM64 Mach-O 파일에서 SHA 세 값을 직접 읽습니다. Go 문자열16바이트 헤더와 연결된64바이트를 계획과 비교하고, 버전·모듈·아키텍처·CGO·trimpath·VCS 없음 검사도 유지합니다.

독립 검토에서는 심볼 개수와 문자열 표 크기만 제한하면 긴 이름을 반복 복사할 수 있음을 발견했습니다. 표준 파서 전에 이름별1024바이트·누적8MiB를 제한하도록 수정했습니다. 로드 명령·심볼·indirect symbol·relocation·섹션·주소 범위도 할당 전에 제한합니다. 이후 작성자가 buildinfo 자체에서 이 검사보다 먼저 Mach-O를 파싱하는 순서 오류를 발견했습니다. 저는 성급하게 전달한 통과 판단을 철회했습니다. 최종 v5는 controller 자신과 worker 모두 buildinfo 전에 제한 검사합니다. 정정 기록에 발견 주체와 제 검토 오류를 남겼습니다.

Root가 보존한 기존 바이너리의 정적 메타데이터는 세 값 모두 일치합니다. 작성자의 최종 테스트는25개 통과했고, 세 단계22·24·25개 통과 기록에서 가짜 자식 시작12회·대기12회·의도한 시작 실패3회를 기록했습니다. 검토자는 테스트나 바이너리를 재실행하지 않았습니다. 검토자의 정적 메타조회는 nm1회·otool1회·xxd5회입니다. 이 검토의 원본·controller·모델·HTTP·컴파일·게시 실행은 모두0회입니다.

예약 → readiness → plan → 정확한 binding → 내구성 있는 한번 실행 기록 흐름과 디렉터리 분리·시작/대기 집계·자원 규칙은 유지했습니다. 프로덕션 입력 목록은 bindings_macho.go를 포함해 네 파일로 늘었습니다. Root가 새로운 source·CI·resource·readiness·바이너리·binding 연결을 고정한 뒤 실제 한번 실행을 별도로 수행해야 합니다. 기존 readiness와 바이너리 핀은 새 연결의 증거로 재사용할 수 없습니다.

이번 검토는 입력을 불변 보존한다는 조건에서 정적 데이터를 비교한 것입니다. 컴파일러·운영체제·초기화 이후 값의 독립 인증이 아닙니다. Go의256MiB 제한은 부드러운 목표이므로 절대 RSS 상한이 아닙니다. 실제 전체 자식의 Darwin RSS를 관측해야 합니다. 권리와 근거 내용 판독은 Root가 담당합니다. Want·라벨·가중치·원본 관측 결과는 바뀌지 않았습니다. REVIEW.v5.json은 소스 핀과 범위를, CORRECTIONS.v5.json과 ACTIVITY.v5.json은 한계와 실패한 메타조회까지 남깁니다.
