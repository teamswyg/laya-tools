캡션을 자세히 쓰면 학습 모델도 자동으로 좋아질 것이라는 가설은 이번3개 개발 목표에서 지지되지 않았다. 같은 요청·코드 정답·후보 순서·모델을 유지하고 캡션만 바꿨는데, 모델71은 확인 횟수3→8, 모델72는5→6으로 나빠졌다. 반면 기존 단어 비교 방식은8→3으로 좋아졌다. 좋은 설명을 제공하는 것과 모델이 그 설명을 올바른 순서로 활용하는 것은 별개의 문제다.

확인 횟수는 첫 정답 후보를 만날 때까지의 위치를 합한 값이며, 작을수록 좋다. 모든9개 후보를 양쪽에서 평가했다. 아래 Top1의 분모는 정답이 있는3부모다.

narrow_rule은 이번 일반 영어 요청에서 기존 BM25 fallback을 사용하므로 별도 의미 추론에 성공한 결과가 아니다. 부모마다 후보가3개라 모든 방식의 Top3=3/3은 순서 품질을 구분하지 못한다. 모델72도 세 목표가 모두 같게 움직인 것은 아니다. datasize는 checks1→3으로 악화, query는2→2, shlex는2→1로 개선했다. 전체 평균만 보면 이런 차이를 놓친다. 모델71의 A3/3도 이 짧은 캡션을 이해했다거나 실사용에 적격이라는 증거는 아니다.
