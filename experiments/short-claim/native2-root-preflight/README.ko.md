# 첫 두 과제의 실행 전 기록

첫 두 과제는 네트워크 입력 처리와 오류가 있는 hook의 선택 순서를 다룹니다. 원본 관측기와 독립 검토를 소스로만 준비했으며, 요청 2개·입력 9개·예정 관측 23회를 구분합니다. 실행과 정답 확정은 아직 하지 않았습니다.

[관측기 준비](../next60-native2-preparation/README.ko.md) · [독립 검토](../next60-native2-review/REVIEW.ko.md) · [정확한 공개 복사 기록](../next60-native2-preparation/ROOT-EXACT-COPY.v1.json)

[바깥 실행 제어기](../next60-native2-outside-preparation/README.ko.md)의 더미 검사 15개와 [독립 검토](../next60-native2-outside-review/README.ko.md)를 마쳤습니다. 원본과 모델을 import하지 않는 제어 코드가 준비됐으며, 실제 바이너리 빌드·원본 시작은 아직 0회입니다. 두 수정 사항과 이전 검사 이력을 함께 보존합니다.

[PR106](https://github.com/teamswyg/laya-tools/pull/106)은 필수 CI 네 개가 첫 시도에서 통과해 자동 병합됐습니다. head와 merge의 파일 트리가 같다는 점도 확인했습니다. [공식값으로 만든 증명](PR106-CI-MERGE.v1.json)은 이전 결과를 기록하며 이 관측기를 CI에서 실행했다고 주장하지 않습니다. [이슈 진행 댓글](https://github.com/teamswyg/laya-tools/issues/19#issuecomment-5957661576)은 게시 후 본문을 그대로 다시 읽어 확인했습니다.

다음 관측을 위한 [지정 파일 저장량 snapshot과 선행 예약](OBSERVATION-BUDGET.v1.json)은 3,497경로·242,894,105B를 세었습니다. 기존 기준 이후 새 단계 소비는 36,187,039B입니다. 결과 cap 12MiB·바깥 측정 cap 1MiB·추가 검토/기록/공개 복사 7MiB를 합한 새 예약 20MiB까지 더하면 단계 한도 64MiB 안에 있습니다. 이 snapshot 자체의 두 기록 925,268B와 후속 복사도 예약 안에서 다시 셉니다. 실제 결과는 아직 0B이며 cap을 소비량으로 해석하지 않습니다.

이는 다음 관측에 필요한 지원 예약을 앞서 재배분하는 단계입니다. 완료된 Project/Fit의 실제 파일은 그대로 셉니다. 그 작업들의 미사용 최대 예약을 새 작업에 이중으로 예약하지 않고, 예비 게시 지원 예약은 앞으로의 관측 예약으로 대체합니다. 기존 초과 기록 834,596B, 실제 corpus Fit 3/8회·논리 모델 3/16개와 과학적 기준은 바꾸지 않았습니다. 자원을 예약했다는 사실만으로 worker 실행·훈련·게시·모델 활성화를 승인하지 않습니다.

같은 지문을 가진 복사본도 서로 다른 경로이면 전체 바이트를 셉니다. 원장 원본과 추가로 지정한 로컬 파일 범위의 조사이며, 전체 Mac·원격 저장소·삭제한 파일·전체 쓰기량 조사는 아닙니다. 두 신규 준비 작업의 개발 도구 8파일·22,806,096B는 별도로 실측했습니다. 이 밖의 캐시·이전 도구와 모든 컴파일 자식 프로세스를 0으로 보고하지 않습니다. 디스크 크기를 RAM이나 GPU 메모리로 해석하지 않습니다.

다음 gate는 바깥 시작 제어, 불변 source/vector/readiness/빌드·CI 핀, 로컬 관측 용도의 권리, 경로 분리와 중복 실행 방지입니다. 이를 통과한 별도 고정 계획으로 원본을 한 번 실행하고 전체 wall/CPU·Darwin 최대 RSS를 기록합니다. 자식 정상 종료와 원문 핀 일치만으로 후보 정답이나 학습 적격성을 부여하지 않습니다.
