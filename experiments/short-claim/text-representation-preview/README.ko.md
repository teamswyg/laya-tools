# 기호와 관계 표현의 개발 진단

이 단계는 아주 작은 주장·힌트가 다음에 확인할 후보를 빨리 좁히는 데 도움이 되는지 시험합니다. 정답을 승인하는 대신 모든 후보를 남기고 순서를 제안합니다. 기호 정보를 복원하는 것과 작은 관계 규칙만 사용하는 것을 분리했으며, 새로운 학습은 하지 않았습니다.

## 관측한 효과

기존 B-tree12요청·96유한 라벨을 그대로 사용했습니다. 한 소스 가족·group84의 `development_train`이며, 문법 설계 당시 이미 본 자료입니다. 정렬에는 요청·후보 원문만 넣고, 순서가 나온 뒤 저장 라벨로 평가했습니다. 기존34fixture·272원본 관측·라벨·mask·역할은 수정하지 않았습니다.

| 기준 | 모의 후보 확인 | 기존 단일 관측의 검증 비용 합 |
| --- | ---: | ---: |
| 기존 표시 순서 | 54 | 187,673 ns |
| 학습 없는 관계 일치 순서 | 26 | 85,793 ns |

정답과 오답이 함께 있는9요청은 모두 첫 후보가 정답입니다. 모든8후보가 정답인 빈 트리 요청1개는 별도로 분리했고, 정답이 없는2요청은 모두8후보를 확인합니다. 조기 종료 요청에는 서로 범위가 다른 정답2개가 그대로 남습니다. 26회는 이 자료의 최소 확인 횟수와 같지만, 비용 합은 가장 빠른 정답을 선택한 oracle80,292ns와 다릅니다.

이는 알려진 자료에서 재계산한 확인 순서입니다. 새 순서대로 원본을 실행해 얻은 속도나 Codex 토큰 절감이 아닙니다. 단순 관계 규칙이 이 과제를 해결하므로, 학습 모델이 추가 이득을 내야 다음 비용을 정당화할 수 있습니다. 독립2,400개 평가와 다른 계보의 전이는 미검증입니다.

## CPU와 Go 할당

Apple M4 Pro·Go1.27.1·CPU1개에서 하나의 지원 문장을8번 반복했습니다. 각 측정은300ms,3회이며 표는 중앙값입니다. 원본 전체 출력은 `BENCHMARK.actual.public.v1.txt`에 있습니다.

| 표현 API | 8후보당 시간 중앙값 | Go 할당 B/op | allocs/op |
| --- | ---: | ---: | ---: |
| 기존 단어 해시 | 319,241 ns | 130,240 | 320 |
| 기호를 보존한 해시 | 432,449 ns | 171,456 | 352 |
| 기존 토큰 계획·scratch 재사용 | 299,022 ns | 704 | 24 |
| 관계 배열 및 원문 파싱 | 2,895 ns | 0 | 0 |

기호 보존은 정보를 늘리는 대신 이 조건에서 더 느리고 할당도 많았습니다. 관계 배열은 매우 작고 빠르지만 표현하는 의미가 훨씬 좁습니다. 기존 재사용 방식은 초기 토큰·scratch 준비를 측정에서 제외했고, 관계 방식은 매번 파싱했습니다. 같은 품질의 모델끼리 비교한 수치가 아니며, 반복 문장은 실제 사용 분포를 대표하지 않습니다. Go 할당은 RSS·native·GPU 메모리와 다릅니다. SIMD나 GPU 가속을 검증한 것도 아닙니다.

## 실행과 재현

[사람과 에이전트의 사용법](../../../cmd/riido-hintpreview/README.ko.md)은 별도 Go 실행 파일로 제공됩니다. 저장 결과를 재현하려면 저장소 루트에서 실행합니다.

```sh
bash scripts/verify-text-representations.sh
go test ./internal/hintrelation -run '^$' -bench '^BenchmarkRepresentations$' -benchmem -count=3 -cpu=1 -benchtime=300ms
```

첫 소스·원문·저장 관측·예산은 `FREEZE.public.v1.json`으로 고정했고, 첫12응답·종료 상태·벤치마크 전체를 해석 전에 보존했습니다. `RESULTS.actual.public.v1.json.gz`에는 모든 후보의 특징 지문·관계 배열·순서·정답 상태가 있습니다. 재현 검사는 원본 API나 모델을 실행하지 않습니다. 비교 기호가 없는 입력의 기존 float64 bits 일치, 입력 경계, Unicode 오류, 문법 실패, 부분 인식, 배열 소유권과 동점 순서를 합성 대조로 검증했습니다.

소스와 문법은 자체 작성 Apache-2.0입니다. 후보 설명과 이전 관측은 [고정 B-tree 출처와 전체 고지](../next-cohort-btree-audit/SOURCE-PINS.public.v1.json)를 따릅니다. 새 라이브러리·모델 라이선스를 추가하지 않았습니다. 모델 본체와 비공개 자료는 Git에 없습니다.

## 다음 학습 조건
