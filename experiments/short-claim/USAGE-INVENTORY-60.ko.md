# 60단계 소스 참조 실행기 사용법

`riido-sourceinventory`는 저장된 소스 정의 60개와 작성 구성 요소 관계 204개를 원본 Go 선언에 연결하는 유지보수용 도구입니다. 모델이나 후보 함수를 실행하지 않습니다. 연결된 문장이 구현을 잘 설명하는지는 [별도의 내용 검토](CONTENT-REVIEW-PROTOCOL-60.ko.md)에서 판단합니다.

## 실행 전 고정하는 것

원본 입력은 Go 소스 4개와 `results-56b.json`이며 전체 SHA·바이트 수를 고정합니다. 실행기에 들어간 Go 파일 5개는 바이너리에 함께 포함해 현재 파일·Git 파일과 비교합니다. 지원 파일 16개에는 이 사용법, 빌드 방법, 테스트, 설명 검토 규칙이 포함됩니다. 이 목록은 의미론적 의존성 전체를 증명하는 목록이 아닙니다.

Go **1.27.1**, `CGO_ENABLED=0`, `-trimpath`, `-buildvcs=false`, `-p=1`로 바이너리를 빌드합니다. 실제 바이너리 SHA·크기·플랫폼·빌드 정보를 계획에 저장합니다. 바이너리와 입력 경로는 공개하지 않습니다. `GOMAXPROCS=1`과 Go 힙 soft limit 256MiB는 설정이며 실제 메모리·속도 측정값이 아닙니다.

## 준비 → 입력 고정 → 실행

다음 예시는 저장소 루트에서 실행합니다. `<...>`에는 해당 실험의 실제 값이 들어가야 합니다. 바이너리와 소스 커밋은 준비와 실행 사이에 바꾸지 않습니다.

```sh
CGO_ENABLED=0 go build -trimpath -buildvcs=false -p=1 -o .cache/riido-sourceinventory-60 ./cmd/riido-sourceinventory
.cache/riido-sourceinventory-60 prepare --source-commit <source-freeze-commit> --out .cache/new-plan-60.json
```

`prepare`는 원본 AST·레지스트리·서식화·inventory를 호출하지 않고 입력·실행 파일·지원 파일의 바이트와 Git 기록만 검증합니다. Git blob 검증은 26개입니다. 새 계획 파일을 검토해 `execution-plan-60.json`으로 기록한 별도 입력 커밋을 만든 후 같은 바이너리를 사용합니다.

```sh
.cache/riido-sourceinventory-60 inventory --input-commit <input-freeze-commit> --out .cache/new-run-60/results.json
```

`inventory`는 입력·계획·바이너리와 Git blob 27개를 다시 검증하고, 저장된 메타데이터에서 필요한 문자열만 읽습니다. 큰 정수·정답 플래그·랭킹·학습 역할을 계산이나 특징으로 옮기지 않습니다. 그다음 새 디렉터리와 결과 파일을 먼저 확보하고 원본 연결을 **1회** 호출합니다. 자동 재시도는 **0회**입니다. 기존 출력 경로나 심볼릭 링크는 실행 전에 거부합니다.

## 성공과 실패를 읽는 법

성공 범위는 파일 4개, 원래 순서의 루트 60개, 구성 요소 관계 204개와 각 기존 해시 일치입니다. 미리 예상한 파싱 4·서식화 264·정규화 112·묶음 24와 실제 반환 카운터도 비교합니다. 기대값을 실제 카운터에 채우지 않습니다. 선언 구간의 원본 해시는 관계마다 계산하며 서로 다른 구간 수를 물리적인 호출 수로 바꾸지 않습니다.

중간 실패는 반환된 부분 결과·실제 작업 횟수·고정 오류 코드를 저장하고 그대로 실패로 종료합니다. 예상과 다른 성공 보고서도 부분 결과를 보존하며 실패로 처리합니다. 패닉으로 함수가 반환하지 않았으면 내부 카운터를 알 수 없다고 기록합니다. 디스크 쓰기 실패나 프로세스 강제 종료에서는 결과 파일이 완성된다고 보장하지 않습니다. 전체 시스템을 막는 전역 lock은 없으며 재시도 횟수는 실험 계획과 기록으로 관리합니다.

결과의 `metadata_rebound_content_review_pending`은 바이트 연결 성공을 뜻합니다. 객체 바인딩·완전한 의존성 탐색·설명 승인·모델 품질·비용 절감을 뜻하지 않습니다. `content_review=pending`, `training_ready=false`를 유지합니다. 공개에는 안전한 결과 JSON과 한글·영문 설명만 사용하며 로컬 바이너리·경로·모델 가중치는 Git에 올리지 않습니다.

## 실행 후 검증 범위

최초 공식 실행 계획은 원본 inventory 1회/재시도 0회입니다. 기존 CI가 합성 제어와 과거 단계의 고정 검증을 실행하는 것과 구분합니다. 이후 회귀 검증을 추가할 때는 이 최초 실행 횟수에 소급해 섞지 않고 별도로 기록합니다. 최초 결과는 원본 선언의 원문 SHA·바이트 구간과 기존 루트·구성 요소 순서·서식화·정규화·묶음 해시, 실제 카운터를 다시 비교하는 대상으로 삼습니다. 선언 연결의 성공 여부가 의미 판단의 정답 역할을 하지는 않습니다.
