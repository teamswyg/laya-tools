# 동작 정답 감사 도구 사용하기

[English](USAGE-56b.en.md) · [사전 계획](PLAN-56b.ko.md) · [결과](RESULTS-56b.ko.md) · [실제 힌트 도구](USAGE-56.ko.md)

`riido-typedaudit`은 학습 자료를 준비하는 유지보수용 Go 도구다. 코드가 반환한 값뿐 아니라 오류 원인, 원본 변경, 메모리 소유권, 획득·정리 순서를 독립적인 유한 정답 표와 비교한다. 설명이 실제 코드를 완전히 표현하지 못하면 `unknown`으로 남긴다. 같은 원천·후보·반례·helper를 공유하는 요청은 전이적으로 합친다.

이 도구는 모델 라우터나 순위 모델이 아니다. 작업 실행에 사용할 힌트는 별도 `riido-shortclaim`에서 확인한다. 이번 감사는 새 모델을 다운로드하거나 학습하지 않으며, Codex 연결·기본 설정 변경도 없다.

저장소 루트에서 Go1.27.1로 빌드한다. Python이나 API 키가 필요 없다.

```sh
mkdir -p bin .cache
CGO_ENABLED=0 go build -trimpath -o bin/riido-typedaudit ./cmd/riido-typedaudit
```

준비 단계는 코드에 고정된 자체 작성 요청을 새 파일로 생성한다. 후보 함수 실행·그룹 감사·순위 계산은 수행하지 않는다. 출력 폴더가 이미 있으면 실패하므로 새 이름을 사용한다.

```sh
./bin/riido-typedaudit --stage prepare --out .cache/typed56b-preparation-example
```

`probes.json`에는 자체 작성 텍스트와 고정된 source/bundle 해시가 있다. 임의의 업무 코드를 넣어 자동으로 라벨을 만드는 기능은 없다. known 라벨을 사용하려면 사전 검토된 요청·후보 문구와 코드 연결이 그대로 맞아야 한다. 짧은 문장의 범위를 통과하는 것만으로 의미가 완전하다고 인정하지 않는다.

공식 감사의 재생 명령과 정확한 계획 해시는 [결과 문서](RESULTS-56b.ko.md)에 있다. 감사 단계는 계획·소스 manifest·컴파일된 소스·두 입력 파일의 해시를 확인하고, 확인한 입력 바이트를 그대로 해석한다. 기존48요청과 새24요청의 정답 기록, 합계72요청의 관계를 새 `results.json`에 남긴다. 기존 파일이나 결과 폴더를 덮어쓰지 않는다.

출력의 `whole_group_gate_pass`와 `labeled_group_gate_pass`는 다르다. unknown-only 그룹은 전체 관계에는 남지만 라벨 그룹 하한을 채우지 못한다. 둘 다 통과하더라도 `training_execution_ready`는 false다. 이번 계획은 역할 분할·학습·가중치·모델 호출·최종 평가·운영 활성화를 허용하지 않는다.

CPU 실행은1thread, Go heap soft limit은256MiB다. 전체 프로세스 RSS나 GPU 메모리의 상한·측정값이 아니며 추론 성능 결과도 아니다. Go 설치의 표준 라이브러리 타입 정보가 필요한 오프라인 `go/types` 감사와, 고정 배열을 사용하는 작은 힌트 도구의 실행 비용을 구분한다. 이 유지보수 감사기는 여러 실제 업무 요청을 저비용으로 반복 처리하는 경로에 넣지 않는다.

사람은 공개 결과에서 보류 이유와 그룹 연결을 읽을 수 있다. 에이전트는 고정 오류 코드·종료 상태와 JSON을 확인할 수 있다. 오류 때 입력·선택한 개인 경로·코드를 되풀이하지 않는다. 원시 프로파일·실제 업무 입력·인증 정보·가중치는 Git에 올리지 않는다.
