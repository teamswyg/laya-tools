# 종료 원인과 신호 결과를 따로 보존하기

기존 native-wire3 원본·실행 기록은 그대로 두고, CI의 임시 컨트롤러에 이 소스를 덧씌웁니다. 첫 macOS CI에서 오류 출력 제한을 넘긴 뒤 종료 신호도 실패하자, 신호 오류가 처음 원인을 가렸습니다. 옛 기록에는 errno가 없어 그 실패의 정확한 운영체제 원인을 알 수 없습니다.

수정안은 처음 **수락한 종료 요청**이 수신기·오류 출력·시간 제한 중 어디서 왔는지 유지합니다. 동시에 프로세스 그룹에 신호를 한 번 시도했는지, 신호가 수락됐는지·그 시점에 해당 그룹이 없었는지·실패했는지, 알 수 있는 숫자 errno를 별도로 기록합니다. 신호 수락을 전체 그룹 종료의 증명으로 쓰지 않습니다. EPERM·EINVAL과 알 수 없는 오류를 무시하지도 않습니다.

수신기·오류 출력·시간 감시가 모두 끝난 뒤 결과를 읽고, 자식 시작과 회수 시도는 각각 한 번입니다. 종료를 요청한 실행은 성공으로 바꾸지 않습니다. 오류 출력은32KiB까지만 보존합니다. 경쟁 요청은 원인을 바꾸거나 신호를 재시도하지 않습니다.

추가 컨트롤은 신호 결과 분류, 포장된 errno, 동시 요청, 완료 전 결과 읽기 방지, panic(nil), 원인 없음, 스스로 끝나는 가짜 자식의 오류 출력·수신기·시간 제한을 검사합니다. 실제 종료 신호가 실패하고 자식이 계속 실행되는 경우에는 Wait가 지연될 수 있습니다. 이 가짜 자식 테스트를 임의의 권한 오류에서도 종료를 보장한다는 증거로 사용하지 않습니다. 종료 신호 재시도나 별도 강제 종료 수단은 이번 변경에 추가하지 않았습니다.

재현: Go1.27.1에서 `bash scripts/verify-next60-native-wire3.sh`. 원본 라이브러리·Laya·학습을 실행하는 명령이 아닙니다. [English](README.en.md).
