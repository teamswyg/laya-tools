# 원래 실수를 직접 반올림하는 작업: 첫 실제 실행

작은 주장 모델을 학습하려면 후보가 실제로 요청을 만족하는지 확인한 데이터가 필요합니다. 이번에는 공개 Go 라이브러리의 숫자 표시 함수와 직접 작성한 두 후보를 같은 입력으로 비교했습니다. 모델 학습·추론 성능 실험과는 별개의 데이터 검증입니다.

예를 들어 `1.375`를 소수 둘째 자리로 반올림하면 `1.38`이어야 합니다. 원본은 먼저 소수 여섯 자리로 표시한 뒤 잘라서 `1.37`을 냈습니다. 개선 후보는 원래 실수에서 바로 반올림했습니다. 오류 후보는 여섯 자리로 먼저 반올림한 중간값을 다시 반올림하며, 아주 작은 값을 잃습니다.

| 입력과 조건 | 기대값 | 원본 | 개선 후보 | 오류 후보 |
|---|---|---|---|---|
| 1.125, 소수 2자리 | 1.12 | 1.12 | 1.12 | 1.12 |
| 1.375, 소수 2자리 | 1.38 | 1.37 | 1.38 | 1.38 |
| 1.999, 소수 2자리 | 2 | 1.99 | 2 | 2 |
| 0.000000125, 소수 9자리 | 0.000000125 | 0 | 0.000000125 | 0 |
| 음의 0, 소수 2자리 | 0 | -0 | 0 | 0 |
| 양의 무한대 | nonfinite 오류 | 오류 반환 채널 없음 | nonfinite 오류 | nonfinite 오류 |

입력 6개 × 후보 3개 = 관측 18건이며, 서로 다른 작업은 **1개**입니다. 독립 정수 계산 기준도 6번 실행해 고정 기대값과 모두 일치했습니다. 원본의 오류 반환 채널이 없다는 사실을 정상 처리나 오류 없음으로 바꾸지 않습니다. 실제 관측 파일의 역할·정답·가중치 필드는 그대로 비어 있으며, 데이터 자격 부여는 후속 검토에서 별도로 기록합니다.

Go 1.27.1 / macOS arm64에서 작업 프로세스를 1회 시작하고 1회 종료 확인했습니다. 재시도·panic·모델 호출·보호 평가 자료 읽기는 0회입니다. 직접 자식 프로세스의 전체 시간은 약 **0.378초**, 운영체제가 종료 시 보고한 최대 RSS는 **5,816,320 B, 약 5.55 MiB**였습니다. Go heap 한 시점의 값은 207,056 B입니다. 관측 루프만의 0.000067333초에는 시작·출처 검사·출력 저장이 포함되지 않습니다. 이 수치는 숫자 검증 작업의 측정이며, Laya나 주장 모델의 속도·GPU·전체 머신 메모리 성능을 뜻하지 않습니다.

CPU 동시 실행 제한 1, soft heap / 관측 RSS 예산 256 MiB, 전체 자식 시간 300초, 결과 12 MiB, 외부 기록 1 MiB를 유지했습니다. RSS는 종료 후 관측 검사이고 hard memory cap이 아닙니다. 저장 검사는 이전 실패 파일과 바이너리도 보존해 합산합니다. 기록 보관 예산 32 MiB는 결과 12 + 외부 1 + 검토 기록 19 MiB이며 추론 메모리 예산과 구분합니다. 과거 저장 한도 초과는 이 새 예약으로 소급 통과시키지 않았습니다.

실행 전에 실제 CI 통과, 원본 파일 범위, 라이선스 고지, 바이너리 설정, 저장 예약과 고정 입력을 확인했습니다. 원본 전체 패키지를 가져온 실행이 아니며, 고정된 숫자 파일만 선택했습니다. Go 컴파일러·생성 헤더와 macOS 시스템 라이브러리는 명시한 신뢰 경계입니다. 제삼자 코드·바이너리 재배포나 전체 법적 계보를 독립적으로 검증했다는 주장은 하지 않습니다.

공개 파일에는 고정된 공개 입력의 구조화된 결과와 경로 없는 검증 정보만 담습니다. 원본 본체, 바이너리, 개인 경로, 인증 정보나 프로파일 추적은 포함하지 않습니다. 원본 함수의 라이선스와 해시는 기존 [준비 기록](../next60-ftoa-singlefile-preparation/README.ko.md)에서 확인할 수 있습니다.
