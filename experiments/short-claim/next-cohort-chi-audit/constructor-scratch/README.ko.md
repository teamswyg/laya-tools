# 준비 단계의 배열 재사용: 메모리 할당 감소와 시간의 교환

[English](README.en.md) · [선택형 Go API](../../../../pkg/hintprepared/README.ko.md) · [사전 채택 기준](PLAN.public.v1.md) · [원본 결과](OBSERVATIONS.actual.public.v1.json.gz) · [수치 요약](SUMMARY.actual.public.v1.json)

`hintprepared.Prepare`가 후보마다 큰 임시 특징 배열을 만들던 부분을, 생성자 안에서 배열 하나를 재사용하도록 바꿨습니다. 먼저 특징 개수를 세고, 각 후보의 결과를 정확한 길이의 최종 저장소에 복사합니다. 반환 객체에는 임시 배열을 공유하지 않습니다. 전역 캐시·pool·lock은 추가하지 않았습니다.

공개 Chi 개발 입력 **부모 1개**로 기존/새 구현을 6쌍씩 비교했습니다. 양쪽 실행 순서는 각 3번씩입니다. N은 준비 뒤 같은 입력으로 순위를 계산하는 횟수이며, 모든 구간에 준비 전체와 N번 Rank가 포함됩니다. 새 구현의 추가 토큰화·특징 개수 스캔도 비용에 포함했습니다.

| 구간 | 기존 Go 누적 할당 | 새 Go 누적 할당 | 바이트 감소 | 새 시간/기존 시간의 쌍별 중앙값 | 할당 횟수 |
|---|---:|---:|---:|---:|---:|
| N=1 | 445,880 B | 281,032 B | 36.97% | 1.0773배, 약 7.7% 증가 | 376 → 664 |
| N=8 | 445,992 B | 281,144 B | 36.96% | 1.0751배, 약 7.5% 증가 | 383 → 671 |

12쌍 모두 바이트 할당이 줄었고, 측정 전 기록한 **20% 이상 감소·N별 시간 중앙값 증가 25% 이내** 기준을 통과했습니다. 이 기준은 메모리를 우선하는 이번 준비 최적화의 선택 기준입니다. 속도가 빨라졌다는 결과는 아닙니다. 시간 비율 범위는 N=1에서 0.9679–1.1537, N=8에서 1.0366–1.1163입니다. 할당 횟수는 288회 늘었습니다. 다음 과제는 반복 토큰화와 작은 문자열 할당을 줄이는 것입니다.

최종 저장소는 기존과 같습니다: 특징 10,589개, tight 배열 169,424 B, 복제한 텍스트 1,000 B, 객체 고정 영역 224 B입니다. 합계 **170,648 B는 논리 저장량**이며 Go allocator·실제 retained heap·RSS 수치가 아닙니다. 위 표는 측정 구간의 `TotalAlloc`과 `Mallocs`이며 기록 래퍼 비용도 포함합니다. 최대 메모리·CPU/GPU 사용률이나 전체 프로세스 메모리를 37% 줄였다는 뜻이 아닙니다.

첫 실제 실행의 24구간과 모든 후보 점수를 보존했습니다. 명시 래퍼 140회가 모두 반환했고 오류·패닉은 없었습니다. Prepare 26회와 Rank 110회이며, 주 비교 구간에는 Prepare 24회·Rank 108회가 들어갑니다. 나머지는 별도로 기록한 입력/모델 읽기·검증·View 생성과 비교 기준입니다. 원본 특징 계산은 수정하지 않았고, legacy Prepare 함수 본문과 Rank도 원래 바이트를 유지했습니다. 모든 특징 Index·float64 비트·순서와 점수·동점 순위가 일치했습니다.

**기존 모델의 올바른 후보 순위는 여전히 5위입니다.** 이 모델은 비활성 RIIDOH01 FP32 해시 특징 scorer이며 Laya 인코더가 아닙니다. 새 학습·모델 교체·기본 라우팅 활성화·독립 Golden 부모 추가·보호 평가·GPU/MPS 실행은 없습니다. 반복 24구간은 새 독립 사례 24개가 아닙니다. 실제 에이전트의 작업 완료 시간이나 LLM 비용 절감을 입증하지도 않습니다.

## 모델 없이 저장 결과 확인

저장소 루트에서 Go1.27.1로 실행합니다.

```sh
go test ./pkg/hintprepared -run '^TestConstructorSaved$' -count=1 -v \
  -constructor-saved "$PWD/experiments/short-claim/next-cohort-chi-audit/constructor-scratch/OBSERVATIONS.actual.public.v1.json.gz"
```

단일 gzip 프레임·CRC·EOF, 중복/누락/알 수 없는 JSON 필드, 고정 배열 길이, 전체 호출·후보 결과와 채택 기준을 검사합니다. 공개 입력의 지문을 확인하고 **변경하지 않은 Features로 특징을 별도 재계산**해 행 전체와 논리 바이트를 대조합니다. 이 사후 검사 호출은 실제 비교 래퍼 140회와 별도이며 모델 파일을 읽지 않습니다. 일반 테스트는 합성 가중치와 실패 대조군을 사용하고, 실제 비용 실행은 세 개의 명시 입력/모델/출력 옵션이 모두 있어야 동작합니다.
