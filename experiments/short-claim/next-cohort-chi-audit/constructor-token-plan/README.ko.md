# 원문 토큰 준비 공유: 할당을 줄이고 결과는 보존

[English](README.en.md) · [선택형 Go API](../../../../pkg/hintprepared/README.ko.md) · [사전 계획](PLAN.public.v1.md) · [전체 관측](OBSERVATIONS.actual.public.v1.json.gz)

`hintprepared.Prepare` 안에서 같은 원문을 여러 번 단어로 나누던 비용을 줄였습니다. 요청과 후보의 순서 있는 토큰을 한 번 준비하고, 요청의 해시 prefix를 특징 개수 계산과 특징 생성에 재사용합니다. 원문을 정규화된 문장으로 바꾸지 않습니다. 두 번의 교차 해시 계산과 최종 배열 복사도 그대로 수행하고 비용에 포함합니다.

준비 자료는 반환 객체에 남기지 않으며 전역 cache·pool·lock은 없습니다. 선택형 `Prepare` → `Rank` 인터페이스와 재사용·오류 계약은 같습니다. 실행은 Go, Node는 관리자용 소스 생성·검증 도구입니다.

## 첫 실측 결과

비교 기준은 이전 [scratch 생성자](../constructor-scratch/README.ko.md)입니다. 초기 legacy 구현과 비교한 수치가 아닙니다. 이미 공개된 Chi 개발 부모 **1개**의 요청과 후보 5개를 사용했습니다. N은 Prepare 후 같은 입력을 Rank하는 횟수입니다. N별 6쌍, 양쪽 실행 순서를 각각 3번씩 바꿔 총 24구간을 측정했습니다.

| 지표 | 기준 scratch | token plan |
|---|---:|---:|
| 구간당 Go 누적 할당 | 281,000 B | 244,792 B |
| 구간당 Mallocs | 662 | 241 |
| N=1 쌍별 경과 시간 비율 중앙값 | 1 | 0.99017 |
| N=8 쌍별 경과 시간 비율 중앙값 | 1 | 0.97795 |

12쌍 모두 할당 바이트가 **12.89%** 줄었고, 할당 횟수는 **421회(63.60%)** 줄었습니다. 시간 중앙값은 N=1에서 약 0.98%, N=8에서 약 2.20% 낮았습니다. 사전에 정한 모든 쌍의 할당 증가 없음·Mallocs 최소 144회 감소·N별 시간 비율 중앙값 1.00 이하 기준을 통과했습니다.

다만 3쌍은 느렸고, 가장 느린 새/기준 비율은 약 1.0910입니다. 반복 과정에서 기준 측정 시간도 낮아졌습니다. 실행 순서 교대만으로 워밍업과 시간 변동을 모두 제거하지 못하므로 보편적인 속도 향상으로 해석하지 않습니다. 프로파일을 켜지 않은 경과 시간이며 CPU 사용률 측정이 아닙니다.

최종 **논리 저장량 170,648 B**는 같습니다: 특징 10,589개(169,424 B), 텍스트 1,000 B, 객체 224 B. 누적 할당은 최대 메모리·retained heap·RSS가 아닙니다. 특징 비트·순서·상쇄된 0, 후보 5개, 점수·동점 순위·offsets·tight capacity·텍스트 소유권을 보존하고 원본 Features를 대조군으로 유지했습니다.

명시 래퍼 140회가 모두 반환했고 오류·패닉은 없었습니다: Prepare 26회·Rank 110회입니다. 주 측정에는 Prepare 24회·Rank 108회가 포함되고 입력/모델 읽기·검증·View 생성·비교 기준은 별도 기록입니다. 사후 모델 없는 특징 재계산과 숨은 내부 호출을 이 140회에 합치지 않습니다.

## 모델 없이 결과 확인하기

저장소 루트에서 Go1.27.1과 Node로 저장 검사를 실행합니다.

```sh
scripts/verify-chi-token-plan.sh
```

지문으로 고정한 임시 모듈로 gzip 전체·CRC·EOF·JSON, 호출 일정, 모든 특징/점수 비트와 기준을 검사합니다. 모델 파일·다운로드·새 모델 추론은 없습니다. 모델 재실행 대신 이 검사를 사용하세요. [동결](FREEZE.public.v1.json), [첫 실행](EXECUTION.actual.public.v1.json)에 원본 JSON 1,047,402 B를 71,015 B gzip에 전체 보존한 근거가 있습니다.

**모델의 올바른 후보는 여전히 5위입니다.** 기존 비활성 failed79 RIIDOH01 FP32 scorer의 [Hugging Face 고정 버전](https://huggingface.co/JooYoon/riidolaya-shortclaim-data-effect-failed-79/tree/5bef215895b69d3f2ef4b82bb3f1970279d67f46)은 모델 보관 참조입니다. 새 학습·Fit·checkpoint·기본 활성화는 없습니다. Laya 인코더·MPS/GPU 실행이나 LLM 비용 절감을 입증하지 않습니다. 반복 24구간은 독립 Golden 사례 24개가 아닙니다.

이 문서 작성 시 로컬 대조군·race 검사는 통과했고 공개 CI·배포는 대기 중입니다. 병합은 필수 CI 성공과 bot gate에 의존하며 사람 승인으로 대체하지 않습니다.
