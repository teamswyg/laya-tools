# Chi 후보 순서의 실제 확인 비용

작은 주장 모델은 후보의 확인 순서를 제안합니다. 이 실험은 그 제안이 **정답을 확인하기까지 드는 실제 비용**을 줄이는지 살펴봅니다. 예를 들어 URL 처리 후보 다섯 개 중 하나만 요구사항을 모두 만족한다면, 그 후보를 앞에 제안할수록 불필요한 확인을 줄일 수 있습니다. 제안 자체가 정답 판정은 아니므로, 선택한 후보는 항상 같은 아홉 개 확인을 모두 통과해야 합니다.

이 자료는 공개 Chi 사례 **부모 하나**를 반복 관찰한 개발 실험입니다. 반복 32회가 독립된 사례 32개가 되지는 않습니다. 현재 실패 판정을 유지한 FP32 모델을 그대로 사용하며, 새 학습·레이블·역할 지정·기본 모델 활성화는 없습니다. Laya 인코더나 GPU를 실행하는 실험도 아닙니다. 모델의 전체 효과나 Codex 비용 절감은 별도 사례와 실제 작업으로 검증해야 합니다.

## 실제 결과

32개 파이프라인이 모두 `post_path`를 아홉 개 확인으로 검증했습니다. 확인 불가능과 fallback은 0회였습니다. 다만 모델은 올바른 후보를 다섯 번째에 제안해 확인 작업을 더 많이 했습니다. **기존 모델의 비활성 상태를 유지합니다.**

| 순서 | 방문 후보 | 확인 실행 | 명시 Chi API 호출 |
|---|---:|---:|---:|
| BM25·고정·단어 기반 | 1 | 9 | 107 |
| 기존 모델 | 5 | 16 | 198 |

아래 값은 방식별 4회 관찰의 중앙값입니다. 내부 구간 시간과 Go 할당을 같은 경계로 비교했습니다.

| 방식 | 새 프로세스 내부 구간 | 준비본 재사용 내부 구간 | 새 프로세스 Go 할당 | 재사용 Go 할당 |
|---|---:|---:|---:|---:|
| BM25 | 262.6µs | 53.5µs | 190,056B | 64,752B |
| 고정 순서 | 261.8µs | 35.9µs | 190,264B | 64,720B |
| 단어 기반 | 263.7µs | 56.2µs | 190,376B | 64,568B |
| 기존 모델 | 1,606.5µs | 64.4µs | 816,424B | 114,392B |

모델/BM25의 같은 블록 시간 비율은 새 프로세스 내부 구간에서 **5.10–6.57배**, 재사용 구간에서 **0.75–1.68배**였습니다. 재사용 시간은 네 쌍 중 두 쌍에서 모델이 짧고 두 쌍에서 길었습니다. 이를 일관된 속도 향상이나 일반 성능으로 해석하지 않습니다. 재사용 블록의 준비에는 별도로 **1.37–1.60ms**, 약 **701,800B의 Go 할당**이 들었습니다. 준비 비용을 제외한 짧은 구간만 보고 전체 비용이 줄었다고 결론 내리지 않습니다.

바깥에서 잰 새 프로세스 시간 중앙값은 BM25 4.43ms, 모델 5.88ms였습니다. 블록별 모델/BM25 전체 프로세스 시간 비율은 0.89–1.39배로 세 쌍에서 모델이 길고 한 쌍에서는 짧았습니다. 재사용 프로세스의 전체 시간 6.58–7.26ms는 준비와 네 방식 모두에 속하므로 방식별 시간으로 배분하지 않습니다. 관찰 수가 작고 같은 부모를 반복했으므로 시간 차이에 통계적 일반성을 부여하지 않습니다.

재사용 블록은 준비 후 서로 다른 네 방식을 한 번씩 실행합니다. 같은 모델을 여러 번 호출하면서 준비 비용이 상각되는 효과는 이번 시험에 포함하지 않았습니다. 이번 재사용 모델 시간은 이미 지불한 준비 비용을 제외한 구간입니다.

실제 Chi 실행은 사전검사 45회와 시간 측정 344회, 합계 389회이며 명시 API 호출은 합계 4,685회였습니다. 모델 순서 계산은 준비 검사 1회와 시간 측정 8회, 합계 **실제 9회**였습니다. 모델을 실행하지 않은 합성 검사는 컨트롤러 7개와 worker 11개입니다. 전체 원문은 [압축 관찰 기록](OBSERVATIONS.actual.public.v1.json.gz), 집계와 블록별 값은 [결과 요약](SUMMARY.actual.public.v1.json)에 있습니다.

## 비교 방법

비교 대상은 BM25, 고정 순서, 단어 기반 순서, 기존 모델의 순서입니다. 모든 방식이 후보 다섯 개를 보존합니다. 순서대로 후보를 방문하고, 후보 하나에서 요구사항 위반이 확인되면 다음 후보로 넘어갑니다. 확인 자료가 불완전하거나 실행이 실패한 경우는 `unavailable`로 남깁니다. 확인 불가능을 통과로 처리하지 않습니다. 아홉 개가 모두 통과한 후보만 `verified`로 선택합니다.

호출과 값 캡처가 모두 남아 있는 상태에서 정상 종료나 반환 값이 요구사항과 다르면 알려진 불일치로 분류합니다. 호출 기록이 없거나 잘렸거나 반환을 확인할 수 없으면 확인 불가능으로 분류합니다.

먼저 45개 조합을 실제 Chi API로 다시 확인하고, 기존 관찰값 전체와 대조합니다. 별도 준비 검사에서는 모델 점수의 비트와 네 검색 기준의 순서를 기존 기록과 대조합니다. 시간 측정 구간에서도 방문한 확인마다 Chi API를 다시 실행합니다. 준비 검사의 정답을 조회해 실행을 생략하는 캐시는 없습니다.

시간 측정은 두 사용 상황으로 나눕니다.

- 매번 새 프로세스: 4개 방식 × 4개 순서 블록, 총 16회. 입력 읽기와 모델 준비 비용을 해당 실행에 포함합니다.
- 같은 프로세스에서 준비본 재사용: 새 프로세스 4개 안에서 방식 4개를 실행하여 총 16회. 입력·모델·특징 준비 비용을 블록별로 따로 기록합니다.

블록 안의 실행 순서는 Williams 배열로 고정했습니다. 각 방식이 첫째부터 넷째 위치에 한 번씩 오고, 서로 바로 앞뒤에 오는 조합도 균형을 맞춥니다. 새 프로세스가 운영체제 파일 캐시까지 초기화한다는 뜻은 아닙니다.

## 숫자를 읽는 방법

후보 방문 수와 Chi 공개 API 호출 수는 일을 얼마나 더 했는지 보여줍니다. 호출 한 번의 비용은 API마다 다르므로, 호출 수만으로 속도 향상을 계산하지 않습니다. 실제 확인 파이프라인 시간, Go 할당 바이트·할당 횟수, 바깥에서 측정한 프로세스 전체 시간을 함께 기록합니다.

프로세스 전체 시간에는 시작, 가비지 컬렉션, 결과 인코딩도 포함됩니다. 내부 구간에서는 가비지 컬렉션과 메모리 통계 조회를 타이머 바깥에 두고, 실제 확인과 기록 생성은 포함합니다. Go 할당값은 전체 메모리 상주량(RSS)이나 GPU 메모리 측정값이 아닙니다. 준비본 재사용의 준비 비용도 결과에 별도로 남깁니다.

측정 작업은 `GOMAXPROCS=2`, `GOMEMLIMIT=96MiB`로 실행합니다. 후자는 Go 가비지 컬렉터의 메모리 목표이며 프로세스 전체 메모리를 강제로 제한하는 값은 아닙니다.

## 재현과 기록

`run`의 공개 Go 프로그램은 소스·입력·모델의 SHA-256과 실행 계획을 확인하고, 제한된 임시 작업 폴더에서 작업합니다. 모델 경로는 사용자가 명시합니다. 모델 본체는 GitHub에 포함하지 않습니다.

Go 1.27.1로 저장된 결과를 검사할 수 있습니다. 이 명령은 모델 파일을 읽거나 확인 작업을 새로 실행하지 않습니다.

```sh
go run ./experiments/short-claim/next-cohort-chi-audit/cost-pilot/run \
  -saved experiments/short-claim/next-cohort-chi-audit/cost-pilot/OBSERVATIONS.actual.public.v1.json.gz
```

실제 시험은 `RIIDO_MODEL_FILE`에 아래 고정 모델 파일의 로컬 위치를 설정한 뒤 실행합니다. 결과 파일은 기존 파일을 덮어쓰지 않습니다.

```sh
go run ./experiments/short-claim/next-cohort-chi-audit/cost-pilot/run \
  -model "$RIIDO_MODEL_FILE" -out chi-cost-local.json.gz
```

모델 참조: [JooYoon의 기존 FP32 실패 모델, 고정 리비전](https://huggingface.co/JooYoon/riidolaya-shortclaim-data-effect-failed-79/tree/5bef215895b69d3f2ef4b82bb3f1970279d67f46). 파일은 32,792바이트이며 SHA-256은 `dff05140098845943ece87c3ab8a31a15564a4b170a59ab017ee393501158004`입니다.

실행 계획과 소스는 첫 시험 전에 고정합니다. 원본 관찰 코드는 `main` 이름만 바꾼 사본으로 재사용합니다. 모든 후보·미방문 표시·실행 호출 기록·실패 사유를 보존하고, 호출 기록이 없거나 결과를 조작한 자료를 거부하는 합성 검사를 둡니다. 합성 검사는 모델 성능 사례에 포함하지 않습니다.

상위 [Chi 실험 설명](../README.ko.md)과 라이선스 고지를 함께 읽어 주세요. 선택한 Chi 소스의 MIT 고지와 Armon 고지는 상위 `source`에 보존되어 있습니다. 이 유한 소스 실행의 허용 여부와 전체 소스 계열의 학습 허용 여부는 별도로 관리합니다.
