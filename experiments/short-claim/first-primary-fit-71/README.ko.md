# 첫 주장 모델 학습: 완료, 효용은 실패

첫 encoder-free FP32 모델은 학습을 마쳤지만 기존 규칙보다 확인 횟수를 줄이지 못했습니다. 현재는 비학습 규칙을 유지합니다. 이 실험은 짧은 요청에서 모든 후보를 남겨 두고 **확인할 순서만 제안**하는 모델을 시험합니다. 후보를 삭제하거나 작업을 승인하는 결정 모델이 아닙니다.

| 검증 요청 15개에 적용한 방식 | 총 확인 횟수 | 첫 후보가 정답인 요청 | 상위 3개 안의 정답 |
|---|---:|---:|---:|
| 원래 순서 | 31 | 1 | 10 |
| BM25 | 28 | 5 | 10 |
| 단어·순서 규칙 | **27** | **5** | 10 |
| 좁은 조건 규칙 | 28 | 5 | 10 |
| 첫 학습 모델 | **31** | **2** | 10 |

검증 요청 20개 중 정답 미확정 5개를 제외한 15개가 분모입니다. 그중 정답이 있는 요청은 10개, 정답이 없는 요청은 5개입니다. 정답이 없으면 모든 후보 확인 비용을 유지합니다. 정답이 알려진 후보 45개는 마스크가 있어도 모두 효용 평가에 포함했습니다. 비교군은 총 확인 횟수가 가장 작은 방식 하나를 고르며 동률 순서는 사전에 고정했습니다.

단어·순서 규칙 대비 개선율은 `(27−31)/27 = −14.81%`였습니다. 최소 5% 개선·Top1/Top3 유지 조건 중 개선과 Top1이 실패했습니다. 이론적 oracle은 21회여서 개선 여지는 있었지만 모델이 이를 얻지 못했습니다. fully eligible 진단 B에서도 26→30으로 악화했습니다. 악화분 4회는 lifecycle-acquire의 요청 세 개에서 나왔습니다. 미확정 자료나 마스킹된 한 후보만의 탓으로 해석하지 않습니다.

## 무엇을 실제로 실행했나

전체 76개 요청의 [배열 준비](../projection-execution-76/README.ko.md)를 재사용했습니다. train 91행/validation 45행과 가중치 0인 18/1행을 그대로 유지했습니다. 새 역할·라벨·feature 추출·calibration 학습·보호된 최종 평가·유료 모델 호출은 하지 않았습니다. 모델의 feature 입력은 원래 요청과 후보 텍스트뿐입니다.

Go 1.27.1에서 seed1729, FP32 계수 8192개, LR0.1, L2 0.0001, batch128, 50epoch를 고정해 FitWithTrace를 **한 번** 실행했습니다. 원래 validation BCE 손실이 가장 낮은 최초 epoch를 선택했고 이번에는 50이었습니다. train NLL 0.6514239277140677, validation NLL 0.6657976915843424였습니다. 같은 validation을 epoch 선택과 효용에 썼으므로 최종 일반화 결과가 아닙니다. 91행이 batch128보다 적어 epoch당 갱신 한 번, 총 50번이었습니다.

FP32 파일은 32,792 B이며 SHA256 `5ecbeb9b35f67cd91de5c1674d0398e9890bae51029684f45cc955e7407c7049`입니다. Decode는 float64 계수로 풀어 계수 배열만 65,536 B가 됩니다. optimizer와 손실 계산도 float64를 사용합니다. 파일 크기가 실행 메모리 전체를 뜻하지 않습니다. 가중치는 private 파일로 보존하고 Git에 올리지 않았습니다. 현재 게시 적격성·production 상태는 false입니다.

전체 학습 자식 프로세스의 최대 RSS는 28,295,168 B(약 26.98 MiB), 바깥 실행 시간은 0.805194625초였습니다. 입력 읽기·기존 비교군·학습·checkpoint·파일 저장을 포함한 단일 관측입니다. CPU 1개·heap soft limit 256 MiB·바깥 timeout 300초를 설정했습니다. GPU/Laya 인코더·상시 추론 지연·LLM 비용 절감을 측정한 것이 아닙니다. [실행 장부](actual/ROOT-ACTUAL-LEDGER-71.v1.json)와 [전체 수치 결과](actual/results.json)에 원래 값을 보존했습니다. 협업 AI 비용은 미측정입니다.

## 다음 한 번의 실험

평균 BCE 감소가 같은 요청 안의 정렬 개선을 보장하지는 않습니다. 그렇다고 BCE로 순위를 배울 수 없다는 결론도 아닙니다. 자료·단어 특징·학습량의 한계를 분리해야 합니다. 다음 [사전 고정 계획](NEXT-PDCA-71.v1.json)은 BCE를 유지하면서 같은 요청의 정답/오답 후보 쌍에 상대 순서 손실을 하나 추가합니다. λ=1, 쌍 평균 뒤 요청 평균으로 고정하고 기존 seed·특징·마스크·validation BCE epoch 선택·효용 조건을 유지합니다. 계수·seed·임계값 탐색은 하지 않습니다.

이는 원래 모델의 압축 자식이 아니라 같은 자료·특징을 쓰는 학습 목적의 형제 실험입니다. 3진 압축은 효용을 확인한 뒤의 별도 단계입니다. 같은 validation의 실패를 보고 고른 후속이므로 개선돼도 개발 신호이며, 새로운 원천 그룹의 도메인별 최소 2,400개 독립 요청으로 검증하는 최종 골든셋 목표를 유지합니다.

지금 사용하려면 기존 Go 도구 `riido-shortclaim --stream --baseline lexical_ordered < requests.jsonl`로 순서 힌트를 받을 수 있습니다. 모든 후보를 반환하고 결과는 `unverified_heuristic`입니다. 실제 업무에서 절감되는지는 별도 관측이 필요합니다. 이 명령은 새 학습 가중치를 사용하지 않으며 Codex 등록도 자동으로 하지 않습니다.
