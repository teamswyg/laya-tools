# 요청 안의 후보 순서를 학습하는 형제 실험

첫 FP32 학습은 개발 검증에서 기존 단어·순서 규칙의 확인 27회보다 많은 31회를 요구했습니다. 후속에서는 후보별 BCE 학습을 유지하고, **같은 요청의 정답 후보가 오답 후보보다 높은 점수를 받는 손실**을 λ=1로 추가합니다. 목적함수만 바꿔 보는 별도 실험이며, 아직 실제 자료로 두 번째 학습을 실행하거나 효용 개선을 확인하지 않았습니다.

`internal/pairlearn`의 `FitWithRanking`과 `FitWithRankingTrace`를 선택적으로 사용합니다. 기본 API와 유효한 λ=0 결과는 기존 구현과 같습니다. 요청별로 양성·음성 쌍을 평균한 뒤 요청 사이에서 평균하므로 후보가 많은 요청이 과도한 비중을 갖지 않습니다. 마스킹된 쌍은 가중치 0으로 기록에 남기며, 정답이 없는 요청은 원래 BCE에 남습니다. 정답 미확정 자료와 calibration의 제외는 상위 입력 준비에서 보장합니다. 요청 ID와 감독 비중은 모델 특징이 아닙니다.

새 배열은 SoA로 소유하며 map·lock을 추가하지 않았습니다. 새 배열의 64 MiB 한도는 전체 프로세스 RSS의 제한을 뜻하지 않습니다. seed·특징·라벨·마스크·역할·epoch 선택과 기존 효용 조건을 유지하고, 실제 후속은 한 번만 실행할 계획입니다. 같은 validation의 실패를 보고 정한 실험이므로 개선돼도 개발 신호입니다. 최종 검증에는 새로운 원천 그룹의 도메인별 최소 2,400개 독립 요청이 필요합니다. 이 모델은 기존 FP32의 압축 자식이 아닌 목적함수가 다른 형제이며, 3진 압축은 별도 단계입니다.

합성 자료의 기울기·마지막 미니배치·기존 동작 검사는 통과했습니다. 독립 검토에서도 literal 쌍 비중, 231개 배치의 평균 기울기, 역사 코드의 12개 구성 동등성을 확인했습니다. 이는 실제 자료의 효용이나 일반화 검증을 대신하지 않습니다. 새 CLI 활성화·Codex 등록·GPU 실행·비용 절감 주장은 없습니다.
