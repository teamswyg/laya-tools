# Independent review of the private 64 pure projection

No concrete code defect was found that blocks a port of the current exported `Project` call. This conclusion concerns newly authored synthetic inputs and bounded code/API reading; it is not approval of live corpus eligibility, a role plan or training readiness. The original projection SHA `572e33a815b9a123c0e521d92567d6f254526250ab4d82e202487ddbe1d517e5` and test SHA `c312a1ba1aab690ff613510a572d4604b74cedc4e243b10c7a666d8ed6ef82c8` matched before and after review and in the independent private copy.

Known truth retains the complete acceptable set and its original order. Other known candidates and the existing negatives of no_answer remain label 0. A mask neither changes the original truth nor deletes a row: it assigns explicit weight 0 to the same feature row. Unknown retains nullable audit state without producing fit rows. Calibration also retains full text, truth and masks without entering loss or training AUC diagnostics. Independent synthetic checks covered eight candidates, all-acceptable and reverse-order acceptable sets, masked positives, no_answer, unknown and calibration combinations.

A `WholeGroup` appearing across roles is rejected, including unknown, all-masked and calibration cases. Checks covered every distinct pair of the three roles and failed before feature calls. The positive-weight AUC view owns backing arrays/RowRefs separate from the loss dataset and contains only positive-weight rows. AUC on this view is the existing unweighted diagnostic; it does not replace full-candidate ranking, fallback, Top or the existing 5% utility evaluation. Unknown-only/all-zero groups do not count as positive-weight groups.

The 64 MiB limit is implemented as an output payload bound. The independent test separately summed Projection and RuntimeParent structures/slice headers, retained string lengths, and the actual **capacities** of sparse columns and RowRefs; the result matched `PayloadBytes`. The exact synthetic output limit passed, while one byte less failed with a zero Projection. A reduced implementation limit also confirmed that an oversized parent array fails before malformed-parent validation or feature extraction. Accounting includes the four offsets sentinels of an empty projection. The existing preflight bounds parent count using output RuntimeParent size and bounds candidate count at eight per parent, so feature totals/row counts cannot arbitrarily cross the int range before rejection. This review did not run a workload near 64 MiB or measure RSS/CPU/GPU. Caller inputs, sorting/row-plan scratch, feature-function temporary arrays and allocator slack are separate; total peak memory cannot be claimed to stay below 64 MiB.

Both feature passes check length, duplicate indices, dimension and finiteness. Current `hintlearn.Dimension=8192` restricts indices to 0..8191, making conversion to uint16 safe. The maximum valid index was preserved; the dimension boundary, 65535, 65536, negative indices and second-pass NaN/±Inf were rejected. Metadata, truth, roles, opaque groups and masks are not feature arguments: only original request/candidate text is passed. Input fixture IDs/provenance remain audit side material. Changing caller acceptable/Prepared/group values after return did not change the returned snapshot, and loss/diagnostic arrays did not alias each other.

The following limits remain.

- `ValidatePrepared` checks internal value consistency only. It does not prove original source/text/truth SHA, original binding or the justification of review eligibility flags.
- `WholeGroup int` is an opaque caller identifier. The function detects cross-role collisions of the same number, but cannot prove that the caller did not assign different numbers to members of one original component or omit members outside the batch. Complete membership and the original 9/3/3 coverage remain responsibilities of the frozen caller path.
- `RoleEnumContract` describes the current 0/1/2 bridge only. Final public integration must separately bind the actual roleplan source and frozen input.
- `Project` does not support callers concurrently modifying inputs. Input strings share normal immutable Go values, while returned slices are mutable caller-owned results. Freezing/integrity before Fit is the separate driver's responsibility.
- The private injectable `project` does not compare **different finite feature values of the same length** between passes. Current exported `Project` accepts no callback and uses only the inspected pure `hintlearn.Features`, so this is not a blocker for the current call contract. This assumption needs review if external extractor injection is introduced later.
- Successful empty/all-zero-weight projection does not mean successful fitting or readiness. The separate driver must preserve existing Fit validation of data and total weight. Unknown or zero-loss groups must not fill the old floors.

Five new top-level tests were added to an independent private copy and passed in one uncached race invocation together with the original seven tests: twelve top-level tests, 27 including subtests, package 1.419s. One vet invocation and formatting checks passed. Execution failures and original/shared file modifications were zero. Intermediate output JSON was truncated by the tool output limit, but final package pass and exit 0 were separately confirmed by polling. No complete raw-output file is claimed. Live corpus/sourceAPI/roles/labels/seed/fit/AUC scoring/model/paid-process/publication executions were all zero, and no new scientific gate was introduced.
