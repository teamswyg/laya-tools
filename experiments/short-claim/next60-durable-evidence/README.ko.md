# 결과를 작게 저장하고 검증하는 실행 연결 실험

[English](README.en.md) · [CI](https://github.com/teamswyg/laya-tools/actions/workflows/ci.yml)

아주 작은 힌트 모델을 여러 번 호출하는 시스템에서는 모델뿐 아니라 주변 코드의 비용도 작아야 합니다. 이 실험은 학습 전에 **실행 결과를 적은 공간에 저장하고, 실패한 실행을 성공 데이터로 받아들이지 않는 연결 코드**를 검증합니다.

모델을 새로 학습하거나 Laya를 실행한 실험은 아닙니다. API는 직접 만든 가짜 함수입니다. 파일 생성·쓰기·Sync·다시 읽기와 저널/ACK 연결은 실제 임시 파일에서 검사했습니다. CI의 기존 Laya 추론 검사는 별도 단계이며 GPU 실행 근거는 아닙니다.

## 무엇이 달라졌나

- 결과를 한 번에 39개 큰 구조체로 쌓는 대신, 한 행씩 작은 JSON으로 저장합니다. 파일 상한 64KiB, 행 상한 1,536B를 유지합니다.
- `모름`, `false`, `nil`, 비어 있는 값과 오류 종류를 구별합니다. 아직 알 수 없는 값을 학습용 정답으로 바꾸지 않습니다.
- 메서드 참조와 호출 스택은 고정 배열입니다. 한 수신 루프가 상태를 소유하므로 map이나 상태 공유용 lock이 필요하지 않습니다. 중첩 호출의 종료 순서가 달라도 처음 예약한 순서를 보존합니다.
- 파일에 저장한 사실, 저널의 Sync, 외부 ACK와 전체 완료를 따로 기록합니다. ACK가 끊기면 파일에 남은 행은 실패 흔적으로 보존되고 성공으로 승격되지 않습니다.
- 행의 실제 바이트·SHA·형식·작업 ID·호출 소속을 먼저 확인하고 저널/ACK를 진행합니다. 마지막에는 전체 파일의 헤더·푸터·행·SHA를 확인합니다.

Go 기본/호환성 race 검사, vet와 포맷 검사를 통과한 테스트는 **93개, 하위 사례 152개**입니다. 연결 테스트는 39행·가짜 메서드 51회·프레임 260개를 처리하며 두 루프 종료와 EOF까지 확인합니다. 이것은 원본 라이브러리의 96개 메서드·91개 콜백 실행이나 새로운 Golden 데이터 증명이 아닙니다.

## 사용법

Go 1.27.1을 준비한 저장소 루트에서 실행합니다. Python이나 모델 다운로드가 필요하지 않습니다.

```sh
bash scripts/verify-next60-durable-evidence.sh
RIIDO_EVIDENCE_BENCH=1 bash scripts/verify-next60-durable-evidence.sh
```

첫 명령은 한·영 문서와 SHA 목록에 고정된 소스를 임시 디렉터리에 옮겨 검사합니다. 두 번째는 읽기 검사 비용도 측정합니다. 임시 검사 파일은 실행 후 정리하며 실패한 원본 실험 기록은 따로 보존했습니다. 자동화에서는 종료 코드 0을 확인한 뒤 다음 단계로 진행하세요. 프로파일 환경 변수는 기본적으로 비활성화됩니다.

## 메모리 측정 결과의 범위

Apple M4 Pro, Go1.27.1, GOMAXPROCS=2, GOMEMLIMIT=64MiB에서 200ms씩 3회 측정했습니다. GOMEMLIMIT은 Go GC의 참고 한도이며 하드 RAM 상한이 아닙니다. 기존 소스 본문을 그대로 복사한 비교 버전과 같은 입력을 사용했습니다.

| 입력과 검사 | 기존 시간 중앙값 | 변경 후 | 기존 B/op | 변경 후 B/op |
|---|---:|---:|---:|---:|
| 최대 64KiB가 모두 LF인 잘못된 파일, 참조 39개 | 677,815ns | 29,907ns | 1,711,176 | 139,336 |
| 정상 파일 39행 | 9,008ns | 8,980ns | 12,782 | 12,783 |

잘못된 파일에서도 올바른 전체 SHA를 공급해, 단순 해시 실패 때문에 빨라진 비교를 피했습니다. 행 수로 문자열 분할의 임시 목록을 제한하여 이 경우 할당 바이트가 약 91.9% 줄었습니다. 할당 **횟수**는 21회로 같습니다. 정상 39행의 속도 개선은 입증하지 못했습니다. 정상 0행은 여유 슬롯 때문에 32B/op 늘었습니다.

이 수치는 Go 읽기 함수의 비용입니다. RSS, GPU 메모리, Laya 추론, 토큰 절약, 전체 작업 시간 또는 1.58-bit 계산 성능으로 해석할 수 없습니다. SIMD 변경은 적용하지 않았습니다.

## 다음 단계와 공개 범위

실제 원본 실행은 라이선스·선택된 의존 소스·컴파일 결과·프로세스 종료·RAM 관측을 확인한 후 진행합니다. 6MiB 바이너리 상한을 강제하는 방법은 아직 실행한 정책이 아닙니다. 이후 독립 작업·Golden 그룹·전체 작업 비용을 확보해야 모델 튜닝과 Hugging Face 새 모델 배포 여부를 판단할 수 있습니다. 현재 새 모델·학습·Golden 추가는 0입니다.

과거 집계 및 배포 목록 5개는 실제 복원 확인 뒤 압축 보관했습니다. 512MiB 실험 기록 저장 예산을 유지하며 새 공간을 확보한 작업입니다. 모델 RAM 개선으로 계산하지 않습니다. 실패한 테스트의 원인과 교정 기록도 `history/`에 남겼습니다.

원본 라이브러리 본문, 사용자 실제 작업, 토큰, 모델 가중치, 바이너리, raw 저널과 프로파일은 포함하지 않습니다. 소스와 검사 증거는 `SOURCE-BINDINGS.public.v1.json`, `evidence/`, `FILE-MANIFEST.v1.json`, `SHA256SUMS`로 연결합니다. 공개용 모듈 경로만 상대 경로로 바꾸었으며 원래 검사 핀과 구별했습니다.
