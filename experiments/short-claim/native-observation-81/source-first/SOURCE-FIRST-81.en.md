# Two new source families: reading before execution

This preparation reads type conditions in `mapstructure` and string-list state in `pflag`. Twelve original source/license files were verified against fixed commits and Git blob bytes. Original compile/import/init/API/tests, observers and models were never executed. Four proposed behavior goals belong to two source families; fixtures and translations do not become independent families. Truth, candidate satisfaction, roles and weights remain null.

`StringToTimeHookFunc` calls `time.Parse` only for a string source and the exact destination type `time.Time`. A pointer or separately defined time type is different. Preserve the returned type/value even on error, and inspect the outer error and unwrap separately. This revision may wrap `*time.ParseError` in its private `timeParseError`. Exact invalid-date values and error strings need a later predeclared Want supported by the applicable Go parser source.

`StringToSliceHookFunc` uses the exact condition `t == reflect.SliceOf(f)`, rather than accepting any slice. For builtin `string` to exact `[]string`, an empty string returns a nonnil empty slice; comma splitting preserves order, duplicates and interior empty fields. The separate weak-slice hook has a different contract. Named string types can pass the Kind guard but conflict with `data.(string)`. Initial proposals use builtin types and make no universal reflection, nil-receiver or panic-safety claim.

Hook constructors return anonymous functions inside `any`. An adapter must not blindly assert the named `DecodeHookFuncType`. The public `DecodeHookExec` conversion path and valid reflection arguments are proposed. A direct hook return is distinct from destination mutation performed by the complete Decoder.

The first successful `pflag` string-list `Set` replaces defaults; later successful calls append parsed CSV fields. CSV errors return before changing the value or internal `changed` state. `FlagSet.Set` adds `InvalidValueError` and changes public `Flag.Changed` only after success. Its observations differ from calling the underlying Value.Set directly.

`Replace` and `Append` do not parse CSV and do not activate internal `changed`. A first successful Set therefore still replaces a prior Replace; after an earlier successful Set, Replace preserves the state that makes the next Set append. Useful inputs distinguish Replace(nil), a nonnil empty slice, a single string containing commas and duplicates. Defaults, Replace input and GetSlice can share backing storage; they are not owned copies. GetStringSlice follows a separate String/CSV reparse path.
