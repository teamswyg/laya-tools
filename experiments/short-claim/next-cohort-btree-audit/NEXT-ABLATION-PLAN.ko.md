# 다음 튜닝은 표현의 효용부터 검증한다

이 자료는 12개 요청·한 소스 가족의 개발 학습 자료다. 기존37 JSONL을 수정하거나 두 형식을 하나의 데이터셋으로 합치지 않았다. 추가96개 후보의 유한 T/F 라벨과 실제 Go Reader/Project 경로를 준비했으며, 새로운 모델 학습은 아직 시작하지 않았다.

이번 관측에서는 최소 확인26회에 비해 네 기준이54~59회 필요했다. 새 힌트가 개선할 여지는 있지만, 가벼운 Go 검증의 낙관적 추가 계산 여유는 요청당 약8.62µs뿐이다. 준비·추론·fallback을 포함해야 하며, 이 숫자는 실제 달성 속도나 새로운 실험 실행 예산이 아니다. LLM을 호출하는 검증의 비용은 별도로 관측해야 한다.

다음 실험은 기존 hashed8192 FP32와 별도 작은 관계 특징 head를 비교한다. 기존 모델 포맷·가중치·기본 라우팅은 보존한다. 관계 특징은 요청과 후보의 원문만 읽고 방향, 연산자·경계 포함, 실행 순서, 조기 종료 같은 제한된 패턴을 표현한다. 인식되지 않는 문장은 coverage가 없는 상태로 남긴다. 특징이 참이라는 판단이나 자동 승인 권한을 부여하지 않는다.

두 표현에서 학습 목적·seed·epochs·라벨·역할을 같게 두어 표현 변화만 비교한다. loss나 threshold 탐색·새 양자화를 함께 바꾸지 않는다. 유용한 FP32 힌트를 확인한 뒤 INT8/ternary를 별도 자식·형제 실험으로 비교한다. 이것은 Laya encoder의 MPS 학습이나 tinyhead3등급 모델과 다른 경로다.

현재 no-answer 두 요청만 `with`, 다른 경계 요청은 `keeping`을 쓴다. 모델이 조건 대신 문체를 외울 수 있다. 이번 원문과 실패 기록을 수정하지 않는다. 다음 수집에서는 문체·후보 순서·truth를 관측 전에 독립적으로 다양화하고, 다른 코드 계보의 전체 가족 역할을 먼저 고정한다. 개발 가족 안의 변형은 새 독립 평가 가족으로 세지 않는다.

추가 Fit 전에 새 자료의 출처·고지·literal Want·unknown·역할을 검토하고 소스·입력·모델·자원 예산을 새로 봉인한다. 합성 실패 시험을 먼저 통과시킨다. 첫 실제 실패를 보존한다. Top1/Top3와 확인 횟수뿐 아니라 각 후보의 검증 비용, 준비·추론·fallback, no-answer·all-positive·unknown 층을 같이 보고한다. 관측하지 않은 독립2400 성능, 실제 에이전트 성공률, Codex 토큰 절감은 계속 미충족이다.
