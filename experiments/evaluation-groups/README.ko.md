# 연결 그룹과 평가 전용2,400개 고정 — 실험29

**중복과 공유 코드 상태를 함께 묶은2,455개 그룹에서 평가 대표 요청2,400개를 고정했다.** 같은 자료로 학습하거나 결과를 보고 쉬운 질문으로 바꾸지 않는다. 이는 평가 목록 준비이며 모델 성능 합격은 아니다.

## 어떻게 골랐나

[사전 계획](plan-29.json)에 따라2,594개 행에서 같은 식별자, 같은 정규화 요청문, 같은 저장소+수정 전 커밋 중 하나라도 공유하면 연결했다. 연결은 전이된다. A와B가 같은 요청문이고 B와C가 같은 커밋이면 A/B/C는 한 그룹이다. Go의 정렬 배열과 union-find 배열로 구현했다.

각 그룹의 대표는 출처를 붙인 식별자의 사전순 최솟값이다. 그룹의 모든 식별자를 정렬해 해시를 만들고, 그 해시 순서의 첫2,400개 그룹을 선택했다. 정답·난이도·성능·요청 길이는 선택에 쓰지 않았다. 전체 원천은 평가 전용이며, 선택되지 않은 그룹이나 형제 행도 학습·보정에 쓰지 않는다.

| 항목 | 결과 |
|---|---:|
| 원천 행 | 2,594 |
| 연결 그룹 | 2,455 |
| 여러 행이 연결된 그룹 | 128 |
| 가장 큰 그룹 | 5행 |
| 선택한 대표 | 2,400 |
| 고유 요청문 / 식별자 / 저장소+커밋 | 각각2,400 |
| 선택된 저장소 | 53 |
| Full / Multilingual 출처 | 2,107 / 293 |

그룹 크기는1행2,327개,2행121개,3행4개,4행2개,5행1개다. 선택한 요청끼리는 위 세 연결 기준에서 겹치지 않는다. **같은 저장소의 다른 커밋이나 의미가 비슷한 요청까지 독립적이라고 증명한 것은 아니다.** Django806개 등 출처 편중도 남는다. 평가에서는 저장소별 결과와 상관관계를 고려해야 한다.

[집계](results-29.json)의 선택 구성 SHA-256은 `fa58c4e51ae307963eb587813e49adf70d987dcb4893f6ee1aa6050bc6b80a5a`다. 원문 없는 개별 선택 목록은 로컬0600 권한 파일에만 보관한다. Git에는 개별 식별자나 개별 해시를 넣지 않는다. 원천 조건이나 과제 적합성 때문에 변경이 필요하면 새 계획과 변경 이유를 남기며, 평가 결과에 따라 조용히 대체하지 않는다.

## 실제 입력 제약 발견

선택한 요청의 원문 합계는4,363,135바이트, 최장 요청은71,136바이트다. **53개 요청이 현재 검색 API의8,192바이트 한도를 넘는다.** 이53개를 제외하거나 이번에 몰래 잘라내지 않았다. 다음 입력 계약에서 전체 요청과 모델/검색에 전달하는 제한된 입력을 구분하고, 잘림·여러 구간 처리·비용·실패를 명시해야 한다. 아직 어떤 긴 입력 처리 방식도 성능 검증하지 않았다.

## 원천 접근 비용 사전 확인

선택된 각 저장소에서 사전순 첫 대표의 수정 전 커밋을 한 개씩 골라 GitHub의 최상위 tree 메타데이터만 받았다. 두 작업자와30초 요청 제한,2MiB 응답 상한, 로컬 캐시를 사용했다. 인증은 기존 GitHub CLI가 담당하며 인증값이나 오류 원문을 공개 보고서로 옮기지 않는다.

53개 모두 접근 가능했고 응답 합계는331,899바이트다.51개 저장소의 최상위에서 LICENSE/COPYING/NOTICE 이름 규칙에 맞는 후보가 있었다. `matplotlib/matplotlib`과 `tokio-rs/axum`은 이 규칙의 최상위 후보가 없었다. **라이선스가 없다는 뜻이 아니며 하위 경로와 원천 조건 확인이 필요하다.** 파일 본문은 받거나 법적 조건을 판정하지 않았다.53개 대표 확인을2,400개 전체 확인으로 확대하지 않는다. [사전 확인 집계](source-preflight-29.json).

이 작은 응답 크기는 소스 코드 전체·하위 디렉터리·컨테이너의 저장 비용 추정이 아니다. 현재는 코드 다운로드/실행을 피한 접근 가능성 확인이다.

## 검증·사용법·다음 단계

전이 연결·동일 식별자의 출처 간 연결·입력 순서 불변·사전순 대표·입력 보존·2,400개 미달 시 기준 유지·긴 요청 미제외를 테스트했다. 원천 사전 확인은 선택 목록을 고정 projection에서 다시 계산해 대조하며, API 오류·불완전 tree·중복 경로를 거부한다. 그룹 집계와 로컬 선택 목록은 재실행에서 모두 바이트 일치했다. 캐시를 사용하는 사전 확인 집계도 바이트 일치했다. 전체 race/vet·형식 검사를 통과했다.

M4 Pro CPU에서 그룹 집계1회는 wall0.53초,user0.16초,peak RSS31,522,816바이트(약30.1MiB)였다. 네트워크 사전 확인·모델·GPU 비용은 포함하지 않는다. 기존 명령/검색 순서/세션은 바꾸지 않았다.

고정 입력 projection이 필요하며 첫 명령의 출력 폴더는 새 폴더여야 한다. `selected.json`은 로컬 유지용이다. 다음 단계는 모든 대상의 원천 조건과 수정 전 파일 목록 확인, 긴 요청 입력 계약, 실제 작업에 맞는 평가 지표 고정이다. 새 학습·모델 추론·HF 배포는 없으며 기존 최종 reserve도 사용하지 않았다. **독립성의 일부 위험을 줄인 평가 준비이며 실제 에이전트 비용 절감은 미검증이다.**
