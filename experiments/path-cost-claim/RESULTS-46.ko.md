# 실험 46 결과: 2,400개 이상으로 학습했지만 유용성 기준은 실패

실제 **학습 4,456개·검증 2,599개**로 고정된 10개 후보를 모두 학습했다. 초기 24문제보다 큰 규모에서 비교했지만, 이번 16개 숫자 특징 기반 주장 모델은 성공 기준을 통과하지 못했다. 가중치 학습 완료와 성능 개선을 구분한다. 운영 기능을 활성화하거나 새 가중치를 Hugging Face에 배포하지 않았다.

| 검증 정책 | 총 페이지 | 보조 선택 수 | 정답이 상위 10위 안인 사례 | 저장소 동일 가중 Hit10 |
|---|---:|---:|---:|---:|
| 기본 검색 | 18,023 | 0 | 1,014 | 41.273% |
| 항상 보조 검색 | 18,179 | 2,599 | 998 | 40.549% |
| 간격 휴리스틱 | 17,967 | 720 | 1,010 | 41.091% |
| 학습 선택, seed 1729 | 18,010 | 55 | 1,013 | 41.245% |
| 학습 선택, seed 2718 | 17,978 | 1,248 | 1,007 | 40.986% |

페이지는 후보 20개를 한 번에 확인한다고 가정한 **첫 정답 파일까지의 페이지 수**다. 돈·LLM 토큰·작업 완료 시간을 직접 측정한 값이 아니다. 보조 선택 수와 `CounterfactualWork`는 저장된 두 검색 결과 중 무엇을 쓸지 계산한 정책 재생값이다. 보조 검색을 실제로 건너뛰어 얻은 실행 시간 절감으로 해석하지 않는다. 전체 후보·제어군·epoch·저장소별 결과는 [원본 집계](results-46.json)에 있다.

두 seed 모두 호출 페널티 4가 정해진 선택 절차에서 골라졌다. 기본 검색 대비 페이지 감소는 **0.072% / 0.250%**로 요구한 최소 5%에 못 미쳤다. Hit10과 저장소 평균도 낮아졌다. seed 2718에서는 cryptography의 페이지가 1,925→2,140으로 11.17% 늘어 저장소별 악화 제한 5%도 넘었다. 페이지가 조금 줄었다는 이유로 통과했다고 보고하지 않는다. 간격 휴리스틱 역시 품질이 낮아져 운영 승격 근거가 되지 않는다.

사후 원인 분석에서는 **정답을 미리 알아 모든 이득 사례만 골라도 561페이지, 최대 3.113%만 절감 가능**함을 실제 비용 행에서 확인했다. 5% 기준에는 최소 902페이지 감소가 필요하다. 품질·호출 제약까지 무시한 낙관적 상한도 기준에 못 미쳤으므로, 보조 검색 자체의 개선 여지가 이번 입력에서 부족했다. 선택 모델의 13 / 45페이지 절감도 이 상한에 훨씬 못 미친다. [상한 진단](diagnostic-46.json)은 이미 관찰한 검증 자료의 설명이며 배포 가능한 oracle이나 새 성공 기준이 아니다. 사전 게이트는 낮추지 않았고 이번 실패를 유지한다.

검증 저장소별 적격 수는 Lightning 287, Google Cloud Python 672, NumPy 679, pandas 634, cryptography 327개다. 각 저장소 최소 100개와 두 역할 각각 최소 2,400개를 넘었다. 같은 질문의 시드·epoch·설정 반복은 새 독립 사례가 아니다. 같은 저장소나 유사한 작업의 상관관계, 사전 학습 오염 부재는 이 숫자만으로 입증되지 않는다. 검증의 약 45.7%가 현재 사용 가능하므로 전체 개발 분포에 대한 결론으로 확장하지 않는다.

항상 보조 검색을 사용한 검증은 이득 116·손해 283·동률 2,200개였다. 실제 정보가 있는 구간은 전체 개수보다 적을 수 있다. 페널티 0에서는 학습 3,722개·검증 2,200개의 가중치가 0이지만 분모에 그대로 남겼다. 양의 페널티에서는 동률 사례도 불필요한 보조 비용을 피할 신호가 된다. 손실 값이 작아도 서로 다른 페널티의 정답과 가중치가 다르므로 성공률처럼 비교하지 않는다.

입력과 [출처 검토 47](../path-cost-data/SOURCE-REVIEW-47.ko.md)을 실제 Go 검증으로 연결했다. 불명확한 221개는 학습에 넣지 않았다. 출처 후보 루트 7,144개와 실제 적격 학습·검증 합계 7,055개는 서로 다른 숫자다. 원문·코드·패치·경로·질문 문자열·저장소/작업 ID·어휘를 계수 입력으로 넣지 않았다. 로컬 숫자 실험의 조건부 출처 검토가 공개 배포 승인은 아니다.

## 재현과 메모리

[계획](plan-46.json)은 비용 결과를 보기 전에 고정했고, 코드 `7d9c64d9dd6e949f6d80e5f5d914b3515c91a711`을 먼저 커밋했다. 그 clean revision에서 만든 binary로 실제 입력을 준비했다. [입력 봉인](input-46.json)을 `d8a4e29`에 별도로 커밋한 뒤 **같은 binary**로 학습했다. 입력 봉인 후 재빌드하면 코드 버전이 바뀌므로 의도적으로 거부된다. 변경한 입력이나 준비되지 않은 분모로 실행하는 우회 옵션은 없다.

5개 페널티 × 2개 seed의 10개 fit과 각각 100epoch를 모두 기록했다. 검증 NLL 동률에서는 먼저 나온 epoch를 선택한다. FP32는 계수 저장 정밀도이며, 특징·shadow 가중치·기울기·손실 누적은 float64를 사용한다. 비용 가중 점수를 보정된 성공 확률로 설명하지 않는다.

일반 재실행에서 집계와 모델 파일 **11개 모두 byte-identical**이었다. 비용 47의 일반·race 재실행도 원본 집계와 private 예제 bytes가 일치했고, 출처 검토의 6개 출력도 오프라인 재현에서 일치했다. 코드의 race 검사·vet·형식·민감정보 검사를 별도로 수행했다. 현재 고정 비용에는 fallback이 0개이며, 이 학습 runner는 완전한 paired cost만 허용한다. 실패·불완전한 보조 실행을 정상 학습 정답으로 만드는 대신 입력 검사를 실패시킨다.

독립된 warm 오프라인 실행 한 번에서 **전체 입력 검증·10개 학습·정책 재생·파일 저장이 1.45초, 최대 RSS 약 108.6MiB**였다. GPU는 사용하지 않았다. 이는 전체 학습 runner의 단일 관찰이며 단일 추론 latency나 cold/warm 성능 분포가 아니다. macOS 프로세스 RSS 측정과 Go heap pprof를 구분하며, 이번 pprof·추론 전용 측정은 하지 않았다. [자원 측정 범위](resources-46.json)를 함께 보아야 한다.

모델 JSON은 1,956~1,985바이트이고 FP32 계수 payload만 64바이트다. 전체 decoded model, 입력 배열, 파일 목록·캐시·검색 비용이 64바이트라는 뜻이 아니다. 모델 본체는 private cache에만 있고 Git에는 설명·집계·hash가 있다.

## 다음 실험의 방향

이 가족의 결과를 실패로 보존한다. 같은 검증 자료에서 페널티·임계값·기준을 바꾸거나 다른 후보를 사후 승자로 골라 성공시키지 않는다. 다음에는 **보조 검색의 달성 가능한 개선 상한과 train 자료에서 이득·손해를 구별할 특징**부터 분석하고, 새 가설과 관찰된 검증 자료 사용 범위를 별도로 고정한다. 표현력이 부족한지, 비용 목표와 품질 목표가 충돌하는지는 아직 가설이다.

유용한 FP32 신호를 확보하기 전에는 이 모델의 INT8/3진 압축을 성능 개선으로 취급하지 않는다. 이후 실제로 보조 검색을 건너뛰는 실행 비용, 문맥 크기, LLM 호출·재시도·완료율을 따로 확인해야 한다. 모델 상향·하향, 저장소 선택, 의존성 있는 작업 분할에는 각각 별도의 골든셋이 필요하다. 이번 파일 검색 자료가 그 도메인들의 정답을 대신하지 않는다.
