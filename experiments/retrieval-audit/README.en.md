Name matching ignores case and uses letter/digit/underscore word boundaries. Name presence is not automatically improper leakage, but named lookup and discovery without a known function name are different capabilities. Only 1,383 rows lack the function name: **this source alone cannot supply 2,400 name-unknown questions.** Rewriting descriptions to inflate the count would not resolve this limitation.

Go scanner removes comments/layout while preserving string literal contents and token boundaries. It does not detect all renamed or semantic clones. Repository membership and equal query/code identities are joined transitively to inform future leakage-resistant splits. The largest component contains 2,579 rows from one repository; meeting the size target with this one group would not establish diversity. No split or exclusion policy has yet been frozen.

## Next evaluation contract

1. Count at least 2,400 distinct questions, not candidate comparisons, repeated runs, translations or trivial rewrites.
2. Natural-language discovery claims require independent questions without a known function name. Keep documentation-based evaluation a separate proxy. Report name-present/absent strata; label name-removal tests as artificial diagnostics.
3. Split repository/duplicate-connected groups and report source-level results and concentration. Adopt sources only after terms are established. Do not select easy examples using model scores.
4. Measure known-target rank, Recall@k/MRR, candidates inspected, preparation time, search p50/p95 and full RSS. Other unjudged candidates are not automatically wrong.
5. Actual agent success, end-to-end time and LLM usage require separate evaluation. This source cannot establish savings or production readiness. Both CoSQA reserves remain unscored.

## Reproduction

Prepare the pinned Parquet and a maintainer PyArrow environment. The projection contains raw rows and must stay local under `.cache`; use a new output path.

```sh
python scripts/training/project_retrieval_audit.py \
  --input .cache/codesearchnet-go/go/test-00000-of-00001.parquet \
  --output .cache/retrieval-audit-new.jsonl
go run ./cmd/riido-retrievalaudit --input .cache/retrieval-audit-new.jsonl
```

The Go CLI bounds input to 64MiB total, 2MiB per row and 100,000 rows. It rejects unknown fields, trailing JSON and empty input. The projection tool checks the pinned source hash; the Go report records the projection hash. The Go CLI alone does not authenticate provenance. Maps are used in this offline deduplication tool, outside inference paths.

On Apple M4 Pro/Go1.27.1 the compiled audit replay took 0.66s wall/0.30s user CPU and 63,143,936 bytes peak RSS. Output matched the first run byte-for-byte. These figures exclude Parquet projection/download and do not measure model inference.
