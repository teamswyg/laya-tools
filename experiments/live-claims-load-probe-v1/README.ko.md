# 로컬 시연 반복 호출 측정

[English](README.md) · [시연 실행 방법](../../docs/live-claims-demo.ko.md)

적은 자원으로 여러 번 호출하는 용도에서 현재 Go 분류기의 기본 처리 비용을 확인했습니다. **분류 품질 평가가 아닌, 짧은 문장 하나를 반복한 로컬 처리량 측정**입니다. GPU나 Laya 가중치는 사용하지 않습니다. 측정 중 다른 자료 검토 작업도 진행 중이었습니다.

## 조건과 결과

- Apple M4 Pro, macOS 26.6.2, Go 1.27.1.
- 이미 모델을 로드한 로컬 시연 서버에 직렬 HTTP 요청. 예제 문장은 공개된 `main.go`에 있습니다.
- 준비 요청 16회 뒤 1,000회 측정. 모든 요청은 실제 추론을 실행하며 결과 판정은 저장하지 않습니다.
- 자체 Go 모델 파일은 73,988바이트. 모델 SHA-256은 `result.json`에 고정되어 있으며 새 모델이나 새 학습 결과가 아닙니다.

| 항목 | 모델 SHA 확인을 추가한 실행 |
|---|---:|
| 1,000회 전체 시간 | 66.98 ms |
| 요청 처리량 | 약 14,930회/초 |
| 로컬 HTTP 중앙값 / p95 / p99 | 54.25 / 117.17 / 147.13 µs |
| 서버 모델 계산 중앙값 / p95 / p99 | 2 / 4 / 6 µs |

`result.initial.json`은 모델 SHA 응답 확인을 코드에 추가하기 전 첫 측정입니다. 1,000회에 67.89 ms, 약 14,730회/초였으며 원래 기록을 보존했습니다. 두 실행에서 모두 같은 시연 서버를 사용했습니다. 모델 판정 점수나 기대 라벨은 이 실험에서 평가하지 않습니다.

첫 실행 전 서버 OS RSS 스냅샷은 10,064 KiB, 첫 실행 후 17,648 KiB, 두 번째 실행 후 18,560 KiB였습니다. 이는 **각 시점의 서버 전체 상주 메모리 관측값**이며 최대값, Go heap 측정, 안정 상태의 메모리, 입력 보관 여부를 증명하지 않습니다. HTTP 처리 뒤 메모리가 증가했으므로 별도의 heap/할당량 측정 없이 원인을 단정하지 않습니다. pprof는 추후 Go heap과 할당 분석에 사용할 수 있으며 GPU 메모리를 측정하지 않습니다.

## 다시 실행하기

먼저 [시연 안내](../../docs/live-claims-demo.ko.md)의 모델과 서버를 실행한 뒤 저장소 루트에서:

```sh
go run ./experiments/live-claims-load-probe-v1
```

측정기는 `127.0.0.1:8877`에만 연결합니다. 2초 요청 제한, 응답 크기 제한, 응답 스키마·모델 SHA 확인을 적용하며 오류가 있으면 결과를 출력하지 않습니다. 웹 입력 대기 시간 180ms와 브라우저 렌더링은 포함하지 않습니다. HTTP 시간에는 Go 측정기의 응답 읽기·JSON 해석 시간이 포함되고, 서버 계산 시간에는 HTTP 처리가 포함되지 않습니다. 서버 시간은 마이크로초 단위로 보고하므로 정밀도에도 한계가 있습니다.

한 종류의 입력, 직렬 호출, 준비된 모델의 측정입니다. 다양한 문장 길이, 병렬 사용자, 정해진 도착률의 open-loop 부하, 초기 모델 로딩 비용은 측정하지 않았습니다. 이 결과를 운영 처리량·최저 사양·분류 정확도·비용 절감으로 일반화하지 마세요. 다음 성능 실험은 여러 입력 길이의 할당량과 제한된 도착률의 지연·큐 길이를 별도로 측정하는 것입니다. 모델 품질 개선은 400개 상황의 전체 의미 검토와 후속 학습·평가를 통해 확인해야 합니다.
