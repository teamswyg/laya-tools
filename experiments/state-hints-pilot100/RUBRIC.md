# Shadow pilot100: 원본 개발 평가 자료

이 파일과 `cases.jsonl`은 짧은 가상 개발 업무 메시지에 붙는 상태 힌트를 관찰하기 위한 개발 평가 자료다. 메시지와 수작업 주석은 직접 작성한 원본 합성 자료로 Apache License 2.0으로 제공한다. 실제 사용자의 업무, 대화, 작업 식별자, 비공개 코드와 계정 정보는 사용하지 않았다. 예측 결과를 보고 작성하지 않았으며, 기존 v2 평가 본문도 열지 않았다.

`expected_intent`는 작성자의 해석이다. 실제 제품에서 확인된 상태나 사용자 의도에 대한 ground truth가 아니다. 특히 완료 보고는 화자의 완료 **주장**이며, 이 주석은 성공·검증·배포·저장 사실을 확인한 결과가 아니다.

## 고정 구성

| 의도 | 한국어 | 영어 | 합계 |
| --- | ---: | ---: | ---: |
| `progress` | 13 | 12 | 25 |
| `completion_report` | 12 | 13 | 25 |
| `question` | 13 | 12 | 25 |
| `blocker` | 2 | 3 | 5 |
| `reference` | 3 | 2 | 5 |
| `cancel_request` | 2 | 3 | 5 |
| `planned` | 3 | 2 | 5 |
| `unclear` | 2 | 3 | 5 |
| 합계 | 50 | 50 | 100 |

주된 표시 대상으로 삼는 진행·완료 보고·질문은 각각 25개다. 표시 범위 밖의 메시지는 나머지 다섯 의도 각각 5개로 총 25개다. 모든 행은 `id`, `family`, `locale`, `text`, `expected_intent`를 갖는다. ID와 사건 family는 이 파일을 위해 새로 만든 식별자이며, 각 100개로 고유하다. 이름·숫자만 바꾸거나 같은 본문을 번역해 행 수를 늘리지 않았다.

100개의 고유 family가 통계적으로 독립적인 표본 100개라는 뜻은 아니다. 같은 작성자, 개발 업무 주제와 문체가 공유되고 의도 경계도 서로 연관될 수 있다. 합성 자료의 균등한 구성은 실제 사용 빈도를 나타내지 않는다.

## 의도와 경계

- `progress`: 현재 수행 중이라는 보고. 앞 단계의 검사 성공이나 일부 완료 뒤 지금 다음 단계를 수행 중이면 진행으로 읽는다. 현재 작업 중이되 아직 제출·발송하지 않았다는 부정도 진행 보고와 양립한다.
- `completion_report`: 특정 작업이나 전달을 끝냈다고 실제로 주장한다. 완료해 달라는 명령, 미래 계획, 가정, 출처 불명의 인용을 완료 보고로 바꾸지 않는다.
- `question`: 답변·설명·위치·기준·예상 동작을 실제로 요청한다. 완료라는 단어, 부정, 조건부 가정이나 자료 속 문구가 등장해도 주된 발화가 실제 질문이면 질문이다.
- `blocker`: 현재 진행할 수 없다는 보고. 단순한 미래 위험과 구분한다.
- `reference`: 배경 자료나 일반적인 설명을 공유하는 것이 주된 목적이다.
- `cancel_request`: 특정 동작·요청을 지금 취소하거나 중단해 달라는 명시적 요청이다. 이미 취소를 처리했다는 주장은 완료 보고다.
- `planned`: 아직 시작하지 않은 미래 작업을 말한다.
- `unclear`: 내용 부족, 충돌, 출처 불명의 인용이나 실제 주장이 아닌 가정으로 상태를 확정하기 어렵다. 일반적인 실행 요청인 완료해 주세요·끝내 주세요도 이 고정 8종에 대응하는 완료 보고가 아니므로 여기서는 `unclear`에 둔다. 이 두 사례의 불확실성은 문장의 이해 불가능함이 아니라 현재 온톨로지의 표시 범위 부족이다.

한 문장에 여러 내용이 있을 때 단어 하나로 분류하지 않는다. 먼저 주된 speech act를 본다. 이미 검사에 통과했고 지금 수정 중이라는 문장은 현재 진행 보고다. 완료 표시의 의미를 알려 달라는 문장은 질문이다. 보조 맥락과 주요 발화를 구분할 수 없는 동등한 의도가 섞이면 확정 표시를 피해야 한다.

이모지는 단독 정답 키가 아니다. 같은 ✅나 🌱가 진행, 완료 보고와 질문에 나타날 수 있다. 숫자와 상태 용어도 실제 시제·부정·발화 목적을 대신하지 않는다.

## 실행 전에 고정할 것

이 두 원본 파일을 예측 전에 고정하고 원본 바이트와 해시를 기록해야 한다. 전체 100개를 같은 조건으로 관찰한다. 결과를 보고 사례를 삭제하거나, 길이로 뒤늦게 잘라 내거나, confidence gate를 추가하여 남은 사례만 성능으로 보고하지 않는다. 표시 범위 밖 25개도 관찰 집계에서 빼지 않는다.

모델 입력은 `text`다. `id`, `family`, `expected_intent`는 정답 예측 특징이 아니며, `locale`은 언어별 집계를 위한 메타데이터다. family와 ID를 클래스 추정이나 모델 선택에 사용하지 않는다. 작성 과정에서는 학습·예측·모델 선택·공개 게시·Git 변경을 수행하지 않았다.

## 해석 제한

이 자료는 shadow 개발 관찰용이며 독립적인 운영 검증셋, 실제 사용자 효용 실험이나 2,400건 규모 일반화 평가를 대체하지 않는다. 일부 요청형 메시지를 `unclear`로 배정한 것은 현재 온톨로지의 정책 선택이다. 다른 정책과 섞어서 모델 오류만으로 해석하면 안 된다. 주석 동의율, 언어·의도별 결과, 범위 밖 메시지에 대한 오표시, 부분 완료와 현재 진행의 혼동을 따로 보고해야 한다.

자료를 만든 사실만으로 성능·안전성·메모리 사용·지연 또는 비용 개선을 주장하지 않는다. 이후 관찰값, 실행 조건과 실패 기록은 원본 작성자의 기대 주석과 구분하여 보존해야 한다.
