# 진행·완료 보고·질문: 첫 100건 개발 시험

[English](README.en.md) · [판정 기준](RUBRIC.md) · [고정 계획](PLAN.json) · [전체 결과](RESULTS.json) · [이슈 #155](https://github.com/teamswyg/laya-tools/issues/155)

Go 도구 `riidolaya state-hint-pilot`은 같은 문장에서 학습 모델·부모 모델·규칙을 비교합니다. 이번에는 별도 AI 작성자가 새로 만든 합성 문장 100개를 실제 공개 Go 가중치로 처리했습니다. 이 도구 자체는 학습하거나 모델을 선택하지 않습니다. 실제 뤼이도 조회·이모지 설치·업무 상태 변경도 하지 않습니다.

진행·완료 보고·질문은 각 25건이며, 다른 다섯 의미는 각 5건입니다. 한국어·영어는 각 50건입니다. 모두 작성자의 의미 주석이며 실제 제품 정답이나 독립 인간 검수가 아닙니다. 고유 family 100개도 통계적 독립성을 보장하지 않습니다. 이름·번호 변형이나 번역으로 행 수를 늘리지 않았습니다.

## 실제 결과

| 같은 100건 | 전체 정답 | 제안 건수 | 올바른 제안 | 잘못된 제안 |
|---|---:|---:|---:|---:|
| Go v0.2 |69|16|15|1|
| 부모 Go v0.1 |31|7|5|2|
| 기존 규칙 |35|22|19|3|
| speech-act 규칙 |44|31|28|3|

규칙의 one-hot 점수는 보정된 확률이 아닙니다. 모델은 기존 온도와 confidence 0.9·margin 0.05를 유지했습니다. 규칙이 더 많이 제안했다는 사실과 모델의 전체 정답 수가 높다는 사실을 각각 기록합니다. 이 결과로 기본 모델이나 규칙을 교체하지 않았습니다.

| v0.2의 세 표시 | 의미 분류 정답 / 해당 정답 문장 | 실제 제안 중 정답 |
|---|---:|---:|
| 진행 보고 |21/25|6/6|
| 완료 보고 |10/25|3/4|
| 질문 |18/25|6/6|

올바른 표시 제안은 대상 75건 중 15건(20%)입니다. 전체 정답률 69%, 제안 정밀도 15/16, 표시 coverage 20%는 서로 다른 분모입니다. 한국어는 38/50, 영어는 31/50입니다. 기존 40건의 85%를 새 100건에서도 유지했다고 주장하지 않습니다.

중요한 실패는 다음 질문입니다.

> Do completed checks have to be repeated after only the description changes?

정답 주석은 질문인데 모델은 `completion_report`를 0.98825 점수로 제안했습니다. 부모도 같은 오류를 냈습니다. 높은 점수가 문장의 뜻이나 완료 사실을 보장하지 않는 구체적인 사례입니다. 원본 주석·문장·실패를 수정하거나 삭제하지 않았습니다. 완료를 언급하는 질문, 실제 완료 주장, 요청·가정·인용·부분 완료를 다음 학습 자료에서 더 구분해야 합니다.

8개 의미 NLL은 부모 2.9244 → v0.2 0.9607, Brier는 1.0299 → 0.4471입니다. 두 모델의 온도는 각각 0.7과 0.9이므로 보정 효과를 포함한 비교입니다. 다른 5개 의미의 확률을 `none`으로 합산한 별도 4범주 손실도 보존하며, 예측이나 제안 기준을 재정규화하지 않습니다. 10개 구간의 calibration 진단은 작은 균형 합성 자료에서만 계산한 값입니다. 실제 사용 빈도의 확률 보정을 뜻하지 않습니다.

## 실행

Go 1.27.1에서 공용 명령을 만들거나 더 작은 전용 바이너리를 만들 수 있습니다. 아래 두 명령은 같은 패키지를 실행합니다. 로컬 모델은 선택한 공개 revision의 파일을 명시적으로 내려받습니다. 자동 다운로드는 없습니다.

```sh
go build -trimpath -o riidolaya ./cmd/riidolaya
go build -trimpath -o riido-statehint-pilot ./cmd/riido-statehint-pilot

hf download JooYoon/riidolaya-statehint-go-v0.2 statehint.rsh --revision 81335eadd9f2753d3b86c932e9b00c636714e3b4 --local-dir ./models/statehint-v0.2

./riido-statehint-pilot --cases experiments/state-hints-pilot100/cases.jsonl --model ./models/statehint-v0.2/statehint.rsh --model-sha256 ae6761dc81501b39ae17f29b48f0f0a8b35305fe11e297b9a787af0f9636df05 --compare-rules --out ./new-report.json
```

`--parent`는 같은 사례에서 기존 모델도 비교합니다. `--cases-sha256`, `--model-sha256`, `--parent-sha256`으로 파일을 고정할 수 있습니다. 잘못된 checksum이나 학습하지 않은 모델은 예측 전에 거절하며 규칙으로 조용히 대체하지 않습니다. 결과 파일은 기본 private 권한이고 기존 파일을 덮어쓰지 않습니다. `--out`을 생략하면 JSON을 출력합니다. 보고서에는 본문을 재출력하지 않지만 case/family ID와 전체 입력의 hash는 민감할 수 있으므로 실제 데이터의 보고서는 private에 둡니다.

## 메모리와 처리 범위

두 별도 macOS 프로세스로 같은 100건을 반복해 공용 명령과 전용 명령을 비교했습니다. 양쪽의 모든 확률·정답·제안·metadata는 정확히 같았습니다. 반복한 100건은 새 독립 사례를 추가하지 않습니다.

| 한 번의 4비교군 실행 | 공용 riidolaya | 전용 riido-statehint-pilot |
|---|---:|---:|
| 바이너리 파일 크기 |11,875,234B|4,390,322B|
| OS 최대 RSS |20,463,616B|12,566,528B|
| JSON 직렬화 전 Go heap 표본 |1,892,600B|1,650,904B|

두 모델을 각각 100번, 두 규칙을 각각 100번 호출했습니다. 모델 로딩·JSON·합성 catalog·보고서 처리가 포함된 OS 프로세스 측정이고, 실제 네트워크 조회·장기 운영·GPU는 포함하지 않습니다. Go heap과 RSS는 더하지 않습니다. v0.2의 첫 100건 분류·합성 조회·집계 구간은 384,000ns였지만 시작·로드·JSON 직렬화가 제외돼 전체 요청 속도로 확대하지 않습니다. 원시 측정 로그는 private에, 정리된 [범위·수치](RESOURCES.json)는 공개 기록에 둡니다.

## 경계와 다음 PDCA

고정 세 표시는 배열로 집계하고 전체 8개 의미의 확률·confusion을 유지합니다. 입력은 최대 2,400건·8MiB, 모델 파일은 1MiB 이하, 조회 batch는 64개입니다. 전체 입력·예산을 검증한 뒤 reader/predictor를 호출합니다. 기본 catalog와 버전1은 명시적인 합성 fixture이며 실제 업무 버전을 대신하지 않습니다.

원본 snapshot을 검증한 뒤 세 의미의 라벨·이모지만 제안합니다. 원래 매핑 충돌이 필터 후 살아나지 않게 처리합니다. 낮은 점수에서도 라벨 누락·inactive 진단을 보존하며 `annotation_checked`가 누락 지표의 분모입니다. 원본 reader 능력과 pilot 정책으로 끈 상태 계획을 구분합니다. 상태 후보 선택은 검사하지 않았다고 표시합니다. 별도 reader를 넣는 API는 있으나 실제 뤼이도 연결을 증명하지 않습니다.

다음 단계는 400개 이상의 다른 업무 문맥, 완료를 언급하는 질문·부분 완료·실행 요청·인용의 주석 보강, 실제 private reader의 revision 연결입니다. 공개 모델 학습에는 공개 가능·라이선스가 확인된 자료만 사용합니다. 이 100건은 이미 노출됐으므로 다음 모델 선택용 새 test로 재사용하지 않습니다. 가중치는 이번 단계에서 변경하지 않았습니다.

소스 CI는 아직 검증 중입니다. 새 CI 단계는 고정된 32KB Go 가중치를 실제 CPU에서 읽어 이 100건을 실행하도록 추가했습니다. 합성 catalog이며 Laya backbone·GPU·모델 학습 단계가 아닙니다. CI 성공은 코드·호환성 검증이고 운영 품질 승인이 아닙니다.
