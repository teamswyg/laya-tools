# 개발 댓글의 세 가지 주장 힌트

뤼이도 개발 댓글에서 답변 요청·진행·완료 보고를 작은 비용으로 찾는 연구입니다. 이전 8분류 모델에서는 리마인드가 높은 확신의 완료 보고로 분류되는 실제 반례를 확인했습니다. 이를 임계값 조정으로 덮지 않고, 여러 주장이 함께 들어가는 댓글에 맞는 새 학습 목표를 시험합니다.

새 모델은 세 항목마다 `true`·`false`·`unknown`을 따로 출력합니다. “수정 완료, 테스트 진행 중”처럼 완료와 활동을 함께 보고할 수 있습니다. `false`는 해당 주장을 하지 않았다는 뜻이며 작업이 미완료라는 뜻이 아닙니다. `unknown`은 학습된 불명확 범주일 수도 있고 낮은 확신 때문에 보류된 결과일 수도 있습니다. 출력의 `winner`, `state`, `unknown_reason`으로 구분합니다.

이것은 **연구 미리보기**입니다. 확신도는 정확도 보장이 아니며 출력은 실제 완료 증명이나 상태 변경 명령이 아닙니다. 자동 라벨·이모지·작업 상태 쓰기는 실행하지 않습니다. 원래 모델과 평가 기준을 대체하지 않습니다. 행위자·활동 범위·출처를 모델 출력에서 만들어 내지 않으며 실제 연동은 이를 별도로 확인해야 합니다.

## 사람과 에이전트의 실행

Go 1.27.1로 `riidolaya`를 빌드하고 명시적인 로컬 연구 모델을 지정합니다. 자동 다운로드나 기본 모델 등록은 없습니다. `.rsc`는 기존 `.rsh`·`.rsm`·`.rsp` 모델과 다른 형식입니다.

```sh
go build -trimpath -o riidolaya ./cmd/riidolaya
./riidolaya claims --model MODEL.rsc --text '타입 검사는 통과했고 지금 회귀 테스트를 돌리고 있어요.' --json
```

반복 실행에서는 모델을 한 번만 읽는 JSONL 모드를 사용합니다. 각 줄은 `text` 필드 하나만 가진 JSON입니다. 이름·업무 원문 등 비공개 입력과 출력은 로컬에 보관하세요.

```sh
printf '%s\n' '{"text":"가상 개발 댓글입니다."}' |
  ./riidolaya claims --model MODEL.rsc --jsonl
```

출력에는 `response_requested`, `current_activity_claimed`, `completion_claimed` 세 항목과 항목별 확률·원래 최다 범주·보류 사유가 들어갑니다. `semantic_quality_qualified`와 `mutation_executed`는 모두 `false`입니다. 잘못되거나 범위를 넘는 입력은 원문을 되풀이하지 않는 사유로 응답합니다.

## 학습과 검증

[한글 판정 기준](RUBRIC.ko.md)은 개발 작업 보고를 대상으로 합니다. 기존 공개 합성 문장을 재검토한 첫 시도에서는 코드 내부 동작 설명이 작업 완료 보고로 해석되거나, 실행 이력의 모순이 작업 주장 불명확으로 해석되는 문제를 발견했습니다. 해당 판정은 이력으로 보존하고 학습에 사용하지 않았습니다. 실제 목표에 맞는 개발 댓글 자료를 별도로 준비하며, 기존 8개 라벨을 자동 변환하지 않습니다. 한영 문장을 각각 AI가 검토하고 근거와 불명확성을 남깁니다. AI 참고 라벨은 사람의 골든셋이 아닙니다.

첫 모델은 동결된 2,048개 문자·단어 특징을 재사용하는 세 개의 3분류 선형 출력입니다. 세 출력의 cross entropy 평균을 AdamW로 학습합니다. 온도 1, 40 epoch, batch 32, 학습률 0.001, weight decay 0.01, seed 1729의 한 가지 조건을 사용합니다. 가중치는 처음부터 학습하며 Laya·기존 부모 모델의 가중치를 파인튜닝했다고 주장하지 않습니다.

가중치 파일은 73,988바이트 형식이지만 이것이 전체 프로세스 메모리는 아닙니다. CPU만 사용하는 Go 코드이며 공유 특징을 한 번 읽고 아홉 출력 계산에 사용합니다. 추론 모델은 읽기 전용이고 호출자마다 작업 공간을 따로 둡니다. 전역 캐시나 추론 락은 없습니다. SIMD나 실제 속도 향상은 측정 없이 주장하지 않습니다.

새 개발 댓글 자료는 작성 전 그룹 단위로 학습·검증·보정·시험을 나눕니다. 기존 넓은 도메인 자료와 그 663/177 분할은 별도 이력으로 유지합니다. AI 개발 결과는 실제 댓글 정확도를 대신하지 않습니다. 이전 보정·최종시험 자료는 열거나 학습하지 않습니다. 원문·모델별 점수·프로파일은 비공개 로컬 공간에 두며, 공개 연구 자산에는 허용된 합성 자료와 안전한 집계만 넣습니다. 모델 바이너리는 Git에 넣지 않습니다.

이 실험의 세 상태와 1.58-bit 가중치는 다릅니다. 우선 float32 모델의 의미 품질을 확인하고 가중치 압축·Laya 표현 기반 학습은 별도 조건으로 비교합니다. [laya.tools](https://laya.tools/)의 선행 프로젝트에 감사를 표합니다.


## 표시와 작업 상태의 구분

[제품 표시 기준 검토](PRODUCT-MARKING.ko.md)는 ❓·🛠️·✅ 후보를 댓글의 응답 요청·활동 보고·완료 보고에 연결하는 첫 시험안을 설명합니다. 하위 작업의 완료 보고를 전체 태스크 종료로 확대하지 않고, 표시의 유용성은 사람 참고 판정으로 따로 검증합니다. 현재 모델은 text만 받아 문맥·귀속·버전은 어댑터에서 확인해야 합니다.
