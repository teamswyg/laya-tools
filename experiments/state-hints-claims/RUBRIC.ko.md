# 세 가지 주장 속성의 학습 기준

판정 범위 버전: **개발 작업 보고 v2**. 최초의 넓은 동작 해석 v1과 그 참고 판정은 로컬 연구 이력으로 보존하며, 해당 판정으로 모델을 학습하지 않았습니다.

목표는 개발 댓글에서 답변 요청, 현재 활동 주장, 완료 주장을 저비용으로 찾는 것입니다. 문장을 생성하거나 실제 업무 상태를 결정하지 않습니다. 기존 8개 주된 의도 분류와 별도의 연구입니다.

각 문장에 아래 세 속성을 **각각** 판정합니다. 각 속성의 값은 `true`, `false`, `unknown`입니다. 여러 속성이 동시에 `true`일 수 있습니다. 별도로 정규화하는 세 학습 출력이 통계적으로 독립적이라는 뜻은 아닙니다.

| 순서 | 속성 | 찾는 내용 |
| --- | --- | --- |
| 0 | `response_requested` | 답변·설명·확인 결과·선택 등 응답을 실제로 요청하는가 |
| 1 | `current_activity_claimed` | 수정·구현·리뷰·검증·빌드·배포 등 개발 작업이 현재 진행 중임을 직접 주장하거나 보고하는가 |
| 2 | `completion_claimed` | 식별되는 개발 작업 또는 그 하위 작업의 완료·검증 완료를 직접 주장하거나 보고하는가 |

`true`는 긍정 요청이나 주장이 문장에 있다는 뜻입니다. 그 주장이 사실임을 보증하지 않습니다. 작성자가 직접 확인·보고한 제3자 활동도 포함합니다. 잠정적인 완료 보고도 완료 주장에 포함하지만, 확정적인 보고인지 조심스러운 보고인지는 근거에 별도로 적습니다.

`false`는 해당 긍정 요청·작업 보고를 하지 않는다는 의미가 문맥에서 명확할 때만 씁니다. 실제 활동이 없거나 작업이 미완료라는 뜻은 아닙니다. `unknown`은 요청·보고의 의도, 현재 진행을 말하는지, 보고한 작업의 범위가 문장만으로 식별되지 않을 때 씁니다. 누락된 라벨이나 근거를 자동으로 `false`로 채우지 않습니다.

프로그램 내부의 일반 동작·실행 이력·상태 변수는 개발 작업 보고와 다릅니다. “예외를 처리기가 잡았다”는 설명만으로 구현·검증 작업을 완료했다고 세지 않습니다. “예외 처리 수정의 검증을 끝냈다”는 직접적인 완료 보고입니다. 현재 실행 중인 테스트·빌드·배포를 직접 보고하면 개발 활동에 포함하지만, 과거 실행 이력의 모순만으로 현재 작업 주장을 `unknown`으로 만들지 않습니다.

주장의 존재와 사실 판정을 구분합니다. 상충하는 긍정 작업 보고가 각각 직접 작성됐음이 명확하면 각 주장의 `true`를 유지하고 모순을 근거 설명에 기록합니다. 명시적인 정정·철회·부정으로 앞의 긍정 보고를 취소하면 그 문맥을 반영합니다. 무엇을 보고하려는지 자체가 불분명할 때만 `unknown`입니다. 실제 작업 상태가 어느 쪽인지 결정하려고 이 범주를 사용하지 않습니다.

인용·코드 예시·가정·미래 계획·부정 표현 자체를 긍정 주장으로 세지 않습니다. 주변 문맥이 별도로 현재 활동이나 완료를 직접 주장하면 그 부분을 검토합니다. 단순한 리마인드는 답변을 원하는지 명확하지 않으면 응답 요청을 `unknown`으로 남깁니다. 답변을 요구하지 않는 명령을 자동으로 질문으로 바꾸지 않습니다.

예를 들어 직접 작성한 가상 댓글 “타입 검사는 통과했고 지금 회귀 테스트를 돌리고 있어요.”는 다른 하위 활동의 완료·진행이 함께 보고됩니다. 전체 태스크가 끝났다는 의미는 아닙니다. 같은 활동의 모순을 해소하려고 다른 하위 작업을 만들어 내지 않습니다.

세 속성은 기존 `expected_intent`, 이전 모델 결과 또는 단어 탐지 규칙에서 자동 변환하지 않고 원문에서 검토합니다. 한영 문장도 각각 검토하며 번역 쌍의 값이 같다고 가정하지 않습니다. 긍정·불명확 판정에는 원본 UTF-8 바이트 근거 구간과 짧은 설명을 남깁니다. 명확한 부재는 전체 문맥 검토로 설명할 수 있습니다. AI의 참고 판정은 사람의 골든셋이 아닙니다. 이전 자료와 AI 이력의 노출·상관 한계를 공개합니다.

학습은 세 개의 3분류 출력에 각각 cross entropy를 적용하고 평균을 줄이는 지도학습입니다. `unknown`도 직접 학습하는 범주입니다. [CrossEntropyLoss 공식 문서](https://docs.pytorch.org/docs/2.14/generated/torch.nn.CrossEntropyLoss.html)의 분류 손실 정의를 참고하되 실행·학습 구현은 Go입니다. 학습된 불명확 범주와 낮은 확신 때문에 출력이 보류된 경우는 결과에서 구분합니다.

기존 확신도 0.9·마진 0.05 기준과 원래 평가 자료·모델은 유지합니다. 새 출력의 연구 표시에도 동일한 수치를 쓰지만 원래 8분류 품질 평가를 통과한 것으로 취급하지 않습니다. 원본 학습 자료 안의 고정 그룹 분할로 얻는 개발 결과는 운영 적격 증거가 아닙니다. 별도의 새로운 평가와 실제 댓글 검증이 필요합니다. 완료 주장 출력은 라벨·이모지·작업 상태 변경 권한을 갖지 않습니다.

세 상태를 출력하는 것과 1.58-bit/3진 가중치는 다릅니다. 첫 실험의 가중치는 float32이며, 가중치 압축과 Laya 인코더 기반 비교는 별도 실험으로 다룹니다. 실제 업무 원문·인증정보는 이 공개 학습 자료에 넣지 않습니다.
