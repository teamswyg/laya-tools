# 작은 공유 신경망으로 주장 의미를 비교하기

현재 목표는 개발 댓글의 답변 요청·진행·완료 보고를 적은 비용으로 제안하는 것입니다. 보고는 실제 작업 완료의 증명이 아닙니다. 기존 선형 모델에서 의미 대조 자료가 일부 연구 지표를 개선했지만, 완료 정밀도와 실제 댓글 활용은 아직 기준 미달입니다. 이번에는 같은 입력 특징을 비선형으로 조합하는 작은 모델을 비교합니다.

## 무엇을 비교하나

두 모델은 같은 1,680행·2,048개 문맥 특징·40epoch·batch32·학습률0.001·weight decay0.01·seed1729·2,120업데이트를 사용합니다. 편향에는 감쇠를 적용하지 않고 AdamW 상태를 새로 시작합니다.

- 처음부터 학습하는 선형 모델은 기존 구현처럼 0으로 초기화합니다.
- 작은 신경망은 공유 ReLU 유닛16개와 독립적인3상태 헤드3개를 둡니다. 입력은Glorot 범위 `sqrt(6/(2048+16))`, 각 출력 헤드는 `sqrt(6/(16+3))`로 초기화합니다.
- 이전4,240업데이트 실수 모델은 참고 결과만 기록합니다. 같은 학습 이력의 대조군이라고 부르지 않습니다.

모든 모델의 온도1·확신도0.9·마진0.05·운영 정밀도·지지 수 기준을 유지합니다.9개 중 하나를 고르는 분류나 문장 생성 모델이 아닙니다. 각 항목은 true/false/unknown 확률을 따로 가집니다. 입력에 주체·범위·맥락이 빠져 있으면 작은 신경망도 이를 복원할 수 없다는 반론을 함께 검증합니다.

## 자료와 판정법

학습 자료는 검토한 원본1,680행을 그대로 사용합니다. 별도의 새 평가360행/180언어쌍 가족/60그룹을 모델 결과 전에 작성·정답 숨김 AI 검토·이견 판정·분할 감사·봉인합니다. 기존 노출 평가와 실제 비공개 업무는 다음 학습이나 선택 자료로 사용하지 않습니다. 언어별 실제 문장이 다르면 정답이 달라도 되며, 같은 정답으로 강제하지 않습니다. AI 참조는 사람 골든셋이나 제품 성능 증명이 아닙니다.

주 비교는 MLP−새 선형의 세 항목 평균 CE입니다. 대조/일반40/20그룹에2:1가중치, paired6행 그룹 bootstrap10000회/seed1729,95% percentile선형보간을 고정합니다. 연구 진행 조건은 구간 상한<0·양 언어 unknown CE 감소·언어/항목별 true오탐 증가없음·일반층CE 악화없음입니다. 실패하면 같은 평가로 hyperparameter·epoch·seed·width·문턱 탐색이나 세 번째 Fit을 하지 않습니다. 두 신규 실제 Fit 예산과 기존 운영 합격 기준은 별도 장부로 관리합니다.

## Go 실행과 자원

`pkg/statehintclaimsmlp`는 입력·출력 가중치를 고정 배열로 보관하고 재사용 작업 공간을 호출자가 소유합니다. 모델별 가변 캐시·map·추론 lock이 없습니다. float32파라미터32,937개이며 float64누산을 사용합니다. RCM형식은131,972바이트입니다. 작은파일·할당시험·코드CI가 실제 의미 품질이나 속도 개선을 보증하지는 않습니다. Go힙·전체RSS·모델/workspace크기를 분리 측정합니다. GPU/MPS는 이 CPU 실험에 필요하지 않습니다.

`riidolaya claims --model MODEL.rcm --jsonl`는 RCM을 명시적으로 읽고 연구 미리보기 JSON을 냅니다. 자동 등록·다운로드·앱 상태 쓰기를 수행하지 않습니다. 기존 RSC/RQT도 유지합니다. 출력의 architecture정보는 계산 구조를 설명하고 운영 적격은 false입니다.

`cmd/riido-statehint-claims-mlp-study`는 유지보수용 고정 실행기입니다. `--check`는 봉인된 평가와 이전 모델의 본문을 열거나 해시하지 않으며 모델Load/Predict/Fit/출력도 하지 않습니다. 상대경로·정규파일·symlink/동일경로/hardlink·크기·스냅샷을 검사합니다. 실제 실행은 두 모델을 모두 학습·저장한 뒤 처음 평가 본문을 읽습니다. 두 번의 소비 장부와 실패/저장된 모델을 보존하며 묵시적 재시도를 하지 않습니다. 파일/디렉터리 sync는 지원 파일시스템의 의미를 따릅니다.

Go1.27.1에서 도움말로 모든 핀 입력과 새 출력 경로를 확인합니다. 원시 프로파일·가중치·평가 원문은 Git에 넣지 않습니다. 미래3진화는 별도 가설이며 이번Float실험에서 압축·BitNet성능을 주장하지 않습니다. [Glorot 원논문](https://proceedings.mlr.press/v9/glorot10a.html)과 [AdamW 원논문](https://arxiv.org/abs/1711.05101)은 알려진 방법의 근거이며 이번 문제의 성공을 보증하지 않습니다.
