# PDCA 53: 행동 변경의 반복 실행과 공개 Go 원천 확대

[English](RESULTS-53.en.md) · [봉인한 계획](plan-53.json) · [사전 Laya 관측](routing-predictions-53.json) · [전체 수치](results-53.json)

새 행동 요청 `repo-keyword-language-guard` 하나를 두 요청 프로필로 각각 두 번 수행했다. 고정한 네 CLI 시도 모두 독립 요구사항 검사를 통과했고, 정상 종료와 기본 사용량을 확인했다. **새 요청은 1개이며 실행 4개가 아니다.** 핵심 소스 변경은 네 번 모두 같은 bytes였다. 검증한 키워드 보호 변경을 실제 저장소 선택 코드에도 반영한다.

누적 실제 코딩 자료는 고유 개발 요청 4개·소유한 실행 기록 12개·두 코드 가족·한 저장소다. 서로 다른 원천의 개발 요청 120개나 도메인별 보호 최종 평가 2,400개를 실행했다는 결과가 아니다.

## Plan

계획 SHA `2205505aeaf03e331ff1d3872c2aee6fe11a1f9668c3c7574f0d30f41cdb2390`을 결과 전 commit `ebd1507c957e8ac3991a2e71cf58eeb5b8f8f8f4`에 고정했다. 요청 순서는 Luna / Sol6 / Sol6 / Luna, 동시 실행 1개, 본 실행 120초·독립 검사 45초, 실행기 재시도·재개·대체 없음이다. 같은 요청의 반복은 변동성 관찰을 위한 사전 선택이다.

실행기는 CI가 통과한 변경 없는 main `ee72334166e2962b0821d5198a50fdd13f92ab29`의 깨끗한 `-trimpath` 빌드다. Go metadata의 해당 revision과 `vcs.modified=false`, 바이너리 SHA `5b801da856ed824a11372a9fb705901f3624f09bd1b52283c46efe28a3420c6c`를 확인했다. 공개 작업은 별도 revision `146b02b9c37e6d90a11386050ccfdffc036c113e`와 이전에 게시한 version1 계약을 그대로 사용한다. 이번에 준비하는 새 파싱 계약이나 원천 목록은 이 네 시도에 사용하지 않았다.

설정·캐시 없는 임시 로그인 공간의 읽기 전용 CLI 카탈로그 조회로 두 프로필의 low를 확인했다. CLI·Go 실행 파일의 이전 고정값은 같았다. 카탈로그는 접근권이나 실제 백엔드 모델의 증명이 아니며, 모든 `observed_model`은 여전히 `unknown`이다. 기존 ChatGPT 로그인을 사용했고 API 키 요금·새 endpoint·클라우드 학습·구매 크레딧은 추가하지 않았다. 금액·구독 사용량과 내부 호출·재시도 수는 미확인이다.

## 작업 결과 전 Laya

기존 후보 목록의 작성자 난이도 가설은 fast였다. 별도 봉인한 계획53은 결과와 Laya 관측 전에 standard를 제안했다. 둘 다 작성자의 가설이며 정답으로 재분류하지 않는다.

정확한 작업 prompt를 고정 Laya INT8 base·CPU 1스레드·임계값0.9로 한 번 실행했다. 제안은 standard, 최대 점수는 0.6692456483으로 **보류**했다. strong 결과의 모델 이름 Astra는 설정상의 fallback이며 실제 Astra 코딩 실행은 없다. 새 fast/Luna·standard/Sol6·strong/Astra 매핑은 이 새 관측에만 적용한다. 이전 예측과 그 6.1 Sol 매핑은 그대로 보존한다.

전체 프로세스 관측은 1,273ms, 앱 보고 `ms`는 860.411ms, OS 최대 RSS는 1,503,657,984bytes(약1.50GB/1.40GiB), 최대 memory footprint는 1,473,218,696bytes다. 한 번의 cold 관측으로 native 로딩을 포함하며 warm 요청 지연·Go heap·GPU 메모리·원격 코딩 모델 자원이 아니다. 초저자원 목표 달성 근거가 아니다. 모델·runtime·귀속 문서 11파일을 변경 없는 manifest와 대조했다.

라우터 바이너리는 고정 공개 Git source archive의 `-trimpath -buildvcs=false` 빌드이며 VCS metadata가 없다. 깨끗한 VCS 실행기 빌드와 구별한다. 예측 파일은 코딩 결과 전 commit `469dc8ffcf72d55046a8bb0ec498a50e94ada099`에 고정했다. confidence는 보정된 코딩 성공 확률이 아니다.

## Act

첫 완료·수용 후보의 `router.go` SHA `e0d9ddb2373604e41b35e151e7b593174dbdc005410ab5132567f15285d7883b`와 같은 변경을 runtime에 반영했다. 실제 기준 소스와 대조했고, 게시한 독립 계약을 함수 이름만 바꿔 runtime 회귀 검사로 가져왔다. 후보가 작성한 테스트는 가져오지 않았다. 선택된 후보의 키워드만 검사하며 nil-Judge·기존 쿼리 보호·lexical fallback을 유지한다. 할당·공유 상태·lock을 추가하지 않았고 기존8후보×32키워드×128byte 한도 안에서 순회한다.

[공개 Go 확보 조사](../../docs/public-go-acquisition-53.ko.md)는 8개 저장소에서 직접 작성한 행동 요청 후보120개를 원천 revision·실제 파일·라이선스 근거에 연결한다. 이는 **실행 적격 요청120개가 아니다**. 독립 완료 검사·닫힌 소스 범위·파일별 귀속·의존성·격리·실행 예산은 다음 단계에서 검증해야 하며 학습 라벨과 final 적격성은 없다. 템플릿·공유 코드·부모/자식·fork 관계는 분할 시 연결한다.

별도 새 파싱 작업은 JSONL event 최상위 키의 중복·64개 개수·128byte 길이 경계를 검증하는 versioned 계약이다. 게시 전 독립 검토에서 type 앞의 키 생략, startup 내부 키의 과도한 제한, 기존 usage 오류 종류 변경, unknown 키 이름 보존, JSON 출력만 숨긴 이름 보존, 비문자열 unknown 값 보존의 여섯 false acceptance를 재현해 계약을 보강했다. 작성한 잘못된 구현17종을 거절하고 올바른 구현을 수용했다. 최종 독립 재검사에서도 privacy 오류3종 거절·같은 올바른 구현 수용을 확인했다. 복수 오류가 섞인 입력의 오류 우선순위는 평가 범위 밖이다. **새 파싱 작업의 실제 모델 시도는0개**이며 기존에 봉인한 계약·이번 네 실행은 바꾸지 않는다. 이 검증용 구현들은 모델 실행 결과나 별도 golden 요청 수가 아니다.

새 fitting·보정·가중치 배포·Codex 정책 활성화는 하지 않았다. 검색용 보호 final2,402개도 계속 미평가다. 다음 실제 실행에서는 서로 다른 요청·저장소·가족과 성공/실패 차이를 확보해야 한다. 이 한 요청에서 두 프로필이 모두 성공한 것만으로 학습 신호나 절감 정책을 완성했다고 판단하지 않는다.
