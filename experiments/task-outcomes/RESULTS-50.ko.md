# 실험 50: 코딩 모델 실행 전에 멈춘 파일럿

[English](RESULTS-50.en.md) · [수치 기록](results-50.json) · [사전 계획](plan-50.json)

**실제 코딩 모델은 한 번도 시작하지 못했습니다.** 첫 실행기는 공개 작업을
모델에 전달하기 전에 `trusted_toolchain_unavailable`로 종료 코드 2를 반환했습니다.
이 결과는 모델의 실패나 작업의 난이도를 알려주지 않습니다. 실행기 패키징의
문제가 드러난 것이므로, 고정한 계획의 나머지 비교를 중단했습니다.

## 계획과 실제 실행을 구분하기

계획은 기존 공개 개발 작업 세 개를 두 요청 프로필로 비교하도록 정했습니다.
`luna-low`는 `gpt-6-luna`와 `low`, `sol-low`는 `gpt-6.1-sol`과 `low`입니다.
Codex CLI 본 실행은 최대 여섯 번, 순차 실행이며 첫 비교의 첫 항목은
`comment-preview-authority` / `luna-low`였습니다.

| 항목 | 확인한 수 |
| --- | ---: |
| 계획한 코딩 CLI 본 실행 | 6 |
| 실행 전 거절 | 1 |
| 시작한 코딩 CLI 본 실행 | 0 |
| 중단 후 실행하지 않은 계획 항목 | 5 |
| 서로 다른 공개 개발 작업 | 3 |
| 코드 가족 | 2 |
| 실제 코딩 모델 결과 | 0 |
| 별도로 실제 수행한 사전 Laya CPU 예측 | 3 |

다섯 개 항목은 성공이나 실패로 채우지 않고 `not_executed_integrity_stop`으로
남겼습니다. 모델별 비교를 계획했어도 같은 작업은 여전히 한 작업입니다.
CLI 실행 횟수와 내부 모델 요청·공급자 재시도 횟수도 다르므로 혼용하지 않습니다.

## 무엇이 실패했나

실행한 패키지의 소스는 `6ae4f1a38ed3d74040f9b1ca7947b3932bb1a5d8`입니다.
배포 형태의 `-trimpath` 빌드에서 실행기가 `runtime.GOROOT()`로 신뢰할 수 있는
Go 도구 경로를 찾지 못했습니다. 필요한 도구에만 읽기 권한을 주는 프로필을
준비하는 단계에서 거절되어, 코딩 모델의 본 프로세스는 시작하지 않았습니다.
이 패키징 조건의 결함은 별도 오프라인 재현으로 확인했습니다.

이전 소스 테스트나 도움말 실행만으로 배포된 실행기의 도구 경로까지 검증됐다고
볼 수 없었습니다. 필요한 수정은 신뢰할 Go 설치를 명시적으로 확인하고 실행기와
독립 검증기에 일관되게 전달하는 것입니다. 이 변경과 재검증 후 다시 실행하려면
**별도 사전 계획 51**로 기록해야 합니다. 계획 50의 거절을 성공 결과로 덮어쓰거나
수정한 실행기를 같은 계획의 조용한 재시도로 처리하지 않습니다.

관측 도구가 보고한 실행기 호출 시간은 대략 **0.52초**입니다. 이는 외부 관측의
근사값이며 코딩 모델 프로세스 시간이나 검증 시간의 수치 기록이 아닙니다.
모델 본 실행의 시작 기록과 종료 기록은 없었고, 검사한 비공개 작업 디렉터리는
`0700`이었습니다. 종료 뒤 복사된 인증 파일이 남아 있지 않은 것도 확인했습니다.
이는 이번 거절 뒤의 제한된 관측이며, 모델 실행·완료·격리 성공을 증명하지 않습니다.

## Laya 자체는 실제로 예측했나

**사전의 세 CPU 예측은 실제로 실행했습니다.** 이것은 코딩 모델 비교와 별개입니다.
기존 고정 `base-int8-v2`를 CPU 한 스레드와 변경 없는 임계값 `0.9`로 실행했으며,
[원본 예측 기록](routing-predictions-50.json)을 그대로 보존합니다.

| 공개 개발 작업 | 작성자의 예상 | Laya 제안 | 가장 큰 확률 | 적용 tier | 차가운 프로세스 시간 |
| --- | --- | --- | ---: | --- | ---: |
| `comment-preview-authority` | fast | standard | 0.479528 | strong, 보류 | 0.98초 |
| `comment-budget-period` | fast | fast | 0.486019 | strong, 보류 | 0.70초 |
| `catalog-min-context` | standard | standard | 0.591143 | strong, 보류 | 0.72초 |

모든 입력은 잘리지 않았지만 신뢰도가 낮아 보류했습니다. 이 확률은 보정한
작업 성공 확률이 아닙니다. 파일럿은 미리 정한 luna/sol의 비교였고, 보류 뒤의
strong 모델인 `gpt-6-astra`를 실행하는 계획은 아니었습니다.

Laya 라우터의 각 최대 RSS는 `1,486,143,488`, `1,482,211,328`,
`1,486,192,640` bytes, 대략 **1.48 GB (1.38 GiB)**였습니다. 각각 native 모델과
session을 새로 불러온 한 번의 차가운 프로세스 관측입니다. 반복 요청의 지연,
Go heap, GPU 메모리나 원격 코딩 모델 자원을 뜻하지 않습니다. 아주 적은 메모리
목표를 달성했다는 근거도 아닙니다.

## 성능 판단에 쓸 수 없는 결과

코딩 작업의 사용량은 관측하지 못했으므로 `null`로 남겼습니다. 사용량이나 비용
절감을 0 또는 100%로 계산하지 않습니다. 작업 수용 여부도 검사하지 않아
`not_assessed`입니다. 예상 난이도를 실제 성공 라벨로 바꾸거나, 거절을 작은
모델의 능력 부족·과소 라우팅으로 분류하지 않습니다.

세 개의 개발 작업과 두 가족은 측정 절차를 준비하는 범위입니다. 영역마다 서로
구분되는 최종 요청 최소 **2,400건**이라는 사용자 목표는 그대로 남아 있습니다.
이번 기록은 그 평가, 실제 사용량 절감, 모델 난이도 보정이나 성공률 일반화를
대체하지 않습니다. 새 학습·임계값 변경·보호된 final 채점·새 가중치 게시·실사용
라우팅 활성화도 하지 않았습니다.
