# 주장 위치 특징 프리뷰 v1 — EXPERIMENTAL

선택적으로 사용할 수 있는 Go 특징 모듈에서 작은 위치 표현을 탐색합니다.
실제 v2 문맥 특징 2048개는 그대로 보존하고, 부호가 있는 해시 위치 뱅크
1024개를 붙여 총 3072개를 반환합니다. 모델·예측·학습·임계값 변경이나
제품 통합은 제공하지 않습니다.

새 위치 특징 추출 전에 [DESIGN.lock.json](DESIGN.lock.json)에 설계를
고정했습니다. 기존 추출기·모델·CLI·학습은 변경하지 않았습니다. 별도 계약명은
`utf8-word12-char2345-v2-pos4-fnv1a-signed-logtf-l2-3072-preview-v1`입니다.
이 프리뷰는 두 matched siblings 계약을 바꾸거나 적격성을 부여하지 않습니다.

## 출발 근거와 해석 범위

앞선 실험은 가상 개발 보고 원문 12개를 6쌍으로 고정했습니다. 모든 쌍의
2048차원 밀집 float32 비트·단어 수·해싱 전 지역 특징 다중집합이 같았습니다.
특징 결과를 보지 않은 별도 AI 문맥의 첫 의미 판단에서는 모든 쌍이 적어도
하나의 주장 헤드에서 달랐고, 작성자와 독자의 상태 불일치는 0/36이었습니다.
두 역할은 같은 제공자의 별도 AI 문맥이며, 실제 모델의 동일성이나 독립성은
확인되지 않았습니다. 사람 정답이나 정확도 평가가 아니며, 서로 연관된 해석
위험은 남습니다.

원래 6쌍 모두 희소 인덱스의 최초 등장 순서가 달랐습니다. 따라서 같은
밀집 비트가 실제 예측까지 같다는 증거는 아닙니다. 부동소수점 누적 순서가
영향을 줄 수 있고, 두 실험 모두 모델을 호출하지 않았습니다. 원래 비공개
증거는 불변으로 보존하며, 공개본은 비공개 경로 없이 논리적 자료명과
다이제스트로 그 출처를 고정합니다.

## 고정된 인코딩

1. 실제 `statehintwide.ExtractContextual`을 호출합니다. 기존 2048개 특징의
   값·float32 비트·0이 된 활성 빈·희소 등장 순서·단어 수를 그대로 노출합니다.
2. 전체 입력의 rune을 `unicode.ToLower`로 소문자화합니다. 길이가 `R > 0`일
   때 시작 rune 위치 `s`의 영역은 `floor(4*s/R)`이며 0~3입니다. 공백과
   문장부호도 `R`에 포함됩니다.
3. v2와 같은 지역 특징을 열거합니다. 유니코드 문자/숫자 단어 1그램·연속
   단어 2그램과 문자 2~5그램입니다. 단어 2그램은 첫 단어 위치를 사용하고,
   영역 경계를 가로지르는 문자 창도 시작 rune의 영역 하나에 배정합니다.
   `R = 0`이면 아무 사건도 내보내지 않습니다.
4. FNV-1a-32에 ASCII `p`, 영역의 원시 바이트 `0..3`, 원래 특징 접두사
   `w/b/2/3/4/5`, 소문자 rune의 UTF-8 바이트를 차례로 넣습니다. 단어
   2그램의 구분자는 v2와 같은 0바이트입니다. 빈은 `h % 1024`, 부호는
   `h >> 31 != 0`이면 -1, 아니면 +1이며 반환 인덱스에 2048을 더합니다.
   영역 네 개가 물리적인 1024빈 뱅크 하나를 공유합니다.
5. 부호 있는 빈별 누적값에 `copysign(log1p(abs(count)), count)`를 적용하고,
   추가 뱅크만 별도로 L2 정규화합니다. 고정 스케일은 **1**입니다. v2와
   같은 float64 제곱합, float32 스케일·곱셈 순서를 사용하며 전체 연결
   벡터를 다시 정규화하지 않습니다. 두 뱅크의 노름이 모두 0이 아니면
   연결 노름은 대략 `sqrt(2)`이고 기존 뱅크의 단위 노름은 그대로입니다.

공개 v2 API에는 지역 사건의 위치가 없으므로 추가 뱅크가 별도의 고정 rune
버퍼에서 입력을 다시 읽습니다. 수동 의미 라벨·정규식 부정 규칙·라벨을
보고 고른 특징은 없습니다. 고정 배열과 분리된 희소 인덱스/값 저장소를
사용하며 추출 반복문에 map·문자열 할당·전역 변경·잠금은 없습니다.

## API와 입력·메모리 수명

```go
var workspace statehintpositionpreview.Workspace
view, err := statehintpositionpreview.Extract(text, &workspace)
// 성공하면 view.Len(), view.At(i), view.WordCount()를 사용합니다.
```

Workspace의 기본값을 바로 사용할 수 있습니다. 입력은 완전한 유효 UTF-8,
최대 4096바이트이며 NUL rune을 포함할 수 없습니다. 잘라내지 않습니다.
빈 입력은 빈 뷰와 단어 수 0으로 성공합니다. 잘못된 입력은 실제 v2와 같은
`statehintwide.ErrInput`과 빈 뷰를 반환합니다. 실패 후 Workspace 내용은
보장하지 않지만 다음 성공 호출이 모든 활성 빈을 초기화합니다.

뷰는 호출자 소유 Workspace를 빌리며, 그 Workspace를 사용하는 **다음 모든
호출**에 만료됩니다. 실패한 호출도 포함합니다. `At`은 값 복사본을 반환하므로
필요한 값은 따로 보관합니다. 처음 사용한 Workspace를 복사하거나, 뷰를 읽는
도중 재사용하거나, 여러 동시 호출자가 공유하면 안 됩니다. 호출자마다 별도
Workspace를 사용하면 잠금 없이 동시 호출할 수 있습니다. `At`의 범위 조건은
슬라이스 인덱싱과 같습니다.

## 결과와 비용

[results.json](results.json)은 실패가 있더라도 원래 6쌍을 모두 보존합니다.
12개 텍스트 모두 기존 비트와 희소 순서를 정확하게 유지했습니다. 추가 뱅크는
6쌍 모두 달랐으며 변경된 정규화 빈 수는 **671, 721, 798, 697, 711, 765**입니다.
이 6쌍에서 특징 분리 실패는 0개였습니다. 공유 정규화 스케일 변화로 다른
빈까지 달라질 수 있으므로 이 수치는 새로 이해한 의미 관계의 개수가 아닙니다.

특징 분리가 **의미 문제를 해결하거나 정확도를 보여 주지는 않습니다**.
영역 네 개는 영역 안의 순서를 잃고 해시 충돌도 가능합니다. 무관한 앞/뒤
문구나 문장부호가 영역 경계를 이동시킬 수 있고 형식상의 지름길을 학습할
위험이 있습니다. 공학적으로 구성한 문장 교환 6쌍은 실제 댓글의 발생률이나
성능을 추정하지 않습니다. 새 주석·예측·학습 가중치·참조를 만들지 않았습니다.

기록된 darwin/arm64 Go 환경의 Workspace `sizeof`는 **54,312바이트**이며,
기존 v2는 **30,744바이트**입니다. 고정 버퍼를 포함한 구조체 크기이며
프로세스 RSS나 실제 모델 메모리가 아닙니다. 9개 로짓의 가상 float32 선형
가중치 배열만 계산하면 `9*3072*4 = 110,592`바이트이고 기존은
`9*2048*4 = 73,728`바이트입니다. **36,864바이트 / 50% 증가**라는 산술일
뿐 실제 모델 페이로드나 GPU 할당을 측정하거나 만들지 않았습니다.

벤치마크는 원래 12개 텍스트를 같은 순서로 순환하며 매 연산 하나를 추출합니다.
CPU 설정 2, 하위 벤치마크당 200ms, 3회 반복으로 제한했습니다. 실제 시간·할당과
소스 핀은 [BENCHMARK.json](BENCHMARK.json), 원시 출력은
[benchmark.txt](benchmark.txt)에 있습니다. 더 큰 뱅크와 별도 입력 분석이 작은
기존 추출기의 메모리·지연 비용을 늘립니다. 표현 증가가 이 비용을 정당화하는지는
앞으로 별도의 의미 평가가 필요하며 이 프리뷰는 그 적격성을 부여하지 않습니다.

| 추출기 | 3회 중앙값 ns/op | B/op | allocs/op |
| --- | ---: | ---: | ---: |
| 실제 v2 | 21,652 | 0 | 0 |
| 위치 프리뷰 | 44,942 | 0 | 0 |

이 제한된 Apple M4 Pro 실행에서 프리뷰의 추출 지연 중앙값은 v2의 약 **2.08배**,
호출자별 Workspace의 추가 크기는 **23,568바이트**입니다.

## 재현과 공개본

저장소 루트에서 필요한 Go 1.27.1 또는 호환되는 로컬 도구로, 네트워크를 끈
검사·race·vet·재현·벤치마크 명령은 [영어 README](README.md#reproduction-and-public-projection)에 있습니다.
재현 도구의 기본 출력은 표준 출력이며 `--output -`도 같습니다. 파일에 쓰려면
`--output 경로`를 명시해야 합니다. `--check`는 고정된 `results.json`의 특징
결과를 다시 계산해 비교하며 파일이나 JSON 출력을 만들지 않습니다. 파일 출력
옵션과 함께 쓰면 거부합니다. 특징 영수증·계약·집계·입력/설계 다이제스트·인코딩
소스 핀·크기 산술을 검사합니다. 실행 환경 정보와 보고 도구의 과거 소스 핀은
달라도 되며 현재 도구 핀은 CHECKS/PROVENANCE/MANIFEST에 있습니다. 기록된
특징 결과와 벤치마크는 원래 소스 핀을 유지합니다.

Go 재현 도구는 공개 cases/design과 허용된 소스 핀만 읽고 12개 원문의 정확한
다이제스트와 기존 추출기 소스를 확인한 뒤 특징만 추출합니다. 의미 라벨이나
모델 연산은 없습니다. 검사에는 기존 비트 동일성, 최대 ASCII/다중바이트 UTF-8,
빈 입력/잘못된 입력, 수작업 위치 사건 예제, 부호 충돌, log-TF와 독립 노름,
할당 0, 재사용/실패 복구, 서로 다른 Workspace의 동시 호출이 포함됩니다.
재현 도구 검사에서는 기본/명시적 표준 출력과 성공/실패한 읽기 전용 검사가
기록된 증거의 바이트를 바꾸지 않으며, 명시적인 파일 출력만 새 결과 파일을
만든다는 점도 확인합니다.

첫 재사용 검사에서 기계적 초기화 예제의 길이가 실수로 4140바이트가 되어
입력 제한이 정상적으로 거부했습니다. 반복 수만 줄여 3910바이트로 수정했으며,
설계와 원래 12개 텍스트는 바꾸지 않았습니다. 이후 패키지 검사·race·vet가
통과했습니다. [CHECKS.json](CHECKS.json)에 기록했습니다.

[cases.json](cases.json)은 쌍/문장 ID·시나리오 종류·원문·다이제스트만 옮긴
정확한 특징 전용 공개본이며 의미 라벨과 근거문은 뺐습니다.
[PROVENANCE.json](PROVENANCE.json)은 불변 출처를 고정하고
[EXCLUSIONS.json](EXCLUSIONS.json)은 영구 제외를 보존합니다. 모든 원문과
동일 시나리오의 바꿔쓰기·번역·절 교환·부정·인용/채택·시간 변경 파생문은
final400/final1200/final2400, **모든 향후 학습과 모든 향후 선택기**에서
제외합니다. manifest가 선택기나 레지스트리를 변경하지는 않습니다.
[MANIFEST.json](MANIFEST.json)은 공개 파일과 총 크기 상한을 고정합니다.
