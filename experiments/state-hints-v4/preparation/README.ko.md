# V4 학습 준비: 개발 진행·완료 보고·질문 힌트

목표는 아주 작은 Go 모델로 개발 글의 의미를 보조하는 것입니다. 완료 보고는
글쓴이의 주장으로 취급합니다. 실제 업무 완료나 상태 변경을 증명하지 않습니다.
Codex 모델이나 추론 수준을 낮추는 작업은 이 단계의 목표가 아닙니다.

계획은 **서로 다른 원본 사건 1,200개 × 한국어·영어 각 한 문장 = 2,400행**입니다.
학습/선택/보정/최종 평가를 사건 840/120/120/120개로 나누며, 번역과 파생 대비
사례가 분할을 넘지 않게 합니다. 같은 사건의 문장 순서·이름·군더더기만 바꾸어
새 사건으로 세지 않습니다. 관련된 사건은 같은 계보로 묶으며, 1,200이라는 숫자가
통계적 독립성이나 실사용 정답을 보장하지 않습니다.

8개 의도는 질문, 장애 보고, 참고 정보, 진행, 완료 보고, 중단 요청, 계획,
불명확입니다. 각 의도에는 총 150개 사건, 분할별 105/15/15/15개를 계획합니다.
API, 타입, 테스트, 빌드, 동시성, 캐시, UI, 문서, 배포를 모든 의도에 섞습니다.
한국어와 영어의 의미 기준은 같습니다. 현재 범위가 어디인지, 진행 중인지,
남은 일이 있는지, 답을 요청하는 것이 주목적인지 원문 안에서 확인해야 합니다.
표 머리글과 코드는 의미 학습 자료와 별도 역할 통제로 관리합니다.

첫 준비에서는 모델 점수 없이 의미 기준을 동결한 뒤 20개 사건의 40행을
작성했습니다. 독립 AI 검토에서 1개 사건의 질문/불명확 해석이 갈렸고, 원본을
그대로 남긴 채 그 2행을 준비 목록에서 제외했습니다. 나머지 19개 사건의 38행도
AI 검토 자료이며 인간이 확인한 골든셋이나 완성된 2,400행이 아닙니다.
새 학습, 최종 평가와 운영 적용은 아직 실행하지 않았습니다.

[Go 구조 점검](../../../internal/statehintcorpus/README.ko.md)을 먼저 구현했습니다.
이 도구는 번역 쌍, 명시한 계보와 입력 한도를 검사하며 개수만 출력합니다.
의미 정답이나 권리는 별도 검토해야 합니다. 이후 새 학습 실행기는 원본 전체·
분할·코드의 해시와 선택 규칙을 고정하고 최종 평가 본문을 선택 이후에 열어야 합니다.
이전 V3 실행기·결과와 기존 모델·임계값은 유지합니다.

학습 방법은 기존 Go 분류기의 교차 엔트로피와 AdamW를 재사용하는 계획입니다.
고정 v0.2 부모에서 학습률 .005/.01/.02로 이어 학습하는 세 후보와 새로 시작하는
.02 후보 하나를 비교합니다. 부모는 이전 학습을 가중치에 포함하고 있으며,
새 비교에서 과거에 공개된 평가 문장이나 비공개 업무 글을 다시 학습하지 않습니다.
Laya 신경망, LoRA나 3진 가중치를 이 실험에서 학습했다는 주장은 하지 않습니다.

선택은 검증 분할만 사용하며 잘못된 완료 힌트의 비용을 크게 둡니다. 사건별
잘못된 완료/질문/진행 제안에 10/3/1의 비용과 놓친 대상 행의 비용을 더합니다.
이 값은 제품 실험의 사전 설계이며 논문의 보편적 최적값이 아닙니다. 각 대상
의도·언어에서 맞는 제안을 5개 이상 사건과 2개 이상 **선언된 계보**에서 얻고,
완료 제안 정밀도 .98 이상과 전체 보류 기준보다 낮은 비용을 함께 요구합니다.
계보 ID가 달라도 실제로 비슷한 사건이면 별도 의미 검토가 필요합니다.

표시 기준 .9 확률/.05 점수차는 유지합니다. 통과한 후보 하나에만 별도 보정
분할로 공통 온도 보정을 적용하며, 자격을 얻지 못하면 최종 평가를 열지 않습니다.
그 후 고정 파일로 저장·재로딩을 확인하고 최종 평가를 한 번 수행할 계획입니다.
이 선택·보정 실행기와 전체 데이터의 구체적 해시 잠금은 아직 준비 중입니다.
