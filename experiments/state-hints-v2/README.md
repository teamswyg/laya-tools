# 내용 힌트 두 번째 PDCA

[English](README.en.md) · [원본 평가 기준](RUBRIC.md) · [학습 기준](TRAINING-RUBRIC.md) · [전체 결과](results/run1.json)

이 단계는 실제 사용자 데이터가 없는 상태에서 원본 자유문맥 사례를 별도로 작성한 개발 실험입니다. V1의 이름·번호 25개 변형을 없애고, 다른 작성자가 학습 320개와 검증·보정·잠긴 평가 각40개를 작성했습니다. 모두 합성이며 외부 독립 제품 정답이 아닙니다. 평가 담당자는 V1 실패를 알았고, 학습 담당자는 새 평가 파일을 읽지 않았습니다.

같은 seed1729, AdamW, 학습률0.02,40epoch, batch32 조건에서 네 후보를 비교했습니다. `v1_warm_start`는 게시한 V1 가중치에서 실제 이어 학습했으며 optimizer는 새로 시작했습니다. `v1_fresh`는 같은1,024구간을 처음부터 학습하고, 나머지는2,048구간에서 기존 특징과 순서 문맥 특징을 각각 학습했습니다. validation NLL만으로 후보를 선택했고, calibration에서0.5–5.0 온도를 맞췄습니다. 모델·온도 잠금 후 새 평가40개를 처음 읽었습니다. 임계값0.9는 그대로입니다.

| 후보 | validation 정답/40 | validation NLL | 선택 |
|---|---:|---:|---|
| 기존 모델 이어 학습 |32|0.6791|선택|
| 1,024구간 새 학습 |31|0.9007|미선택|
| 2,048구간 기존 특징 |34|0.8082|미선택|
| 2,048구간 문맥 특징 |30|0.9522|미선택|

선택된 모델은 같은32,960바이트이며 학습 step은1,520→1,920입니다. 새 평가에서 기존 모델22/40(55%) 대비34/40(85%)로 개선됐고, 한국어·영어 각각17/20입니다. 완료 보고는1/5→5/5, 질문은0/5→4/5였습니다. 신뢰도0.9 이상인 비모호 제안은3/40→17/40이며 관측된17개는 모두 맞았습니다. 한 의미당5개·전체40개는 작으므로 실사용 정확도100%나 안정적인 완료 판단 성능으로 확대하지 않습니다.

새 규칙 기준선도 사전에 작성해 비교했습니다. 기존 규칙17/40, 새 speech-act 규칙20/40이었으며 새 규칙의 선택19건 중2건은 틀렸습니다. 규칙 점수는 확률이 아닙니다. 더 큰 구간과 더 긴 문맥 특징이 자동으로 더 좋다는 결론도 얻지 못했습니다. 현재 결과는 이름 변형을 늘리는 것보다 다양한 문장으로 작은 모델을 이어 학습할 가치가 있다는 개발 근거입니다. 가중치만의 효과와 데이터 다양성 효과를 분리한 것은 아닙니다.

원본 [plan-v2.json](plan-v2.json)과 결과·잠금 파일은 유지합니다. 이후 manifest/rubric/후보 순서 검사를 추가한 driver는 원본 학습 소스와 구분하며 가중치를 다시 선택하지 않습니다. 전체·언어별 지표는 같은 잠긴 모델의 반복 예측입니다. 테스트 파일을 한 번 읽었다는 사실을 forward 한 번이라는 주장으로 바꾸지 않습니다. 이제 이 평가도 노출됐으므로 다음 튜닝의 선택 기준으로 재사용하지 않습니다.

사용자 runtime은 Go이고 상태 쓰기를 실행하지 않습니다. [read-only catalog bridge](../../pkg/statehintcatalog/README.md)는 앱의 신뢰할 수 있는 조회 경계에서 opaque 참조를 받아 실제 catalog를 연결하는 interface입니다. 공개 모델에 native ID·이름·인증정보를 전달하지 않으며, canonical 버전이 없으면 가짜 버전을 만들지 않습니다. Live Riido adapter·권한·이벤트 검증은 아직 연결하지 않았습니다.
