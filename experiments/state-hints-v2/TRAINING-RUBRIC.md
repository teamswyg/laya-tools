# 상태 힌트 v2: 학습 예문 작성 기준

이 자료는 뤼이도에서 짧은 업무 메시지의 내용·라벨·이모지를 저렴하게 읽어 상태 **힌트**를 만드는 실험의 개발용 학습 자료다. 모델이나 추론 수준을 고르는 라우팅 데이터가 아니다. 출력은 메시지에서 읽을 수 있는 주장이나 요청의 종류이며, 실제 업무 상태를 검증하거나 자동 취소·완료 처리하는 권한을 뜻하지 않는다.

`training.jsonl`에는 직접 작성한 가상의 메시지 320개를 넣었다. 한국어와 영어 각각 160개이며, 아래 8개 의도마다 각 언어 20개다. 모든 행의 `split`은 `train`, `origin`은 `original_authored_synthetic_development`다. 실제 사용자의 대화·업무 코드·비공개 도메인 목록·외부 서비스 출력은 사용하지 않았다. 본문과 수작업 의도 주석은 원본 합성 저작물이며 Apache License 2.0으로 제공한다.

## 고정된 8개 의도

| 의도 | 읽는 기준 | 경계 |
| --- | --- | --- |
| `question` | 답변·설명·기준·방법을 실제로 요청한다. | 물음표 유무보다 현재 화자의 답변 요청이 중요하다. 인용된 질문은 그 자체로 요청이 아니다. |
| `blocker` | 현재 작업을 더 진행할 수 없다고 말한다. | 불편함이나 미래 위험만으로 막힘을 단정하지 않는다. 원인 설명은 현재 진행 불가 주장에 종속될 수 있다. |
| `reference` | 배경, 범례, 예시, 비교 자료를 공유하는 것이 주된 목적이다. | 완료라는 단어가 자료 설명에 나와도 화자 자신의 완료 보고는 아니다. |
| `progress` | 지금 작업 중이거나 작업을 시작해 계속하고 있다고 보고한다. | 일부 단계 완료 뒤 계속 작업 중이면 주된 현재 상태는 진행이다. |
| `completion_report` | 작업·요청·전달을 끝냈다고 주장한다. | 완료 보고이지 검증된 완료가 아니다. 잘못된 주장일 가능성까지 제거하지 않는다. |
| `cancel_request` | 현재 특정 작업·예약·신청·자동 동작을 취소하거나 중단해 달라고 명시한다. | 이미 취소를 처리했다는 보고와 구분한다. 가능성·가정·인용은 실제 취소 요청이 아니다. |
| `planned` | 미래에 할 작업을 말하며 아직 시작하지 않았다. | 현재 진행 중인 준비 작업을 숨기고 미래 시제만 보고 분류하지 않는다. |
| `unclear` | 내용 부족, 충돌, 인용, 가정, 또는 여러 동등한 주된 의도로 단일 상태를 정할 수 없다. | 나머지 클래스를 억지로 고르는 대신 정보 부족을 보존한다. |

단일 의도가 명확할 때만 해당 클래스를 붙인다. 원인·설명·부수 맥락이 있다고 무조건 `unclear`로 바꾸지는 않는다. 반대로 실제 질문·완료 보고·취소 요청이 병렬로 있고 우선순위를 정할 수 없다면 `unclear`다. 완료라는 단어와 아직 시작하지 않았다는 주장이 충돌하는 메시지도 `unclear`로 둔다.

## 이모지·시제·부정의 취급

✅, 🌱, 🚧, ❓, 💛를 특정 의도의 확정 신호로 정의하지 않았다. 같은 기호가 여러 의도에 등장하며, 기호 하나만 있는 메시지는 상태를 확정할 맥락이 없을 수 있다. 이 예문만으로 팀마다 다른 이모지 규칙을 일반화할 수는 없다. 뤼이도에서 별도로 정의한 공개 규칙이 있다면, 그 규칙에 대한 독립 실험을 이후 추가해야 한다.

진행 중, 예정, 완료 주장, 취소 요청을 시제와 화자의 행위로 구분한다. `못 한다`는 현재 불가일 때 막힘이고, 조건부 가정만 있으면 막힘을 확정하지 않는다. `아직 보내지 않았다`와 함께 현재 작성 중이라고 명시하면 진행이다. 취소 처리 완료와 취소해 달라는 요청은 서로 다르다.

## 행과 사건 그룹

각 행은 `id`, `group_id`, `locale`, `intent`, `split`, `text`, `origin`을 가진다. ID와 그룹 ID는 동일한 고유 사건 식별자다. 이름·숫자만 바꾸어 행을 늘리지 않았으며, 숫자는 좌석·시간·수량 등의 자연스러운 맥락에만 사용했다. 각 행은 별도의 가상 메시지로 작성했다. 언어 사이에 비슷한 의도 경계와 설명 구조가 반복되는 부분은 있으므로, 320개가 모두 통계적으로 독립적인 표본이라는 주장은 하지 않는다.

예측 입력은 `text`다. ID에 들어 있는 클래스 약자, `group_id`, 정답 `intent`, `split`, `origin`을 모델 특징으로 사용하면 정답 누출이 생긴다. `locale`은 언어별 결과를 집계하는 메타데이터이며, 정답을 추론하는 단서로 취급하지 않는다.

## 작성 범위와 평가 분리

학습 예문은 채팅·메모·행사 운영·문서·일정·자료 정리 같은 공개적인 가상 업무 상황으로 한정했다. 이 파일을 작성하는 동안 평가 파일이나 v1 평가 템플릿을 열지 않았다. 평가 예문을 복사하거나, 평가 성적에 맞추어 학습 예문을 수정하지 않았다. 모델 예측·학습·튜닝·다운로드·API 호출·외부 게시도 수행하지 않았다.

이 파일 자체로 검증셋이나 테스트셋을 만들지 않는다. 독립적으로 작성하고 먼저 고정한 평가 자료로 평가해야 한다. 향후 같은 사건의 변형이나 번역을 추가한다면 원래 사건과 같은 그룹으로 묶고, 학습·평가에 양쪽이 나뉘지 않도록 해야 한다. 현재 그룹 ID의 고유성만으로 문체나 주제의 유사성을 없앴다고 볼 수는 없다.

## 한계와 다음 검토

320개는 시작용 합성 학습 자료다. 실제 운영 빈도, 긴 대화, 구어체 오탈자, 한국어 높임말 변화, 혼합 언어, 여러 메시지 사이의 지시 대상, 팀별 이모지 규칙을 충분히 대표하지 않는다. 클래스별 수가 균등하므로 현실의 발생 비율이나 확률 보정도 제공하지 않는다.

단일 작성자의 어휘와 문체, 유사한 업무 주제, 언어 사이의 병렬적인 경계 사례는 과적합 위험이다. 특히 `unclear`는 서로 다른 이유를 모은 클래스라 내부가 균일하지 않다. 인용과 실제 자료 공유의 경계도 독립 검토자끼리 의견이 갈릴 수 있다. 먼저 블라인드 주석 검토로 경계를 확인하고, 실제 결과는 언어·의도·이모지 유무·부정·시제·인용 유형별로 나누어 보고해야 한다.

모델이 맞는 상태를 골랐는지뿐 아니라 애매한 내용을 확정하지 않았는지, 비용과 크기가 목표에 맞는지도 따로 확인해야 한다. 이 자료 작성 완료는 모델 성능 개선, 운영 안전성, 메모리 절감이나 지연 감소의 증거가 아니다.
