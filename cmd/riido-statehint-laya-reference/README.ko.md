# 고정 Laya 참고 점수의 Go 집계

이미 관찰한 검증 자료와 기존의 본문 없는 Laya 점수 파일을 해시로 지정해 읽는
명령입니다. **모델 실행·가중치 읽기·학습·보정·모델 선택을 하지 않습니다.**
별도의 오프라인 참고 실행기가 MPS에서 특성을 얻고 두 고정 선형층의 점수를
CPU에서 계산합니다. 이 Go 명령은 그 점수의 연결과 수치를
검사해 사람과 에이전트가 읽을 수 있는 집계를 제공합니다.

참고 대상은 기존 Laya 원본과 공개된 v0.1 마지막 선형층 교체 파일입니다.
새로운 원문을 추론할 때는 둘 다 원래 backbone이 필요합니다. 4,252바이트의
교체 파일만으로 Go 모델을 실행할 수는 없습니다. 과거 선택지 정의는 새 V4
범위 판정과 다르므로, 이전 가능한지 살펴보는 진단이며 새로운 독립 검증이나
배포 근거로 취급하지 않습니다.

## 사용법

저장소 루트에서 Go **1.27.1**로 실행합니다. 승인된 상대 경로와 정확한
SHA-256을 아래 자리에 넣습니다.

```sh
go run ./cmd/riido-statehint-laya-reference \
  --validation exposed-validation120.jsonl --validation-sha256 VALIDATION_SHA \
  --scores scores.json --scores-sha256 SCORES_SHA \
  --check
```

`--check`는 입력과 계산을 검사하며 출력 파일은 만들지 않습니다. 집계를 저장할
때는 이를 `--out .cache/statehint-laya-reference-report/NEW-RUN`으로 바꿉니다.
0700 새 폴더에 0600 `report.json`을 한 번만 쓰고, 표준 출력에도 JSON을 냅니다.
오류 메시지에는 업무 본문이나 사용자가 준 인자를 넣지 않습니다.

자료는 동결 V4 기준의 `validation` 분할이어야 하며, 한·영 가족 120개와 prose
240행, 의도별 가족 15개를 요구합니다. 최대 16MiB이고 기존 파서의 제한된
본문 조건을 적용합니다. 점수 파일은 최대 2MiB입니다. calibration, 최종 test,
model, Fit 옵션은 없습니다.

## 점수 형식과 검사

작성 실행기와 맞춘 형식은 `riido-statehint-laya-reference-scores-v1`,
상태는 `reference_only`입니다. 검증 자료 해시, 여덟 의도 순서, 원본·교체 파일의
출처와 해시, 과거 온도, 질문·특성 캐시 출처 해시를 기록합니다. 학습 횟수는
`training_steps_known: false`, `training_steps: null`로 알 수 없음을 표시합니다.
각 행에는 ID·언어·정확한 UTF-8 문장 해시, 두 모델의 여덟 logit·확률과
`truncated: false`만 있습니다. 업무 본문·정답 라벨·가족 메타데이터는 없습니다.

| 참고 모델 | 출처 | 온도 | 가중치 SHA-256 |
| --- | --- | ---: | --- |
| 원본 | `base_pretrained` | 1.0000158548355103 | `891102d372688fc2a094dac56a384bc537b87c63f21f9f3dac0be2b7cbc8d86c` |
| 공개 v0.1 교체 파일 | `published_v1_delta` | 0.65 | `e7037a4c92460dd0c77facb643a26a2f3ce99240e6a59bd78c15ad91df314fcc` |

원본 온도는 과거의 여덟 선택지 설정이고, 0.65는 교체 파일의 과거 보정 값입니다.
V4에서 보정한 값이 아닙니다. 유한한 여덟 값, 확률 범위·합계, logit과 온도로
계산한 안정적인 softmax와의 일치(허용 차이 1e-6)를 확인합니다. 전달된 확률은
바꾸지 않습니다. 점수 행의 순서가 달라도 정렬한 ID 조회로 모든 문장·언어·해시를
대응합니다. 중복·누락·잘림·형식 불일치·크기 초과는 거부합니다.

질문은 고정된 UTF-8 SHA-256
`255725ec00a4526fefedfad729ddd75acc9681181b81fc0f8f96b89b0a400fd3`과
일치해야 합니다. 학습 횟수의 알 수 없음 필드를 생략하거나 수치를 넣으면 거부합니다.
출처 필드는 작성 측의 선언과 해시입니다. 실제 추론이나 발행자 인증의 증명은
아니므로 실행기의 소스·자원·실행 기록을 따로 보관합니다. 이 집계 명령은 특성
캐시나 모델 파일을 읽지 않습니다.

## 결과 읽기

배열은 고정된 여덟 의도 순서이며, 표시 후보는 **진행 / 완료 보고 / 질문**,
언어는 **KO / EN** 순서입니다. 원시 점수가 정확히 동률이면 Laya/Torch와 같이
의도 순서의 첫 분류를 고릅니다. 동률은 마진 0이므로 기존 **신뢰도 0.9 / 마진
0.05** 기준을 통과하지 못합니다. 나머지 다섯 의도에는 표시 후보가 없습니다.

여덟 분류 혼동 행렬·정답률·NLL(log 하한 1e-15), 표시 수, 언어별 올바른 근거와
범위, 잘못된 표시의 고유 가족·계보 수를 보고합니다. 표시 0건의 정밀도는
**정의되지 않으며**, `precision_defined`가 false입니다. 성공률이나 정밀도 0으로
해석하지 않습니다. 가족과 번역 행을 독립적인 제품 관측으로 세지 않습니다.

참고 모델의 학습 횟수를 임의로 만들어 SDK의 `Learned`로 포장하지 않으며,
학습 모델의 가족 적격 평가기를 호출하지 않습니다. 적합 여부는 평가하지 않으므로
false 계약 필드는 실측 부적합 판정이 아닙니다. 선택 가중치·보정·시험·집계기의
모델 호출·승격·배포 적격은 모두 0 또는 false입니다. 완료 라벨도 업무 완료를
검증한 증거가 아닙니다. 원본 가짜 logit 테스트는 연결·수치·0건 근거·가족 단위
잘못된 완료와 비공개 출력을 검증하며 실제 추론이나 의미 성능의 근거는 아닙니다.

## 실제 고정 참고 실행 결과

오프라인 FP32 MPS 작업자 하나가 이미 관찰한 검증 가족 120개·문장 240개에
인코더 호출 240회를 완료했습니다. 두 선형층은 같은 특성을 사용했고, Go 집계는
모델 호출 없이 완료했습니다.

| 측정 항목 | 원본 | 공개 v0.1 교체 파일 |
| --- | ---: | ---: |
| 전체 정답 /240 | 89 | 88 |
| KO 정답 /120 | 16 | 16 |
| EN 정답 /120 | 73 | 72 |
| 올바른 표시 / 전체 표시 | 12/12 | 11/11 |
| EN 올바른 진행 / 완료 / 질문 표시 | 8 / 4 / 0 | 7 / 4 / 0 |
| KO 표시 수 | 0 | 0 |
| 여덟 분류 NLL | 1.738268 | 1.616183 |

영어 완료는 정답 가족 15개 중 4개(26.7%), 계보 3개를 표시했고, 완료 표시
4건은 모두 맞았습니다. 잘못된 후보 가족은 없었습니다. 한국어는 표시 자체가
없으므로 후보 정밀도가 정의되지 않습니다. 작은 영어 완료 신호는 관찰했지만,
전체 정답률이 낮고 과거 정의가 V4와 다르며 이미 본 자료이므로 적격 교사 모델로
취급하지 않습니다. NLL 차이에는 가중치와 과거 온도 설정 차이가 함께 들어 있어
분류층 개선만의 효과를 확정하지 않습니다. 모델 선택·적격화·학습·승격은 없었습니다.

모델 로딩과 검사를 포함한 작업자 경과 시간은 23.44초였고, 동기화한 실제
forward 합계는 13.23초(문장당 평균 55.12ms)였습니다. 별도로 기록한 전체
프로세스 시간은 24.24초였습니다. 프로세스 최대 RSS는 2,887,172,096바이트,
샘플링한 MPS driver/allocated 최대값은 각각 2,166,046,720 / 1,688,613,632바이트,
시스템 가용 비율 최저값은 51%였습니다. MPS 샘플은 순간 최대값을 놓칠 수 있고
unified memory에서 RSS와 겹치므로 합산하지 않습니다. 비공개 특성 캐시는
7,864,320바이트였고, 원본 실제 logit 재구성의 최대 차이는
0.0000019073486328125였습니다. 새 Fit·보정·최종 시험·모델 다운로드는 없었습니다.
학습 횟수는 계속 알 수 없음이며 적합 여부도 평가하지 않았습니다.
