# 개발용 특징 비교

이 별도 관리 명령은 **기존** `statehintwide.Simple`과
`statehintwide.Contextual`을 비교합니다. 두 모델 모두 특징 칸이 2,048개입니다.
원본 학습 가족 840개와 **이미 결과가 노출된 개발 검증** 가족 120개를 사용합니다.
결과는 개발 진단이며 새 평가나 배포 자격의 증거가 아닙니다. 기존 V4 실행,
v1 SDK, 모델 자산과 학습 드라이버는 바꾸지 않습니다.

Simple은 단어 한 개와 문자 2·3개 특징을 개수로 정규화합니다. Contextual은
단어 쌍과 문자 4·5개, 부호 해시와 log-TF를 추가합니다. 따라서 여러 특징을
함께 바꾼 비교이며, 단어 순서 하나의 인과 효과를 분리한 실험은 아닙니다.
둘 다 새 가중치에서 학습률 .02, 40 epoch, batch 32, decay .001, seed 1729로
학습합니다. 온도는 1로 유지합니다. 보정, 적응적 실험 추가, 모델 선택,
최종 테스트 입력, 모델 승격은 없습니다.

Go 1.27.1을 사용합니다. 승인된 로컬 원본 입력의 작업 공간 상대 JSONL 경로와
정확한 소문자 SHA-256을 지정합니다. 아래 해시 자리표시는 실제 해시로 바꿉니다.
다운로드나 전체 manifest 입력은 없습니다.

```sh
go run ./cmd/riido-statehint-ablate \
  --train .cache/statehint-development/train840.jsonl --train-sha256 TRAIN_SHA256 \
  --validation .cache/statehint-development/validation120.jsonl --validation-sha256 VALIDATION_SHA256 \
  --check

go run ./cmd/riido-statehint-ablate \
  --train .cache/statehint-development/train840.jsonl --train-sha256 TRAIN_SHA256 \
  --validation .cache/statehint-development/validation120.jsonl --validation-sha256 VALIDATION_SHA256 \
  --fit --out .cache/statehint-feature-ablation/run01
```

`--check`와 `--fit` 중 하나만 지정해야 합니다. Check는 해시, 크기 제한이 있는
corpus 파싱, 한영 쌍, 가족 수 840/120, 의도별 가족 수 105/15, 분할 간
가족·계보·행·본문 중복을 검사합니다. 출력 파일이나 모델 호출은 만들지 않습니다.
원본 합성 자료의 승인된 출처는 호출자가 확인해야 합니다. 해시와 구조 검사는
의미나 권리를 검증하지 않습니다. 모델 특징에는 `text`만 들어가고 예상 의도는
학습 정답으로 사용합니다. 주석 필드는 특징에 넣지 않습니다.

Fit은 Git에서 제외되는 `.cache/statehint-feature-ablation` 아래의 새 실행
폴더를 요구합니다. 관리 폴더와 실행 폴더는 0700, 파일은 0600이며 기존 결과를
덮어쓰지 않습니다. 두 입력의 원래 바이트, 고정 설정, 두 `.rsh` 모델,
validation 원본 행 순서의 전체 8개 확률과 가족별 보고서를 보존합니다.
저장 모델을 다시 읽어 해시를 확인하고 모든 validation 예측 필드가 학습 직후와
같은지 비교합니다. 실행 실패 시에도 부분 결과와 실패 보고서를 남깁니다.

평가는 기존 `statehintfamily.Evaluate`를 그대로 사용합니다. 신뢰도 .9,
마진 .05, 진행·완료·질문 오제안 비용 1/10/3을 유지합니다. 대상 미탐 비용은
한영 두 행 평균으로 반영하며 한 행만 놓치면 가족당 .5입니다.
커버리지 .2, 지원 가족 5개·계보 2개, 완료 정밀도 .98, 비용 .375 미만 기준을
유지합니다. 이미 결과가 노출된 개발 검증에서 자격 기준을 충족해도 개발 결과이며,
이 명령은 배포 자격을 인정하지 않습니다. 실패와 미정 정밀도·부족한 지원 수도
그대로 보고합니다.

v1 참고 자산 크기는 32,960바이트, 기존 확장 모델은 각각 65,728바이트입니다.
v1 값은 크기 참고이며 대조 모델을 읽거나 다시 학습하지 않습니다. 학습과
validation 예측 시간은 해당 로컬 실행의 기록이고 native/GPU 메모리나
속도·품질 개선을 증명하지 않습니다. 앞선 32 KiB 모델 결과와의 비교도 개발용입니다.
Laya·LoRA·3진 모델 학습은 수행하지 않습니다.

테스트는 임시 소유 메타데이터를 사용합니다. 두 모드의 실제 소규모 학습과
재저장·예측·보고서 일치, 해시·크기 제한 실패, 분할 중복, 비공개 독점 출력
검사를 확인합니다. 모델 품질을 입증하는 테스트는 아닙니다.

## 관측된 개발 실행

원본 학습 자료와 이미 결과가 노출된 개발 검증으로 고정 두 모드를 실행한 결과입니다.
제안 수는 기존 진행·완료·질문 표시 게이트를 사용하며, 완료 지원 수의 대상은
언어별 가족 15개입니다.

| 모드 | 8개 의도 정답 행 | 올바른 제안 / 전체 제안 | 올바른 완료 제안 가족 KO / EN | 자격 충족 |
|---|---:|---:|---:|---|
| Simple2048 | 176/240 (73.33%) | 35/36 | 3/15 · 1/15 | 아니요 |
| Contextual2048 | 179/240 (74.58%) | 40/40 | 3/15 · 0/15 | 아니요 |

모델은 각각 65,728바이트이며 2,120번 갱신 후 저장·재읽기 예측 일치를 통과했습니다.
두 모드 전체 로컬 실행은 1.46초였고 관측된 프로세스 최대 RSS는 18,022,400바이트입니다.
GPU 런타임은 사용하지 않았습니다. 이 한 번의 자원 관측이 다른 환경의 성능을
보장하지는 않습니다. 두 모드 모두 자격 미달이며 특히 영어 완료 지원 수가 부족합니다.
이미 결과가 노출된 검증에서 특징 묶음을 비교한 개발 결과입니다. 새 평가나
문맥 특징 하나의 개선 증거가 아니며 모델을 선택하거나 승격하지 않습니다.
