# 개념 메타데이터 검증

문구 제작 전에 명시적으로 해시가 고정된 잠정 개념 메타데이터를 검사하는
관리자용 명령입니다. 첫 트랜치부터 연속된 1–10개 트랜치를 받으며, 각각
40개 그룹으로 총 40–400개 그룹과 120–1,200개 이중언어 가족을 검사합니다.
Go 표준 라이브러리만 사용하며 모델 호출, 추론, 할당, 개별 사례 인증을
수행하지 않습니다. [타입 계약](SCHEMA.CONTRACT.TEXT-FREE.md)은 기존
메타데이터 스키마를 유지하며 다른 스키마를 변환하지 않습니다.

저장소 루트에서 Go 1.27.1을 사용합니다. 정규화된 상대 `.json` 경로마다
독립적으로 기록해 둔 소문자 SHA-256을 지정합니다. 트랜치별로 `-input`을
반복하고, 뒤 트랜치가 참조하는 이전 파일도 모두 제공합니다. 입력은 읽기만
하며 메타데이터 안의 출처 해시 선언을 따라 파일을 자동으로 열지 않습니다.

```sh
mkdir -p reports
GOMAXPROCS=2 GOMEMLIMIT=512MiB GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off \
  go run ./cmd/riido-statehint-concept-audit \
  -input metadata/tranche01.json="$TRANCHE01_SHA" \
  -input metadata/tranche02.json="$TRANCHE02_SHA" \
  > reports/concept-metadata-audit.json
```

내용을 읽거나 해시·디코딩을 수행하기 전에 입력 개수, 경로·해시 형식,
일반 파일 크기를 검사합니다. 파일당 204,800바이트, 합계 2,097,152바이트가
상한입니다. 연 파일의 정체성, 사전 확인 크기, 실제 바이트 수가 일치해야
합니다. UTF-8, 중복·알 수 없는·누락 키, 정확한 JSON 타입, 정규 ID, 명시적
false 메타데이터 경계, 이전 파일의 정확한 참조를 검증합니다. 보존된 batch 1
수정은 허용된 필드의 1–32개 변경만 받으며 이전 바이트와 SHA를 정확히
복원해야 합니다. 관계 끝점의 전체 배열 변경은 쌍으로 있어야 하며 현재
배열과 입력 파일을 변경하지 않습니다. 타입이 있는 null의 유일한 예외는
해당 수정 내부의 `prior_correction_object: null`입니다.

성공하면 집계 개수, 등록된 분류 태그, 이름 길이·중복 통계, 잠정 검토 연결,
호출자가 제공한 파일 경로·해시를 JSON으로 출력합니다. 개별 개념 원문,
ID, 타깃, 원시 입력은 출력하지 않습니다. 실패는 고정 진단 코드와 종료
코드 2를 사용합니다. 보고서는 로컬 파일이며 자동 업로드하지 않습니다.
“Text-free” 보고서도 자동으로 공개에 안전한 것은 아니므로 분류 태그와
제공한 경로·해시를 게시 전에 검토해야 합니다.

메타데이터는 실제 메시지, 사람의 정답 또는 모델 품질의 근거가 아닙니다.
경계 선언만으로 개념 원문에 실현 문구가 없음을 증명할 수 없습니다. ID의
고유성이나 그래프 구성요소는 의미적 독립성, 계보, 유효 표본 수, 편집 품질,
편입 자격 또는 연구 타당성을 확정하지 않습니다. 메타데이터 안의 출처 해시는
형식을 검사한 선언이며 검증된 외부 계보가 아닙니다.

자체 합성 검증에는 메타데이터나 모델 파일이 필요하지 않습니다.

```sh
GOMAXPROCS=2 GOMEMLIMIT=512MiB GOTOOLCHAIN=local GOPROXY=off GOSUMDB=off \
  go run ./cmd/riido-statehint-concept-audit -self-test
go test -race ./cmd/riido-statehint-concept-audit
go vet ./cmd/riido-statehint-concept-audit
```

자체 검증과 패키지 테스트는 바이트·파일 사전 검사, 엄격한 디코딩,
40–400개 그룹 결합, 공급된 참조의 일치, 수정 전 복원, 출력 경계를 검사합니다.
합성 결과는 구조적 동작만 보여줍니다. 자체 검증 성공은 실제 메타데이터를
검증했다는 뜻이나 CI 결과가 아닙니다.
