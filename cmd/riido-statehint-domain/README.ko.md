# 개발 댓글 도메인 실험

유지보수용 고정 2×2 실험입니다. 기존 Contextual2048 선형 모델과 은닉 노드16개
ReLU MLP를 새로 학습하면서, 기존 fit 자료의 클래스 균형 재표집과 새 개발 댓글
TRAINONLY64가족을 비교합니다. 새 자료는 기존 fit 시나리오에서 파생한 AI주석이며
작성자·검토자의 이전 평가 자료 노출을 공개합니다. 새로운 평가 정답, 사람의 검증,
서로 독립적인 제품 관측으로 취급하지 않습니다.

| 실험군 | 모델 | 추가 학습 가족 |
| --- | --- | --- |
| `linear_balanced_control` | Contextual2048 선형 | 의도별 기존 fit8가족 재표집 |
| `linear_domain64` | Contextual2048 선형 | 의도별 새 도메인8가족 |
| `mlp16_balanced_control` | Contextual2048 → ReLU16 → softmax8 | 의도별 기존 fit8가족 재표집 |
| `mlp16_domain64` | Contextual2048 → ReLU16 → softmax8 | 의도별 새 도메인8가족 |

모든 실험군은 동결된663가족 fit부분집합에64가족의 한국어·영어 쌍을 추가하여
1,454행을 사용합니다. 같은 자료 구성에서는 두 모델에 정확히 같은 순서의 샘플을
전달합니다. hard CE(alpha0),40epochs,batch32,rate.02,decay.001,seed1729,
T1을 고정하며 실험군당1,840번 갱신합니다. 선형 모델의0초기화와 MLP의 시드 기반
Glorot초기화를 유지하므로 초기화를 포함한 모델 구성의 비교입니다. 기존 모델
가중치나 학습 설정 변경은 입력받지 않습니다.

대조군은 고정8의도 순서에서 가족ID앞에 `dev-comment-domain-control-1729:`를
붙인 SHA-256순으로 의도별8가족을 고릅니다. 한국어·영어 쌍 전체를 함께 뽑으며
후보가 부족할 때만 순환합니다. 반복은 재표집이고 새 가족이 아닙니다. 이 접두사와
의도별 균형은 이전 completion중심 대조군과 의도적으로 다릅니다.

```sh
go run ./cmd/riido-statehint-domain \
  --train TRAIN.jsonl --train-sha256 TRAIN_SHA \
  --augmentation DOMAIN.jsonl --augmentation-sha256 DOMAIN_SHA \
  --split SPLIT.json --split-sha256 SPLIT_SHA \
  --source-overlay SOURCE-GROUPS.json --source-overlay-sha256 AUDIT_SHA \
  --check
```

입력은 저장소 기준의 명시적 상대 경로와 정확한 바이트 SHA를 요구합니다. 기존
train840과663fit/177dev그룹 분할 SHA는 고정입니다. 새 자료는64가족128행이며
의도별8가족이어야 합니다. 필수 `statehint-dev-comment-domain-source-groups-v1`
감사 자료는 새 자료·train840·분할 SHA를 묶고 `pair_id == family_id`를 사용합니다.
연결된 원본 그룹과 그 전체 구성원을 기록하며 모두 동결된 fit쪽이어야 합니다.
같은 원본 그룹에 여러 증강 대표 그룹을 부여하거나 연결된 구성원을 빠뜨릴 수
없습니다. 기존840그룹과dev배정을 바꾸지 않습니다. 출력 폴더를 만들기 전에 입력
크기·핀·자료를 확인합니다. `--check`는 모델 호출과 파일 출력을 하지 않습니다.

승인된 실제 실행은 `--check`대신
`--fit --out .cache/statehint-domain/NEW-RUN`을 사용합니다. 새 실행 폴더는0700,
모든 결과 파일은0600입니다. 선택 입력인
`--validation VALIDATION.jsonl --validation-sha256 VALIDATION_SHA`는 이미 결과가
노출된120가족 개발 검증 자료만 받습니다. calibration이나 최종test입력은 없으며
177가족 내부dev도 이미 노출됐습니다. 두 자료 모두 **진단 전용**입니다. 선택 가중치는
0이고 선택 모델·승격·배포 적격 판정을 만들지 않습니다. 기존 가족 평가와
confidence.9/margin.05기준을 유지합니다.

입력 원본 바이트·핀·출처 감사, 가족 단위 표집, 클래스·언어별 수를 포함한 순서별
학습 영수증,8확률과 가족 보고서,4학습 모델을 저장합니다. 선형 RSHv2와 MLPRSMv3는
각자의 로더로 다시 읽어 모든Prediction필드와 저장 바이트의 완전 일치를 확인합니다.
실패는 성공 보고서 대신 명시적 `FAILED.json`과 부분 결과를 남깁니다. 모델과 원문은
Git에 넣지 않고 무시되는 로컬 캐시에 보관합니다.

모델별 자료 구성 차이는 기술적 관측으로 비교하며 인과관계, 새로운 평가 적격성,
실제 작업 완료의 권한으로 해석하지 않습니다. Go힙 수치는 프로세스RSS가 아닙니다.
전체 실행의 OS최대RSS는 외부에서 측정하며 실험군 시간은 순차 실행값입니다.
코드 검증에는 직접 만든 합성 자료만 사용하며 실제 자료 결과는 승인된 실행 뒤
별도로 보고합니다.

## 실제 run01

승인된 로컬 실행1회에서 입력 핀과 학습 모델의 재로딩 완전 일치를 확인했습니다.
내부dev는177가족354행155선언 그룹, 이미 노출된 개발 검증 자료는120가족240행
43선언 그룹입니다. 모두 진단 전용이며 번역 쌍과 연결된 시나리오를 독립 관측으로
계산하지 않습니다.

| 실험군 | 내부 C정밀도 (정답/제안 행) | 내부 적격 | 검증8분류 정답 /240 | 검증 gated정답/제안 | 검증 C정답 가족 KO/EN (각 /15) |
| --- | --- | --- | --- | --- | --- |
| 선형 / 균형 대조군 |25/25|예|171/240|37/37|3/0|
| 선형 / 도메인64 |27/27|예|181/240|39/39|3/1|
| MLP16 / 균형 대조군 |36/38 (94.74%)|아니요|178/240|53/56|5/1|
| MLP16 / 도메인64 |35/38 (92.11%)|아니요|185/240|56/58|5/1|

**노출된 개발 검증 자료에서는4개 모두 적격 기준에 실패했습니다.** 영어 완료 보고의
정답 지원은0또는1가족에 머뭅니다. 선형 대조군은 영어 완료 제안이0건이므로 해당
언어의 완료 정밀도는 정의되지 않습니다. 도메인 자료를 추가한 MLP는 내부dev의
잘못된 완료 제안 가족이2에서3으로 늘어났고, 두 구성 모두 변경하지 않은 완료
정밀도 기준에 실패했습니다. 모델별로 검증8분류 정답 수가 늘었지만 유용한 완료
범위나 새로운 제품 품질의 증거를 확보하지 못했습니다. 실험군 선택·승격은 없고
calibration·최종test호출은0입니다.

전체4실험군은 로컬 관측1회에서4.01초, OS최대RSS27,082,752바이트였습니다.
통제된 메모리 비교가 아닙니다. 선형 모델은65,728바이트, MLP는131,872바이트이며
새 native/GPU추론 백엔드는 추가하지 않았습니다. 이전 실험·자료·기준·모델은
변경하지 않았습니다.
